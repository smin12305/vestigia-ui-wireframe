# 가방 v0.5.0 전투 v0.9.0 변경내역

사용자가 편집한 가방 v0.4 검수본과 전투 v0.8을 기준으로 이번 드래그 교환 리뷰를 반영했다. 기존 화면 이미지는 유지했다. 가방 플로우만 새 교환 분기에 맞춰 교체했다. 페이지는 최종 Word 렌더 기준이다.

| 문서와 페이지 | 수정 내용 |
|---|---|
| 가방 4쪽 | 플로우에 보유 유물 드래그 → 손가락 아래 대상 강조 → 드롭 → 인벤토리 내부 교환 / 빈 슬롯 이동 / 원위치 복귀 분기 추가. |
| 가방 6~8쪽 | 슬롯 매핑 갱신과 단일 후보 강조, I01 내부 교환과 I03 파우치 배치의 입력 구분 반영. 만석에도 내부 교환 가능. |
| 가방 9쪽 신규 | 위치 교환 정의, 드래그 시작, 대상 표시·갱신, 드롭·취소, 데이터와 검토 기준. B가 강조될 때 놓으면 A는 B 자리, B는 A 출발 자리로 이동. |
| 가방 10쪽 I02-01 | 기존 선택 유물 강조를 교환 후보에도 재사용. 정보 열람 대상과 드래그 후보는 별도 상태. |
| 가방 15쪽 | 파우치 배치에서도 손가락 아래 유효 대상 하나만 강조. 찬 파우치 교환은 인벤토리 내부 교환과 별도 미정 정책으로 구분. |
| 가방 17~19쪽 | 제거 방식·비용·한도 도달 시 보상 선택 및 획득 처리를 협의 중으로 정리. 내부 위치 교환을 새 유물과의 대체 획득으로 해석하지 않도록 명시. |
| 전투 10쪽 B01-02 | 교환 가능한 아군 슬롯 전체가 아니라 현재 손가락 아래 대상 하나만 강조. 후보가 바뀌면 이전 강조 해제. 출발 슬롯·적군 슬롯·영역 밖에는 후보 없음. |
| 전투 16쪽·19쪽 | 공통 입력 조건과 순서 편집 표시에도 같은 단일 후보 규칙 반영. |

## 유물 제거와 만석 정책 확정 반영

- 상점에서 유물 제거 기능 제공. 기존 아웃게임 와이어프레임을 따른다.
- 인벤토리 자체 버리기 불가. 가방에 제거 버튼·추가 화면을 만들지 않는다.
- 총 보유 한도 8개에 도달하면 전투 보상 유물 선택 불가. 빈 파우치가 있어도 동일하다.
- 전투 보상 카드는 만석 시 딤·비활성으로 표시하고 선택·획득 전달·I04 진입을 차단한다.
- 만석 시 보상 선택 없이 다음 단계로 진행하는 구체 입력은 이번 결정에 포함되지 않아 B10의 남은 확인 항목으로 둔다.

추가 수정 위치: 가방 4·8·17·18·19쪽, 전투 51·52쪽. 앞 표의 제거·보상 정책 ‘협의 중’ 기록은 이 확정 내용으로 대체한다. 다른 미정 정책은 유지한다.

## 버전 규칙

이번 수정은 내용 버전을 올리지 않고 가방 v0.5를 v0.5.0, 전투 v0.9를 v0.9.0으로 표기 정규화했다. 이후 일반 수정은 패치 번호를 0.0.1씩 올리고, 중대한 변경은 마이너 번호를 0.1.0 올리면서 패치를 0으로 한다. 예: 가방 v0.5.1 → 중대한 변경 시 v0.6.0.

## 와이어프레임 후속 체크

- [ ] 가방: A를 잡은 상태에서 B 하나만 기존 선택 강조로 표시한 화면.
- [ ] 가방: B→C로 손가락을 옮기면 B 강조 해제·C 강조, 영역 밖이면 후보 없음.
- [ ] 가방: 만석 상태에서 A↔B 드롭 결과와 무효 드롭 원위치 복귀 연결.
- [ ] 전투: 드래그 중 손가락 아래 아군 슬롯 하나만 강조. 적군·출발 슬롯·영역 밖에서는 후보 없음.

Figma 원본은 수정하지 않았다. 기존 전투 v0.8 체크리스트의 다른 미완료 항목은 유지한다.
