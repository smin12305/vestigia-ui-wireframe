# Waredo 2.0 전체 기획 관리

> 결정 상태: `[확정]` — 기존 확정 승격 이력 기준 · 검수 상태: `[수정 필요]` — 개별 미결정 잔존
> 최근 수정일: 2026-09-20
> 기준: 각 시스템의 단일 원본과 후속 사용자 결정
> 범위: 문서의 위치·책임·연결과 현재 적용 상태를 관리한다. 개별 시스템 규칙 원본을 대체하지 않는다.

## 1. 관리 기준

- 이 문서는 현행 기획 문서의 관리대장이다. 수치·조건·예외의 단일 원본은 연결된 각 시스템 문서에 둔다.
- 기존 확정 승격 이력과 후속 결정을 기준으로 상태를 표시한다. 개별 [작성 필요]·[논의 필요]·[보류]는 확정 범위에서 제외하며 문서 관리·검수 운영 규칙 자체의 [제안]과 구별한다.
- `[작성 전]`은 독립 기획서가 없는 항목, `[기존 유지]`는 이번 재작성 대상이 아닌 기존 기능, `[보류]`는 현재 적용에서 제외된 기획이다.
- 사용자가 답한 항목은 해당 본문에 반영하고 확인 필요 목록에서 제거한다. 미해결 사항은 각 원본 문서와 [연결성 검토](문서관리/Waredo_2.0_연결성_검토.md)에서 관리한다.
- 인게임 화면의 시스템 연결은 아래 표로 정리한다. 후속 요청에 따라 이번 인게임 연결도 그림은 넣지 않는다. 이전 공격 실행 흐름 그림은 별도 요청으로 만든 기존 자료이므로 그대로 둔다.
- UI 참고 기준은 최근 작업된 [v5 프로토타입](../도구/전투%20프로토타입/실험버전/v5/README.md)이다. 화면 구성만 참고하며 실험용 수치·규칙은 기획 기준으로 가져오지 않는다.

## 2. 전체 시스템 구조

- [통합 범위 데이터 시스템](시스템/Waredo_2.0_통합_범위_데이터_시스템.md) — 범위 ID 1·2·3·4·6·7·8·9(ID 5 폐기), 셀 좌표, 시전자 중심 보드 그림, 범위 없음 데이터의 단일 원본. 캐릭터·공격·스킬·궁극기·반격의 범위 참조를 연결한다.
- 콘텐츠 표는 중복 인덱스를 제거하고 int ID와 공격·스킬·궁극기 분류를 사용한다. 공격 전달 방식은 DIRECT / AREA / NONE enum이며 미정은 별도 표시한다.

### 2.2 후속 결정이 반영된 연결 항목

- 환경요소 파괴: 파괴 트리거만 발생하며 캐릭터용 공격·피격 트리거에서는 제외한다. 파괴 1개당 기본 시간 파편 5는 시간대 전환 4-2에서 지급하며 기존 획득 공통 조건을 따른다.

- 사용자 후속 결정: 보정은 합연산 후 곱연산, 서로 다른 유물 효과 중첩, 기본 치명타 피해율 150%. 띄워짐·기절은 후속 효과로 교체하고 밀치기·당기기는 기존 상태를 유지한 채 위치를 변경한다.
- 피해·회복 선택: 캐릭터 시스템에서 일반 공격·스킬의 수치 효과를 정의하고, 전투 시스템에서 실행한다. 회복에도 피해 보정을 적용하며, 보정별 대상·적용 조건은 각 원본을 따른다.
- 공격력 적용 범위: 일반 공격·스킬·둘 다를 구분한다. 유물은 해당 범위의 보정 효과를 정의하고 캐릭터·전투는 이를 참조한다.
- 면역 태그 유물: 유물은 면역 태그 추가 효과를 정의하고, 상태이상 적용 판정은 상태이상 시스템과 연결한다. 면역 추가 시 해당 기존 상태이상을 즉시 제거한다.
- `[임시]전투 시뮬레이션`: 전투 시스템 4-1-9가 단일 원본이다. 현재까지 그린 계획과 실제 상태를 참조해 가상으로만 재현하며 실제 계획·캐릭터·연계 시스템 상태를 변경하지 않는다.

## 3. 전체 콘텐츠 구조

- 2026-09-13 자료형 정리: [공통 자료형 규칙](문서관리/Waredo_2.0_기획_조정값_통합표.md#공통-자료형-규칙)에 ID·수치·태그·상태의 형식을 정리했다. [캐릭터 콘텐츠 변수 정의 및 연결표](콘텐츠/Waredo_2.0_캐릭터_콘텐츠_변수_정의_및_연결표.md)는 콘텐츠 변수·문법·enum·원본 기획서 연결과 실제 int ID 등록을 관리한다.

## 4. 인게임 화면과 시스템 연결

### 4.1 화면 기준

- 전투판은 정면에서 보는 6×6 격자다. 쿼터뷰·마름모 격자로 설명하지 않는다.
- v5의 상단 행동바, 중앙 전투판, 캐릭터 정보 카드, 공격·스킬 조작, 회중시계·시간 파편, 작전 실행 영역을 화면 참고 요소로 삼는다.
- 이 절은 화면의 어느 요소가 어느 시스템을 보여주는지 정리한다. UI 배치 변경이나 프로토타입 구현을 수행하는 문서가 아니다.

### 4.2 화면 요소별 연결표

| 화면 요소 | 직접 연결할 시스템 | 함께 연결되는 시스템 | 표시·처리 책임 |
|---|---|---|---|
| 위쪽 행동바 | 전투 | 캐릭터, 적 캐릭터 AI | 전투가 슬롯·순서·행동 진행을 관리. 초상화·캐릭터 정보는 캐릭터 정의 참조. 적 계획의 판단은 AI와 구분 |

| 6×6 전투판·점유 셀 | 전투판 | 전투, 상태이상 | 셀과 점유·충돌 판정. 일반 이동 경로는 전투, 밀쳐짐·당겨짐은 상태이상에서 연결 |
| 셀 위 나무 박스·바위 | 환경요소 | 레벨디자인, 전투판, 전투 | 사전 배치. 둘 다 점유·직사 차단. 박스는 피격 시 파괴·점유 해제, 바위는 유지. 충돌 시 캐릭터 피해·이동 종료 |
| 이동 경로·도착 표시 | 전투 | 전투판, 캐릭터 | 사용자가 그린 경로와 진행 표시. 이동력과 셀 유효성·점유 판정 참조 |
| 공격·스킬 버튼과 지정 범위 | 캐릭터·전투 | 전투판, 상태이상 | 정의된 지정 방식·범위를 보여주고 전투에서 실행 검증. 실제 피해·회복·부가 효과를 해당 대상에 적용 |
| 띄워짐·기절·면역 표시 | 상태이상 | 캐릭터, 전투, 가방·유물 | 상태의 적용·해제·행동 제한과 면역 판정 결과 표시. 유물 면역 태그 효과와 연결 |
| 강제 이동·충돌 표시 | 상태이상·전투판 | 전투, 캐릭터, 가방·유물 | 강제 이동 방향·거리 산출과 셀 진입·충돌 판정을 구분. 피해 보정·행동 중단은 관련 원본 참조 |

| 캐릭터의 유물 보정·면역 표시 | 가방·유물 | 캐릭터, 상태이상, 시간대 | 활성 효과의 결과를 표시. 전투 중 가방·유물을 조정하는 기능은 아님 |
| 작전 개시 영역 | 전투 | 각 실행 모듈 | 계획 작성에서 실제 행동 실행으로 연결 |
| [임시]전투 시뮬레이션 영역 | 전투 4-1-9 | 위 전투 연계 시스템 전체 | 현재 계획 가상 재현. 실제 계획·상태 불변. v5의 미래 관측 UI는 참고이며 세부 기능의 자동 채택 근거가 아님 |

### 4.3 전투 상황별 연결

아래는 서로 다른 순간의 예시다. 여러 행동이 동시에 실행된다는 규칙이나 새로운 콘텐츠 수치·범위를 뜻하지 않는다.

| 상황 | 시스템 연결 | 확인할 결과 |
|---|---|---|
| 계획한 이동 뒤 일반 공격 | 전투의 계획·순서 → 전투판의 이동·점유 확인 → 캐릭터 공격 정의 → 전투 실행 | 실제 도착 위치에서 범위·대상을 다시 판정 |
| 적이 띄워진 뒤 후속 공격 | 캐릭터의 스킬 효과 → 전투 실행 → 상태이상 적용 → 후속 전투 판정 | 띄워짐 상태와 후속 공격의 기존 연계 규칙을 적용 |
| 기절로 남은 행동 중단 | 상태이상 → 전투 | 기절 결과에 따라 행동을 제한·중단. 면역이면 상태 적용 결과를 구분 |
| 밀쳐진 대상이 점유 셀과 충돌 | 상태이상의 강제 이동 → 전투판의 셀·충돌 판정 → 전투의 결과 반영 | 실제 이동 결과와 충돌 결과를 구분. 밀치기는 시전자 진영을 가해 진영으로 판정하고 Ally→Enemy 피해 요청만 유물 보정 |
| 회복형 공격·스킬 사용 | 캐릭터의 피해·회복 선택 → 전투 실행 → 캐릭터 체력 | 회복에도 피해 보정 적용. 최대 체력 제한·보정별 적용 조건은 원본 참조 |
| 계획 단계에서 시간대 변경 | 시간대 전환 → 캐릭터 활성 스킬·공통 버프 및 유물 효과 → 전투의 계획·실행 참조 | 시간 파편·체류, 활성 스킬과 남은 쿨타임을 각 소유 규칙대로 표시 |
| 유물 면역 태그로 상태 적용 제한 | 가방·유물 → 캐릭터 면역 정보 → 상태이상 판정 | 면역 여부에 따른 적용 결과. 면역 태그 추가 시 해당 기존 상태 즉시 제거 |
| 반격 범위 안에서 상대 행동 | 전투의 반격 → 전투판 위치·상태이상 참조 → 전투 결과 | 대상별 발동 제한과 기절·전투불능 시 중단을 원본대로 처리 |
| 현재 계획을 가상 실행 | 전투 시뮬레이션 → 각 시스템 규칙 참조 → 가상 결과 표시 | 실제 계획·캐릭터·파편·유물 상태 등에 결과를 반영하지 않음 |

## 5. 검토 및 후속 관리

- [기존 1차 피드백 검수 문서](../보류/문서관리/Waredo_2.0_개발팀_1차_피드백_검수.md)는 사용자 요청으로 보류 보관한다. 현행 처리 내용은 피드백 원문 각 항목 아래의 수정 기록을 따른다.

- 개발팀 1차 피드백: [접수 원문](../피드백/Waredo_2.0_개발팀_1차_피드백.md)은 보존한다. 사용자 답변 1~24의 적용 결과는 [1차 피드백 및 수정 기록](../피드백/Waredo_2.0_개발팀_1차_피드백.md)에 기록했다. 원문은 25개 항목이며 원문 9장 문서 공통 정리(검수표 25번)도 후속 요청으로 반영했다. 미해결·보류·자체 검토 범위를 구분하며 전체 검수 완료는 아니다.
- 개별 미결정: 각 시스템 문서의 확인 필요 목록을 따른다. 시뮬레이션은 미지정 행동을 하지 않고 실제 계획 실행과 같은 종료 흐름을 따른다. 동일 상태·계획·난수 상태에서 실제 실행과 동일한 결과를 보장하며 전투 4-1-9를 따른다.
- 문서 간 충돌: [연결성 검토](문서관리/Waredo_2.0_연결성_검토.md)의 미해결 항목을 따른다. 이 관리 문서에서 임의로 결론 내리지 않는다.
- 적 캐릭터 AI·UI·레벨디자인 실제 배치와 환경요소의 추가 효과 기획은 작성 전이다. 연결표만으로 상세 설계가 완료됐다고 판정하지 않는다.
- 참고한 문서 관리·검수 규칙은 `[제안]` 상태다.

| 검수 항목 | 결과 |
|---|---|
| 전체 구조 | 확정 관리대장의 시스템·콘텐츠 분류를 대조하고 임시 문서·미작성·보류 범위를 구분 |
| 후속 결정 | 피해·회복, 공격력 적용 범위, 면역 태그 유물, 전투 시뮬레이션을 관련 원본에 연결 |
