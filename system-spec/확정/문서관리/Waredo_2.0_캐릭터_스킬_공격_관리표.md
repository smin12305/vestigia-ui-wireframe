# 캐릭터·스킬·공격 관리표

> 결정 상태: [제안] · 작성 문법 정리 완료, 콘텐츠 값 입력 전 · 2026-09-12
> 범위: 임시 콘텐츠 작성용. 확정 콘텐츠를 자동 이관하거나 덮어쓰지 않는다.
> 연결: [전체 기획 관리](../Waredo_2.0_전체_기획_관리.md) · [조정값 통합표](Waredo_2.0_기획_조정값_통합표.md) · [검토 결과](Waredo_2.0_연결성_검토.md)

## 1. 작성 문법

- 자료형은 [공통 자료형 규칙](Waredo_2.0_기획_조정값_통합표.md#공통-자료형-규칙)을 따른다. ID는 int, 이름·설명은 string, 수치·거리·쿨타임·효과 순서는 int, 기절 적용 여부는 bool, 선택 유형·태그는 enum이다.

### 개별 캐릭터 콘텐츠 문서 공통 양식

- 문서는 `1. 캐릭터 관리표 → 2. 공격·스킬 관리표 → 3. 작성 문법 → 4. 실행·기획 유의사항 → 5. 작성·확인 필요 → 6. 검수·변경 기록` 순서로 작성한다.
- 상단은 결정 상태·검수 상태·책임자·검수자·양식 검토자·최초 작성일·최근 수정일·기준 문법·관련 시스템·확정 범위 순으로 표시한다.
- 캐릭터 표는 `항목 / 값` 2열이며 캐릭터 ID·이름·분류·시간대 태그·최대 체력·이동력·치명타 피해율·상태이상 면역 태그·일반 공격 ID·일반 스킬 ID·각성(궁극기) ID 순으로 작성한다.
- 공격·스킬 표는 `항목 / 일반 공격 / 일반 스킬 / 각성(궁극기)` 4열이다. 분류·ID·이름·타겟팅·사용 가능 범위 패턴·영향 범위 패턴·범위 설명·대상·효과 종류·공격력·회복 수치·공격 전달 방식·관통·효과 순서·치명타·쿨타임·반격 범위·반격 시 기절 순으로 작성한다. `공격력·회복 수치`는 한 항목이다.
- 반격·회복 등 유형별로 사용하지 않는 항목은 `해당 없음`, 미정은 `[작성 필요]`, 의도적으로 없는 효과는 `없음` 또는 문법의 `NONE`으로 구분한다. 칸을 채우려고 기능을 새로 만들지 않는다.
- 작성 문법은 `3.1 캐릭터 / 3.2 일반 공격 / 3.3 일반 스킬 / 3.4 각성(궁극기)`로 분리한다. 기존 확정 문법의 호환 항목은 양식 수정만으로 삭제하지 않는다.
- 기획 근거·예외·범위 해설은 4장에, 미해결 사항만 5장에, 과거 승인·검수 이력과 이번 수정 범위는 6장에 남긴다. 수치·효과 순서·ID의 원문 대응을 검증한다.

- 변수·자료형·기획서 연결 및 콘텐츠 ID 등록은 [캐릭터 콘텐츠 변수 정의 및 연결표](../콘텐츠/Waredo_2.0_캐릭터_콘텐츠_변수_정의_및_연결표.md)에서 확인한다. 캐릭터·일반 공격·스킬·패턴의 실제 ID는 int다. 별도 표시 인덱스는 두지 않는다. 범위 ID는 [통합 범위 데이터](../시스템/Waredo_2.0_통합_범위_데이터_시스템.md)에서 관리한다.

- 이 절은 임시 캐릭터·스킬·일반 공격 작성 문법의 단일 원본이다. 동작·예외는 각 시스템 기획서가 소유한다.
- 꺾쇠 안은 작성할 값, 세로선은 택일, `NONE`은 의도적으로 없음이다. 미정 값은 `[작성 필요]`로 표시하며 `0`이나 `NONE`으로 대체하지 않는다.
- 문법은 기획 항목과 의미를 통일하기 위한 표기다. 파일 형식·저장 방식·함수나 처리 기술을 지정하지 않는다.
- 표에서는 문법의 한 항목을 한 열로 대응시킨다. ID는 각 종류 안에서 중복 없이 쓰고, 참조 ID가 실제 작성된 행에 존재하는지 확인한다.
- 캐릭터 → 일반 공격·스킬 → 범위 패턴을 참조한다. 궁극기도 같은 스킬 문법과 스킬 관리표를 사용한다.

### 1.1 캐릭터

```text
CHARACTER <캐릭터ID:int> "<캐릭터명>"
CATEGORY <NORMAL_ENEMY | BOSS_ENEMY | ALLY>
TIME_TAG <PAST | FUTURE | NONE>
MAX_HP <1 이상의 정수>
MOVE_RANGE <0 이상의 정수>
CRITICAL_DAMAGE_RATE_PERCENT <0 이상의 정수>
NORMAL_ATTACK <일반공격ID:int>
SKILL <일반스킬ID:int>
ULTIMATE_SKILL <궁극기ID:int | 0>
STATUS_IMMUNITY <NONE | AIRBORNE, STUN, PUSH, PULL 중 면역 태그 목록>
```

- 아군은 과거·미래 태그 중 하나와 궁극기 ID를 작성한다. 적은 현재 기획 범위에서 시간대 태그는 `NONE`, 궁극기 ID는 `0`이다.
- 일반 스킬과 궁극기의 쿨타임은 같아야 한다. 시간대 교체 시 남은 쿨타임은 공유·유지한다.
- 캐릭터에 별도 공격력 원본을 중복 입력하지 않는다. 일반 공격력은 연결된 공격의 수치, 스킬 공격력은 각 수치 효과에서 작성한다.
- 치명타 피해율은 확률이 아니다. 기본값은 150%다. 아이작의 기존 150%와 일치하며, 캐릭터별 별도 값은 콘텐츠에서 작성한다.

### 1.2 스킬

```text
SKILL <스킬ID:int> "<스킬명>"
CONTENT_TYPE <SKILL | ULTIMATE>
ATTACK_DELIVERY <DIRECT | AREA | NONE | [작성 필요]>
DESCRIPTION "<효과와 사용 목적>"
TARGETING <DIRECTIONAL | SELF_CENTERED | TILE_SELECT | SELF_BUFF>
RANGE_PATTERN <사용가능범위패턴ID:int>
AFFECTED_CELL_PATTERN <영향범위패턴ID:int>
COOLDOWN <1 이상의 정수>

EFFECT NUMERIC <SELECTED_CELL | AFFECTED_CELLS | SELF> TYPE <DAMAGE | HEAL> TARGET_TEAM <ENEMY | ALLY | ALL> VALUE <0 이상의 정수>
EFFECT PUSH AFFECTED_CELLS TARGET_TEAM <ENEMY | ALLY | ALL> DISTANCE <0 이상의 정수>
EFFECT PULL AFFECTED_CELLS TARGET_TEAM <ENEMY | ALLY | ALL> DISTANCE <0 이상의 정수>
EFFECT AIRBORNE AFFECTED_CELLS TARGET_TEAM <ENEMY | ALLY | ALL>
EFFECT STUN AFFECTED_CELLS TARGET_TEAM <ENEMY | ALLY | ALL>
EFFECT COUNTER SELF RANGE_PATTERN <반격범위패턴ID:int> APPLY_STUN <true | false>
```

- 위 효과 행은 선택 가능한 문법 목록이다. 모두 넣으라는 뜻이 아니며 실제 스킬에는 필요한 효과를 1개 이상 작성한다.
- 효과는 위에서 아래로 적용한다. 관리표에서는 같은 스킬 ID의 효과 순서가 문법의 행 순서다. 동일 효과를 반복하는 다단 공격도 행을 합치지 않는다.
- `NUMERIC`은 수치 효과이며 옆의 `TYPE`으로 피해·회복을 선택한다. `VALUE`에는 해당 효과의 기본 수치를 입력한다.
- `SELF_CENTERED`는 수치 효과를 하나 이상 포함한다. `PUSH`·`PULL`은 `DIRECTIONAL`에서만 사용한다.
- `AFFECTED_CELLS`와 방향성·자기 기준·타일 선택형 공격 스킬은 영향 범위 패턴을 작성한다.
- `SELF_BUFF`는 자신에게 적용하며 영향 범위 ID `9`(등록된 범위 없음)를 사용한다. `COUNTER`는 이 유형에서만 작성하고 반격 범위·기절 적용 여부를 함께 작성한다. 아직 정의되지 않은 자가 버프 효과를 임의로 추가하지 않는다.
- 캐릭터에 적용하는 효과는 대상 진영을 작성한다. `COUNTER SELF`는 자신에게 반격 상태를 부여하며 실제 반응 공격은 전투 4-1-8을 따른다.

### 1.3 일반 공격

```text
NORMAL_ATTACK <일반공격ID:int> "<일반공격명>"
CONTENT_TYPE ATTACK
ATTACK_DELIVERY <DIRECT | AREA | [작성 필요]>
EFFECT_TYPE <DAMAGE | HEAL>
VALUE <0 이상의 정수>
TARGETING <DIRECTIONAL | SELF_CENTERED | TILE_SELECT>
RANGE_PATTERN <사용가능범위패턴ID:int>
AFFECTED_CELL_PATTERN <영향범위패턴ID:int>
VALID_TARGET_TEAM <ENEMY | ALLY | ALL>
```

- 일반 공격에는 자가 버프형과 스킬 쿨타임을 작성하지 않는다.
- 일반 공격의 수치와 피해·회복 용도는 이 표가 소유하며 캐릭터 표에 다시 입력하지 않는다.
- 사용 가능 범위는 선택·실행 가능 여부를 판정한다. 영향 범위는 실제 효과 대상을 찾는다. 같은 패턴 ID를 쓸 수 있지만 두 역할을 합치거나 한쪽을 생략하지 않는다.

### 1.4 직사·관통과 환경요소 작성 보조 항목

- 공격 전달 방식은 `attackDeliveryType` enum으로 작성한다. 관통은 별도 항목이며 기존 있음·없음·해당 없음·[작성 필요] 구분을 유지한다.
- 이는 기존 환경요소 차단 규칙을 콘텐츠에 연결하기 위한 기획 설명이다. 새 타겟팅 유형이나 사거리·투사체 기술 규격을 만들지 않는다.
- 방향 선택형이라고 반드시 직사인 것은 아니다. 두 개념을 자동 대응시키지 않는다.
- 비관통 직사는 박스를 파괴해도 그 공격이 박스에서 끝난다. 관통 직사는 박스를 통과할 수 있으나 바위에서는 끝난다. AREA는 환경요소 4-1-2에 따라 중간 장애물 사선 차단 없이 범위 셀에 적용한다. 별도 곡사·궤적 판정은 후속 기획이다.
- 캐릭터 대상 진영은 환경요소의 진영을 뜻하지 않는다. 환경요소 대상 가능 여부와 무효 효과는 [환경요소](../시스템/Waredo_2.0_환경요소_시스템_기획서.md) 4-1-2를 따른다.

### 1.5 이전 문법과의 대응

| 이전 표기 | 현재 작성 표기 | 보존할 의미 |
|---|---|---|
| 일반 공격 DAMAGE·normalAttackDamage | EFFECT_TYPE DAMAGE + VALUE·normalAttackValue | 기존 피해 수치 유지 |
| EFFECT DAMAGE·damageEffectValue | EFFECT NUMERIC … TYPE DAMAGE … VALUE·numericEffectValue | 개별 효과의 대상·수치·순서 유지 |
| CAN_CRITICAL | 신규 작성 항목에서 제외, 기존 콘텐츠 호환 검토에 기록 | 상태 기반 치명타는 스킬별 스위치 없이 적용. 확정 콘텐츠의 기존 필드를 자동 삭제하지 않음 |
| 본문의 Directional·SelfCentered·TileSelect·SelfBuff | DIRECTIONAL·SELF_CENTERED·TILE_SELECT·SELF_BUFF | 표기만 대응. 일반 공격은 SELF_BUFF 불가 |
| 본문의 Airborne·Stun·Push·Pull | AIRBORNE·STUN·PUSH·PULL | 동일한 상태·효과를 뜻함 |

### 분류와 공격 전달 방식

| 변수 | 자료형 | enum | 의미 |
|---|---|---|---|
| contentType | enum | ATTACK / SKILL / ULTIMATE | 공격 / 스킬 / 궁극기. 일반 공격 정의는 ATTACK, 일반 스킬은 SKILL, 각성은 ULTIMATE |
| attackDeliveryType | enum | DIRECT | 직사. 진행 경로의 피격·차단과 별도 관통 규칙을 적용 |
| attackDeliveryType | enum | AREA | 범위 적용. 정의된 영향 셀 안 유효 대상에게 피해·회복을 적용 |
| attackDeliveryType | enum | NONE | 공격 전달 없음. 자신에게 반격 상태를 부여하는 자가 버프 등 |

- [작성 필요]는 enum 값이 아니라 미정 표시다. 미정 공격을 NONE으로 바꾸지 않는다.
- 전달 방식은 피해/회복 종류·타겟팅·관통 여부와 독립적이다. AREA의 환경요소 적용·차단은 환경요소 4-1-2를 따른다.
- NONE 전달 스킬의 COUNTER 효과는 반격 상태를 부여한다. 이후 반격의 실행과 피해는 기존 전투 반격 규칙을 따른다.
- 일반 공격 1과 스킬 1은 분류와 함께 식별한다. 스킬·궁극기는 같은 스킬 ID 집합 안에서 중복될 수 없다.
- 범위 참조에는 등록된 int ID를 사용한다. 범위 없음은 9, 시전자 한 칸은 6이다. 범위에 null·0·빈칸·문자열 NONE을 넣지 않는다.
- 스킬 기본 정보 표에는 분류를 함께 작성하고 값은 SKILL 또는 ULTIMATE로 지정한다.

## 2. 기획 시 유의사항

- 효과별 대상 재조회·한 효과 안의 처리 순서는 캐릭터 4-1-6-4를 따른다. TileSelect는 통합 범위 4장의 목표 셀 원점·무회전 규칙을 사용한다. 좌표 목록은 콘텐츠에 복제하지 않는다.

- 공격력 보정의 적용 범위는 일반 공격·스킬·둘 다로 구분한다. 회복도 피해 보정을 받지만 각 보정의 진영·시간대·적용 범위는 유지한다.
- 회복에는 피해 치명타를 적용하지 않으며 최대 체력까지만 회복하고 전투불능을 되살리지 않는다. 유효한 회복의 실제 회복량이 0이어도 정상 사용 규칙을 따른다.
- 효과 실패·면역을 이유로 다른 효과까지 임의 취소하거나 대상을 자동 재선택하지 않는다. 중단·실패와 쿨타임 적용은 [전투](../시스템/Waredo_2.0_전투_시스템_기획서.md) 4-1-6·7을 따른다.
- 계획 미리보기는 예정 도착 셀 기준, 실행은 이동이 끝난 실제 점유 셀 기준이다. 충돌로 정지했어도 예정 위치로 공격 원점을 옮기지 않는다.
- 타일 선택형의 목표는 시전자 기준 상대 방향·거리로 정한다. 실제 범위 좌표와 패턴 원점은 패턴 콘텐츠에서 명시하며 미정 좌표를 예시 그림에서 가져오지 않는다.
- 띄워짐·기절은 나중에 성공한 효과가 기존 상태를 교체한다. 밀치기·당기기는 기존 상태와 지속 기준을 유지한 채 위치만 변경한다. 면역은 각 효과에 따로 판정한다.
- 상태이상은 [상태이상](../시스템/Waredo_2.0_상태이상_시스템_기획서.md)의 적용·면역·지속·교체 규칙을 따른다. 별도 확률·지속 턴·중첩 수를 빈칸을 채우기 위해 만들어 넣지 않는다.
- 환경요소는 상태이상·강제 이동·회복을 받지 않는다. 환경요소 대상 공격·피격을 캐릭터용 트리거로 세지 않는다.
- 환경요소 파괴 사건은 EnvironmentDestroyed 하나다. 파괴 보상은 [시간대 전환](../시스템/Waredo_2.0_시간대_전환_시스템_기획서.md) 4-2를 참조하고 스킬 보상에 중복 기입하지 않는다.
- 시뮬레이션은 계획 실행과 같은 규칙으로 지정된 행동만 가상 실행한다. 계획이 없으면 넘어가고 공격 지시가 없으면 공격하지 않는다. 실제 캐릭터·계획·점유·파편·유물 상태는 바꾸지 않는다.
- 현재 체력·남은 쿨타임·현재 위치·보정 반영 공격력 등 전투 중 상태·계산 결과는 아래 콘텐츠 원본 표에 입력하지 않는다.
- 유물 보정은 합연산 후 곱연산을 적용하고 최종 결과만 반올림한다. 동일 유물 중복은 불가하지만 서로 다른 유물 효과는 함께 반영한다. 면역 태그 추가 시 해당 기존 상태를 즉시 제거한다. 원본은 가방·유물 4-3-4다.

## 6. 참조 완결성 확인

- [캐릭터 시스템](../시스템/Waredo_2.0_캐릭터_시스템_기획서.md) 4-1-1·5·6이 기능 의미, 이 문서 1장이 기획 작성 표기를 소유한다.
- 기존 범위 8종과 범위 없음은 [통합 범위 데이터](../시스템/Waredo_2.0_통합_범위_데이터_시스템.md)에서 좌표·그림을 확인한다. 추가 모양은 새 데이터로 등록한다.
- [아이작 확정 콘텐츠](../콘텐츠/Waredo_2.0_아이작_캐릭터_콘텐츠_테이블.md)는 기존 콘텐츠 참고다. 이번 빈 양식에 자동 복사하거나 승인 상태를 이전하지 않았다.
- 작성 후 확인: ID 연결 → 허용 유형·수치 범위 → 효과 순서 → 일반·궁극기 쿨타임 일치 → 패턴 좌표·원점 → 환경요소 차단 → 상태·시간대·유물 조건 → 실제 실행·가상 실행 경계.
- 문법 검토 결과: 일반 공격 SELF_BUFF 제외, 스킬 SELF_BUFF 허용, 피해·회복 통합, 효과 순서 유지, 상태 기반 치명타 스위치 제외를 본문과 대조했다. 미정 콘텐츠·연산 규칙이 있어 전체 콘텐츠 실행 준비 완료는 아니다.
