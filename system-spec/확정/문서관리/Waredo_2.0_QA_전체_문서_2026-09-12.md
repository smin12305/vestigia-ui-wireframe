## 2. 상세 발견 사항

### Q-001 · 우선 보완 · 남은 쿨타임으로 사용 가능 여부를 확인한다고 참조표에는 쓰지만, 실제 스킬 실행 규칙에는 0일 때만 허용하는 조건과 0 초과 실패 처리가 없다

- 근거: [원본 문서](Waredo_2.0_전투_시스템_기획서.md) 전투 4-1-7-1 (596~607행), 캐릭터 4-1-6-5 (610~619행). 신뢰도 높음.
- 문제: 남은 쿨타임으로 사용 가능 여부를 확인한다고 참조표에는 쓰지만, 실제 스킬 실행 규칙에는 0일 때만 허용하는 조건과 0 초과 실패 처리가 없다.
- 결과 예시: 남은 쿨타임이 있어도 범위 검증만 통과하면 다시 사용하고 쿨타임을 재설정하는 해석이 가능하다.
- 보완 방향: 계획 선택과 실제 실행 시점의 쿨타임 검사·실패 결과를 명시한다.

### Q-002 · 우선 보완 · 남은 쿨타임은 유효 최대 쿨타임 이하라고 하면서 시간대 변경 전후 남은 값은 변하지 않는다고 한다

- 근거: [원본 문서](Waredo_2.0_캐릭터_시스템_기획서.md) 캐릭터 4-1-2 (349·371행), 4-1-3-2 (427행), 유물 4-3-4. 신뢰도 높음.
- 문제: 남은 쿨타임은 유효 최대 쿨타임 이하라고 하면서 시간대 변경 전후 남은 값은 변하지 않는다고 한다. 시간대에 따라 유물 쿨타임 보정이 바뀌면 두 조건을 동시에 지킬 수 없다.
- 결과 예시: 남은 값 4, 새 최대값 2에서 4 유지와 2 제한 중 결과가 갈린다.
- 보완 방향: 최대값 변화 시 남은 값의 유지·제한 우선순위를 정하고 표와 실행 규칙을 맞춘다.

### Q-003 · 우선 보완 · 공격력·이동력·최대 체력·쿨타임에 Instant를 허용하지만 즉시 처리한다는 말만 있고, 어떤 결과를 변경하며 언제 소멸하는지 없다

- 근거: [원본 문서](Waredo_2.0_가방_유물_시스템_기획서.md) 유물 4-3-2 (334행), 유물 관리표 1·1.3. 신뢰도 높음.
- 문제: 공격력·이동력·최대 체력·쿨타임에 Instant를 허용하지만 즉시 처리한다는 말만 있고, 어떤 결과를 변경하며 언제 소멸하는지 없다. 원본을 직접 변경하지 않는다는 제약도 존재한다.
- 결과 예시: 공격력 즉발 +3을 현재 공격 한 번, 다음 공격 한 번, 현재 시간대 보정으로 서로 다르게 해석할 수 있다. 쿨타임도 최대값과 남은 값 중 적용 대상이 갈린다.
- 보완 방향: 즉발의 변경 대상·소비 시점·종료 조건을 정의하거나 미정 조합은 작성 가능 범위와 구분한다.

### Q-004 · 우선 보완 · 경로 작성 때만 직교 인접·이동력 제한을 확인한다

- 근거: [원본 문서](Waredo_2.0_전투_시스템_기획서.md) 전투 4-1-5-1·2 (473~491행), 캐릭터 상대 목표 규칙. 신뢰도 높음.
- 문제: 경로 작성 때만 직교 인접·이동력 제한을 확인한다. 실행 전에 강제 이동으로 시작 위치가 바뀌거나 이동력 보정이 달라진 경우 기존 경로를 어떻게 처리할지 없다.
- 결과 예시: (1,1)에서 (1,2)로 갈 계획을 세운 캐릭터가 (3,1)로 밀리면 다음 기록 셀까지 거리가 3이다. 비인접 이동 허용·중단·경로 재계산 결과가 갈린다.
- 보완 방향: 실행 시작 셀과 첫 경로 셀의 인접성, 갱신된 이동력 적용 시점, 불일치 시 이동·주 행동의 처리만 명확히 정한다. 자동 보정은 임의 추가하지 않는다.

### Q-005 · 우선 보완 · 획득량·최대 파편에 빼기와 배율 감소를 허용하지만 해당 값의 하한이 없다

- 근거: [원본 문서](Waredo_2.0_시간대_전환_시스템_기획서.md) 시간대 4-2 (225·270~271행), 유물 4-3-4 (417·431~434행). 신뢰도 높음.
- 문제: 획득량·최대 파편에 빼기와 배율 감소를 허용하지만 해당 값의 하한이 없다. 지급식은 min(timeShard + gain, maxTimeShard)뿐이어서 보유량 0 이상 조건을 보장하지 않는다.
- 결과 예시: 기본 획득 5에 빼기 10이면 보유량 0에서 -5가 된다. 최대 저장량 100에 빼기 150이면 상한 자체가 -50이 된다.
- 보완 방향: 획득량·최대 저장량의 허용 하한과 음수 보정 결과 처리, 보유량 제한을 원본 시간대 규칙에 정의한다. 최대 저장량을 반드시 100 이상으로 둘지는 사용자 결정이다.
