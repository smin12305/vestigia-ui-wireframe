# 인수인계 에이전트 도입

> 작업일: 2026-09-01
> 결정 상태: 합의됨
> 대상 브랜치: `main`

## 배경

사용자는 한 컴퓨터에서 진행한 Waredo 2.0 작업을 다른 컴퓨터에서도 맥락 손실 없이 이어가길 원한다. 기존 `AGENTS.md`는 역할과 작업 규칙만 정의했으며, 작업 대화를 분석해 지속 가능한 상태로 남기는 기능은 없었다.

## 사용자 결정

- GitHub 저장소를 로컬 간 공유 기억장치로 사용한다.
- 전용 에이전트가 작업 대화에서 결정과 진행 상태를 추출해 저장소 문서로 남긴다.
- 대화 전문보다는 다음 작업에 필요한 요약 정보에 집중한다.

## 적용한 설계

- `인수인계/CURRENT.md`를 최신 상태의 단일 진입점으로 사용한다.
- `인수인계/기록/`에 완료된 주요 작업의 날짜별 스냅샷을 보관한다.
- `프롬프트/ainus-handoff-recorder.md`가 기록할 정보, 사실 확인, 보안, 반환 형식을 정의한다.
- 루트 `AGENTS.md`가 모든 작업 시작 시 `CURRENT.md`를 먼저 읽고, 의미 있는 작업 종료 시 갱신하도록 지시한다.
- 명시적인 마무리·푸시 요청이 있을 때만 인수인계 기록과 작업 변경을 함께 GitHub에 올린다.

## 기대하는 복원 흐름

1. 다른 로컬에서 저장소를 clone 또는 pull한다.
2. Codex가 `AGENTS.md`와 `인수인계/CURRENT.md`를 읽는다.
3. Git 실제 상태와 기록을 대조한다.
4. 완료된 일을 반복하지 않고 `다음 작업 순서`부터 이어간다.

## 남은 확인

- 실제 다음 작업에서 `작업 시작`과 `작업 마무리` 흐름이 충분한지 사용해 본다.
- 기록이 너무 길어지거나 누락되는 경우 템플릿을 조정한다.
