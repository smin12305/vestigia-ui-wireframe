# 2026-09-07 시간대 전환 기획서 책임 범위 개편

## 목표

- 유물 자체에 시간대가 없다는 사용자 결정을 반영하고, 시간대 전환 시스템 기획서가 다른 시스템의 콘텐츠 문법까지 소유하던 문제를 정리한다.

## 사용자 결정

- 유물은 시간대 또는 시간대 태그를 갖지 않는다.
- 유물 효과의 적용 시간대는 유물을 배치한 가방 칸으로 결정한다.
- 시간대 전환 시스템 기획서에서는 캐릭터 데이터 문법을 다루지 않는다.
- 시간대 버프는 아군에게만 적용하고 적군에는 적용하지 않는다.
- 시간대 전환 시 시간 파편 100을 전부 소모한다.
- 적의 치명타 일반 공격은 시간 파편 30을 지급하며 일반 공격의 시간 파편 10과 중복하지 않는다.
- 시간대 적용 판정은 `currentTimePeriod`를 단일 원본으로 사용하고, 변경 알림에는 `toTimePeriod`·`fromTimePeriod` 같은 중복 시간대 값을 넣지 않는다.
- `timeShiftTarget`, `canTimeShift`, `timeShiftEvent`는 저장 변수로 두지 않는다.
- `pastMoveBonus`, `futureNormalAttackBonus`는 별도 변수로 두지 않고 현재 시간대에 따른 고정 규칙으로 적용한다. `timePeriodChanged`는 변경 알림으로 유지한다.

## 완료한 일

- 시간대 전환 시스템의 책임을 현재 시간대, 시간 파편, 계획 단계 전환, 체류 턴, 시간대 공통 버프와 변경 이벤트로 한정했다.
- 캐릭터 문법과 유물 문법, `relicTimeTags` 정의를 시간대 전환 문서에서 제거했다.
- 캐릭터 시스템은 캐릭터 태그·스킬 전환·공유 쿨타임을, 가방·유물 시스템은 가방 칸 시간대·유물 배치·효과 활성 판정을 소유하도록 경계를 정리했다.
- 유물에는 시간대를 저장하지 않는다고 확정 문서와 전체 기획 관리에 반영했다.
- 시간 전환 처리의 원자성, 버프 비중첩과 `timePeriodChanged` 1회 전달을 명시했다.
- 외부 시스템이 변경 알림을 받은 뒤 `currentTimePeriod`를 직접 읽도록 정리하고 중복 이벤트 필드를 제거했다.
- 과거·미래 버튼 값은 일회성 입력으로 사용하고 전환 가능 여부는 즉시 계산하며 결과 알림은 `timePeriodChanged`로 통일했다.
- 시간대 효과 모듈의 두 보정 변수를 제거하고 과거 아군 이동력 +1·미래 아군 일반 공격력 +3을 고정 규칙으로 남겼다.
- 캐릭터 문서에 남아 있던 폐기된 과거 일반 공격·현재 치명타 보정을 미래 아군 일반 공격 +3 규칙으로 교정했다.
- 과거 이동력 +1과 미래 일반 공격력 +3을 아군 전용 버프로 명시하고 적군 적용을 제외했다.

## 검토 결과

- 기존 문서는 시간대 시스템이 캐릭터·유물 문법과 활성 판정을 함께 소유해 책임이 중복되어 있었다.
- 유물 자체의 복수 시간대 태그는 가방 칸 기준 단일 시간대 적용 결정과 충돌했다.
- 전환 시 상태·버프·외부 시스템 갱신 순서와 이벤트 중복 방지 기준이 부족해 이를 보완했다.
- 캐릭터 문서에 과거 버전의 시간대 능력치 보정이 남아 있어 확정 시간대 규칙과 충돌하던 문제를 해소했다.
- 현재 기획 문서 기준으로 캐릭터 문법은 캐릭터 시스템에만 남고, 유물 활성은 가방 칸 시간대를 기준으로 한다.

## 미결정·후속 작업

- 가방·유물 시스템 단일 원본 문서가 필요하다.
- 프로토타입과 `도구/전투 프로토타입/유물_문법.md`의 `relicTimeTags` 구현을 가방 칸 시간대 방식으로 이관해야 한다.
- 프로토타입 v5의 미래 아군 치명타 피해율 +20%p를 확정 규칙인 미래 아군 일반 공격력 +3으로 이관해야 한다. v3의 시간대 능력치 버프는 이미 아군에게만 적용된다.

## 검증

- 확정 문서에서 `relicTimeTags`, `TIME_TAGS`, 폐기된 시간대 능력치 보정 잔재를 검색했다.
- 시간대 전환 문서에 캐릭터·유물 콘텐츠 문법이 남지 않았음을 확인했다.
- `git diff --check`를 통과했다. 줄바꿈 변환 경고 외 형식 오류는 없다.
