# 전투 프로토타입 2.0 리팩터링

> 날짜: 2026-09-03
> 상태: 사용자 화면 검토에서 기각·보류 / 기존 v3 직접 수정으로 방향 전환
> Git: 로컬 미커밋, GitHub 미동기화

## 목표

과도하게 누적된 v3의 모바일·복수 말판·유물·UI 분기를 제거하고, 전장 배경과 모든 Phaser 표시가 하나의 좌표계와 명시적 레이어 계약을 사용하는 새 데스크톱 전용 6×6 프로토타입을 만든다.

## 사용자 결정

- 새 경로는 `도구/전투 프로토타입/프로토타입 2.0/`으로 한다.
- 기존 회중시계 외형과 전투·시간 시스템 내용은 유지한다.
- 메인 → 배치 → 전투 → 결과 → 다시하기 흐름을 유지한다.
- 모바일 모드, 9×9 격자, 유물 시스템을 제거한다.
- 상단 행동바의 공통 반투명 배경을 제거해 고원지대 배경이 한 화면으로 이어지게 한다.
- 격자·이동·공격·선택·반격 표시와 원형 행동바·계획 완료·적 계획 공개·순서 교체 규칙을 새 UI 기준으로 적용한다.

## 구현

- `1920×1080` 고정 Phaser 전장에 배경, 6×6 격자, 범위, SD, 효과를 통합했다.
- 배경 원본 `9750×4500`을 `3900×1800` WebGL용 사본으로 최적화했다. 원본은 변경하지 않았다.
- 전투 상태와 계산은 `src/core`, 좌표와 렌더링은 `src/render`, DOM HUD는 `src/ui`로 분리했다.
- 캐릭터마다 하나의 `UnitView`를 유지하고, 기본 격자·계획·캐릭터·딤·포커스·효과·텍스트 깊이 구간을 고정했다.
- 단일 Phaser 포인터 입력을 셀 좌표로 변환해 타일과 SD가 클릭 우선순위를 다투지 않게 했다.
- 기본 회색 격자, 진영별 이동 외곽선, 선택 가능·선택 완료 범위, 반격 빗금, 발자국, 거리별 밀치기 화살표를 분리했다.
- 적 계획 순차 공개, 원형 행동 순서, 계획 완료 오라, 실행 슬롯 확대, 2초 길게 누르기 순서 교체를 구현했다.
- 배경 없는 원형 공격·스킬 버튼과 상단 확정 버튼, 작전타임/작전 개시 플립을 구현했다.
- 전투 실행에는 이동, 공격, 스킬, 반격, 밀치기, 상태이상, 치명타, 사망, 시간 추가 피해와 시간 조작을 연결했다.
- 모바일·9×9·유물 관련 런타임 코드는 새 `src`에 포함하지 않았다.

## 사용자 검토 결과와 전환

- 사용자 화면 검토에서 격자·SD·UI 배치와 전체 인상이 기존 v3보다 나쁘다는 판정을 받았다.
- 새 구조를 리팩터링 결과로 채택하지 않고 기존 v3를 직접 수정하는 방향으로 전환했다.
- 새 배경·격자 규칙·원형 행동 UI 중 필요한 표시 사양만 v3에 다시 구현하며, 신규 초안 코드를 구조째 병합하지 않는다.
- 첫 v3 UI 적용에서 배경과 보드를 같은 확대 폭으로 강제해 보드가 과도하게 커진 문제가 발생했다. 후속 수정에서 배경은 화면 채움, Phaser 보드는 기존 `1920×893` 비율과 화면 폭 100%를 사용하도록 분리했다.
- 공격·스킬 버튼 글자를 복원하고 확정 버튼 크기를 바로잡았으며, 순서 변경 길게 누르기를 1초로 줄이고 안내 문구를 `캐릭터 행동 순서 변경`으로 변경했다.
- 배치 화면을 실제로 띄워 배경 안쪽 마름모 선과 6×6 격자의 네 꼭짓점을 비교했다. 격자 배율만 추측해 바꾸던 값을 폐기하고 가로 크기, 세로 아이소메트릭 비율, X 원점, Y 중심을 함께 보정했으며 `npm.cmd run build:standalone`으로 독립 실행판을 갱신했다.
- 공격·스킬 선택 중 Phaser 캔버스 경계에서 딤이 끊겨 배경이 수평으로 잘려 보이는 문제를 확인했다. `targeting-focus` 상태를 DOM에 동기화하고 캔버스 바깥의 위·아래 배경에도 Phaser 딤과 같은 농도를 적용해 경계가 이어지도록 수정했다.
