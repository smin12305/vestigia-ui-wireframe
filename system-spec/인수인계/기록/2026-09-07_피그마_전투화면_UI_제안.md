# Figma 전투 화면 UI 제안

> 작성일: 2026-09-07
> 기준 브랜치: `codex/time-system-combat`
> 기준 커밋: `5cc58be`
> 산출물 상태: `[제안]`

## 목표

- 쿼터뷰에서 플랫 사각 보드로 바뀐 전투 방향을 반영해 Waredo 2.0 전투 화면의 Figma 제안 시안을 만든다.
- 전투 흐름을 끊는 별도 시간 이동 창 없이, 충전 완료 순간 전투 화면에서 바로 과거 또는 미래를 선택하는 UX를 시각화한다.

## 사용자 결정

- 전투판은 정면에서 내려다보는 플랫한 `6×6` 사각 격자를 사용한다.
- 시간 파편 게이지가 가득 차 시간 이동이 가능할 때 별도 창·모달·확인창을 사용하지 않는다.
- 시간 이동은 전투 화면 안에서 즉시 선택 가능해야 한다.
- 시간 이동 UX는 v5의 회중시계 외곽 충전 링과 시간 선택 서랍을 참고한다.

## 설계 반영

- 새 Figma 디자인 파일 [`Waredo 2.0 전투 화면 UI 제안`](https://www.figma.com/design/g8Zbg92TSdRibOzSgHdzD3)을 생성했다.
- `1920×1080` 화면 중앙에 플랫 `6×6` 보드를 배치했다.
- 상단에는 아군·적군의 행동 순서를, 우측에는 선택 캐릭터와 계획 정보를, 하단에는 행동 명령을 배치했다.
- 좌측 회중시계에 시간 파편 `100/100` 충전 상태를 표시하고, 같은 전투 화면에서 `과거로 회귀`와 `미래로 도약`을 바로 선택하도록 구성했다.
- v5는 회중시계와 시간 선택 노출 방식만 참고했다. 미래 보너스 문구는 최신 확정 문서 기준인 `아군 일반 공격력 +3`을 사용했다.

## 검증 결과

- 전체 화면 캡처로 `1920×1080` 프레임과 주요 HUD 배치를 확인했다.
- 폰트 QA에서 잘못된 폰트 0개를 확인했다.
- 바인딩 QA에서 변수에 연결되지 않은 단색 페인트 0개를 확인했다.
- 전체 노드 198개, 텍스트 84개, 인스턴스 22개를 다시 확인했다.
- 미래 보너스 문구가 폐기된 v5 치명타 보너스가 아니라 `아군 일반 공격력 +3`으로 표시되는지 확인했다.

## 미결정·주의사항

- 이번 산출물은 UI 제안 시안이다. 확정 기획 문서나 프로토타입 구현 상태를 변경하지 않는다.
- 실제 플레이 기준의 정보 밀도, 클릭 영역, 패널 비율과 시선 흐름은 사용자 검토 후 조정할 수 있다.
- v5에 남은 미래 아군 치명타 피해율 `+20%p`는 현재 규칙으로 사용하지 않는다.
- 확정·제안 기획 문서는 이번 작업에서 수정하지 않았다.

## 모바일 가로 클릭 프로토타입 `[방향 기각]`

> 최신 상태: 사용자가 모바일에 맞지 않아 요소만 가져오고 처음부터 다시 설계해야 한다고 평가했다. 아래 내용은 제작·검증 이력이며 승인되거나 완료된 모바일 디자인을 뜻하지 않는다.

### 목표와 설계 원칙

- 같은 Figma 파일의 `04 Battle Screens`에서 모바일 가로 환경의 전술 입력 흐름을 직접 눌러 확인할 수 있게 한다.
- 명일방주 레퍼런스의 각진 검정 패널, 흰 테두리, 주황 핵심 CTA와 가장자리 HUD를 참고해 시각 체계를 통일한다.
- SRPG 레퍼런스 원칙에 따라 이동과 공격 범위를 분리하고, 대상 확정 단계를 두며, 중앙 전장을 HUD로 가리지 않는다.
- 모바일 입력을 위해 시각 요소보다 넓은 투명 히트 영역을 사용한다.

### 완료한 일

- `1920×1080` 모바일 가로 SRPG 클릭 프로토타입을 구성했으나 사용자 검토에서 모바일 디자인 방향이 기각됐다.
- 시작점 `18:68`의 이름을 `PROTO / P0 전투 기본 · Mobile Landscape`로 지정하고 `flowStartingPoint`를 `Waredo Mobile SRPG Battle`로 설정했다.
- 상태 프레임을 다음과 같이 구성했다.
  - P1 이동: `34:68`
  - P2 공격: `34:231`
  - P3 대상 확정: `34:394`
  - P4 과거: `34:557`
  - P5 미래: `34:720`
  - P6 일시정지: `34:883`
  - P7 행동 실행: `34:1046`
- 기본 → 이동/공격 → 대상 확정 → 행동 실행 → 기본의 전술 입력 흐름을 연결했다.
- 기본과 전술 상태에서 과거·미래로 즉시 전환하고, 일시정지에 진입했다가 복귀할 수 있게 연결했다.
- 과거·미래 상태에는 비용 소모 후 시간 파편 `0/100`, 시간대 보너스와 남은 `2턴`을 표시했다.
- `2턴 경과` 입력으로 현재 시간대 자동 복귀를 시연하도록 구성했다.

### 검증 결과

- P0~P7의 반응 노드 수가 각각 `5/5/5/5/1/1/3/2`인 것을 확인했다.
- `flowStartingPoint`가 `Waredo Mobile SRPG Battle`로 정상 설정된 것을 확인했다.
- 폰트는 `Noto Sans KR Bold`와 `Noto Sans KR Regular`만 사용했다.
- 기본, 이동, 과거, 일시정지 상태 스크린샷에서 배경·캐릭터·HUD와 상태별 표시가 정상 렌더링되는 것을 확인했다.
- Figma 변경은 클라우드 파일에 반영됐다.

### 다음 작업

## 모바일 재설계용 요소 수집

### 사용자 결정

- 기존 모바일 시안은 모바일에 맞지 않으므로 요소만 가져와 처음부터 다시 설계한다.
- 현재 시안을 승인되거나 완료된 모바일 디자인으로 취급하지 않는다.
- 우선 UI 요소, 캐릭터와 다양한 범위 표시 재료를 수집한다.

### 확인한 재료

- v5 `content.ts`, `patterns.ts`, `characterAssets.ts`, `BattleScene.ts`에서 아군 3명과 타락 성기사를 포함한 적 이미지 4종을 확인했다.
- 방향 선택 직선 1~5칸을 각각 확인했다.
- 자기 중심 `3×3`, 자기 중심 `5×5`, 곡사 착탄 `3×3`, 반격 주변 8칸을 확인했다.
- 위 직선 5종과 범위 4종을 합친 9종 범위 비교 시각화를 대화에 제공했다.
- 이동 가능 범위와 이동 도착 홀로그램 표시도 함께 확인했다.
- 범위 비교 시각화는 v5 코드 정의를 바탕으로 만든 도식이며 실제 게임 캡처나 전투 플레이 검증 결과가 아니다.

### 이번 단계의 변경 범위

- 요소 수집은 읽기 전용으로 진행했다.
- Figma와 게임 코드는 수정하지 않았다.
- 기존 Figma 프레임의 가짜 수치, 지원 배치와 별도 궁극기 슬롯은 현재 규칙으로 승계하지 않는다.

### 다음 작업

1. 사용자가 수집된 캐릭터·UI 요소와 9종 범위 비교 재료를 검토한다.
2. 모바일 실제 표시 크기와 터치 영역 기준을 정한다.
3. 빈 레이아웃에서 전투 화면을 처음부터 다시 설계한다.
4. 새 설계에는 이동·공격 범위 분리, 대상 확정, 중앙 전장 보호와 전투 화면 내 즉시 시간 전환만 현재 규칙에 맞춰 반영한다.
