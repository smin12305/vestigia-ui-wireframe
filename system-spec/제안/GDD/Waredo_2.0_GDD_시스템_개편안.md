| 그래픽 기반 | 2D 기반 2.5D | 3D 기반 2.5D | 모바일 쿼터뷰와 기존 디자인 무드를 유지하며 표현 기반 전환 |
| UI·연출 | 기존 UI·연출 | 전투 UI, 스킬 이펙트, 애니메이션 전반 고도화 | 행동 설계에 필요한 정보 제공과 빠른 전투 연출 지원 |
| 개발 방식 | 기존 개발 구조 | 전반적인 리팩토링 후 핵심 시스템 우선 구현 | 시스템 검증 후 콘텐츠를 쌓고 반복 기준을 시스템 기획에서 선정의 |

- 캐릭터·배경 시나리오, 대화 시나리오 시스템, 디자인 에셋과 무드, 배경, 정사각형 전투판, 아웃게임 요소 및 환경 요소 시스템은 유지 대상이다.
- 유지 대상도 단순 이관하지 않고 3D 기반 2.5D 전환과 개편된 전투 구조에 맞는지 최소 1회 이상 검토 및 업데이트한다.
- 콘텐츠 상세와 최종 MVP 범위는 시스템 검증 및 회의 이후 정의한다.

## 1. 개편 개요

### 1.1 프로젝트 목적

**쿼리도 슈팅**을 **Waredo 2.0**으로 전면 개편한다.

기존 2D 기반 2.5D에서 **3D 기반 2.5D**로 변경하며, Unity 기반 모바일 쿼터뷰 게임으로 개발한다. 핵심 재미는 **쿼리도 + 턴제전투**에서 **위치 변경 계산을 중심으로 한 턴 설계형 난투 게임**으로 변경한다.

플레이어는 밀치기, 당기기, 띄우기, 기절 등 상태이상과 위치 이동을 활용한다. 행동에 따라 달라지는 아군·적군·환경 요소의 위치를 계산하고, 그 결과를 고려해 행동 순서와 내용을 설계한다. 설계에는 충분한 시간을 제공하고, 확정된 전투 행동은 빠르게 연출하여 난투의 분위기를 만든다.

개발 전반은 리팩토링을 전제로 한다. 시스템 구현을 빠른 기간 안에 진행하고, 이를 기반으로 콘텐츠를 쌓아간다. 콘텐츠 기획에서 반복적으로 발생하는 기준은 가능한 한 시스템 기획에서 선제적으로 정의하여 불필요한 리소스 소모와 게임 기획 과열을 막는다.

`[유지]` 시스템과 요소도 단순 이관하지 않고 최소 1회 이상 검토 및 업데이트를 권장한다.

### 1.2 기획 의도

Waredo 2.0은 기존의 **쿼리도와 턴제 전투를 결합한 구조**에서 벗어나, 플레이어가 한 턴의 행동 순서와 위치 변화를 미리 설계한 뒤 그 결과를 빠르게 확인하는 **턴 설계형 난투 게임**을 목표로 한다.

플레이어는 단순히 공격 대상을 선택하는 것이 아니라 캐릭터의 이동 경로와 행동 시점, 공격 또는 스킬의 범위와 방향을 함께 결정한다. 밀치기와 당기기로 캐릭터의 위치를 바꾸고, 띄우기로 치명타 조건을 만들며, 기절로 특정 행동 슬롯을 패스시키는 방식으로 전투의 흐름을 설계한다. 위치 변경은 피해를 주기 위한 보조 기능이 아니라 공격 기회, 행동 실패, 충돌 및 환경 요소 발동에 연결되는 핵심 판단 요소다.

전투의 리듬은 **긴 행동 설계와 빠른 행동 연출**의 대비로 구성한다. 행동 설계 단계에서는 플레이어가 순서와 위치를 충분히 계산할 수 있도록 시간을 제공하고, 턴 종료로 계획을 확정한 뒤에는 아군과 적군의 행동을 빠르게 이어서 보여주어 난투의 분위기를 만든다.

개발은 전반적인 리팩토링을 전제로 핵심 시스템을 먼저 빠르게 구현하고 검증한 뒤, 확정된 시스템 규격을 기반으로 콘텐츠를 쌓는 방향으로 진행한다. 스킬·유물·캐릭터 등 콘텐츠 기획에서 반복되는 조건과 변수는 가능한 범위에서 시스템 기획이 먼저 정의하여 불필요한 리소스 소모와 기획 과열을 방지한다.

기존 캐릭터·배경 시나리오, 대화 시나리오 시스템, 디자인 에셋과 무드, 배경, 아웃게임 요소 등 유지 대상은 정체성을 이어받되, 3D 기반 2.5D 전환과 변경된 전투 구조에 맞는지 최소 1회 이상 검토하고 업데이트한다.

위치 변경 결과를 별도의 예상 결과 UI 없이도 플레이어가 충분히 이해할 수 있는지는 핵심 논의 및 검증 대상으로 둔다.

회중시계를 이용한 **시간대 전환**을 핵심 전투 시스템으로 추가한다. 플레이어는 행동 설계 단계에서 과거·현재·미래 중 해당 턴의 시간대를 선택하며, 위치·행동 순서 설계에 더해 전장 전체의 피해·치명타·회복 규칙까지 설계한다. 시간대 선택은 위치 계산을 대체하지 않고 같은 행동 계획의 위험과 보상을 바꾸는 상위 판단으로 작동한다.

### 1.3 게임 핵심 루프

#### 전체 진행 루프

```text
메인 메뉴
→ 도전 모드 입장
→ 타일 선택
→ 전투 입장
→ 전투 진행
→ 승리 또는 패배
→ 결과 이후 진행 [작성 필요]
```

- 메인 메뉴, 도전 모드, 타일 선택 및 기존 아웃게임의 상세 구조는 현재 시스템을 유지한다.
- 전투 타일을 선택하면 해당 레벨의 정사각형 전투판으로 진입한다.
- 승리·패배 결과 이후의 보상, 재도전 및 다음 진행 방식은 `[작성 필요]`다.

#### 전투 핵심 루프

```text
레벨별 설치 가능 범위에 캐릭터 초기 배치
→ 전투 시작
→ 첫 턴은 동전 던지기, 이후 턴은 교대로 선공 결정
→ 행동 슬롯 생성 및 적 행동 예고
→ 아군 행동 순서·이동 경로·일반 공격 또는 스킬 설계
→ 현재 보유 시간 파편으로 이번 턴의 시간대 선택
→ 턴 종료 입력으로 계획 확정
→ 시간대 전환 비용 소비·시간대 효과·유물 활성 상태 확정
→ 행동 번호 순서에 따라 아군·적군 행동을 빠르게 실행
→ 각 피해·효과 처리 후 승리·패배 즉시 판정
→ 승패가 없고 모든 행동이 끝나면 상태이상·쿨타임·환경 요소·유물 카운트 정산
→ 정산 결과 승리·패배 판정
→ 전투가 계속되면 선공 진영을 교대하고 다음 턴 설계로 반복
```

1. 플레이어는 전투 입장 후 레벨별 설치 가능 범위 안에 모든 출전 캐릭터를 배치한다.
2. 첫 턴의 선공 진영은 동전 던지기로 결정하고, 이후 턴부터는 선공 진영을 교대한다.
3. 선공 진영부터 아군과 적군의 행동 슬롯을 교차로 생성하며, 교차 배치가 불가능한 남은 캐릭터는 후순위에 배치한다.
4. 적 행동 시스템은 타겟과 예정 이동 경로를 예고한다. 적 AI의 구체적인 행동 결정 기준은 `[추후 기획]`이다.
5. 플레이어는 아군 행동 슬롯에 캐릭터를 배치하고 각 캐릭터의 이동 경로와 일반 공격 또는 스킬을 설계한다.
6. 턴 종료 전까지 아군 캐릭터의 행동 순서와 계획 및 이번 턴에 적용할 시간대를 자유롭게 수정할 수 있다.
7. 시간대 변경에 사용할 수 있는 시간 파편은 계획 확정 시점의 현재 보유량이다. 이번 턴의 공격·콤보·턴 경과로 얻을 예상 파편은 미리 표시하지만 다음 턴부터 사용할 수 있다.
8. 턴 종료를 누르면 행동 계획과 선택 시간대를 함께 검증·확정한다. 다른 시간대로 변경한다면 비용을 소비하고 시간대 효과와 유물 활성 상태를 갱신한 뒤 행동 번호에 따라 아군과 적군의 행동을 빠르게 실행한다.
9. 실행 중 위치와 셀 점유는 셀 단위로 갱신된다. 이동 경로가 막히면 직전 유효 셀에서 정지하고 해당 캐릭터의 이후 공격 또는 스킬을 취소한다.
10. 각 행동에서 이동은 최대 1회, 일반 공격 또는 스킬은 최대 1회 사용할 수 있다. 공격이나 스킬만 제자리에서 사용하는 것은 가능하지만 공격 또는 스킬 이후 이동할 수는 없다.
11. 아군의 직접 공격이 적에게 1 이상의 피해를 주면 시간 파편을 얻는다. 공격 행동 시작 시 적이 기절 또는 띄워짐 상태였다면 콤보 추가 파편을 함께 얻는다.
12. 피해와 효과 묶음을 처리할 때마다 승패를 판정한다. 모든 적이 전투 불능이면 즉시 승리하고 모든 아군이 전투 불능이면 즉시 패배하며, 남은 행동을 중지한다.
13. 승패가 결정되지 않은 상태로 모든 행동이 끝나면 상태이상, 스킬·유물 쿨타임, 환경 요소 및 유물 카운트를 정산하고 턴 경과 충전을 지급한 뒤 승패를 다시 판정한다.
14. 정산 후에도 전투가 계속되면 선공 진영을 교대하고 다음 턴을 반복한다.

## 2. 핵심 용어

### 2.1 전투 흐름

| 용어 | 정의 |
|---|---|
| 전투 | 전투판에 배치된 아군과 적군이 턴과 행동을 반복하며 승리·패배 조건을 판정하는 전체 과정. |
| 턴 | 전투가 진행되는 반복 단위. 행동 설계, 행동 실행, 턴 종료 정산으로 구성된다. |
| 행동 | 턴 안에서 캐릭터 한 명이 배정받는 실행 단위. `적 → 아군 → 적` 구조에서 각 항목 하나가 행동 1회다. |
| 행동 슬롯 | 해당 턴에 행동할 진영과 캐릭터가 배치되는 순서 자리. 행동 가능한 캐릭터는 해당 진영의 슬롯에 정확히 한 번 배치된다. |
| 행동 번호 | 행동 슬롯이 실행되는 1 기반 순서 번호. 예: 1·2·3·4·5·6번 행동. |
| 행동 계획 | 행동 슬롯에 배치된 캐릭터의 이동 경로와 일반 공격·스킬·행동 없음 중 선택한 내용을 합친 데이터. |
| 행동 설계 | 플레이어가 아군 행동 슬롯의 캐릭터 순서와 행동 계획을 작성하고 수정하는 단계. |
| 선공 | 해당 턴의 첫 행동 슬롯을 배정받는 진영. 첫 턴은 동전 던지기로 결정하고 이후 턴에는 교대한다. |
| 후순위 슬롯 | 양 진영의 행동 가능 캐릭터 수가 달라 교차 배치할 수 없는 남은 캐릭터를 위해 뒤에 연속으로 추가하는 행동 슬롯. |
| 턴 종료 입력 | 행동 설계를 끝내고 계획 검증과 잠금을 요청하는 플레이어 입력. 입력 즉시 실제 턴이 끝나는 것은 아니다. |
| 계획 확정 | 검증을 통과한 행동 순서와 행동 계획을 잠가 더 이상 수정할 수 없게 된 상태. |
| 턴 종료 정산 | 모든 행동 슬롯 실행 후 상태이상, 쿨타임, 환경 요소와 유물 카운트를 처리하는 단계. |
| 전투 불능 | 현재 체력이 0에 도달한 캐릭터 상태. 즉시 해당 셀 점유를 해제하고 남은 행동을 무효화한다. |
| 승리 | 모든 적 캐릭터가 전투 불능이 된 전투 결과. |
| 패배 | 모든 아군 캐릭터가 전투 불능이 된 전투 결과. 아군과 적군이 같은 효과 묶음에서 모두 전투 불능이 되면 패배한다. |

### 2.2 전투판과 위치 이동

| 용어 | 정의 |
|---|---|
| 전투판 | 전투가 진행되는 정사각형 격자 판. |
| 셀 | 전투판의 논리적인 최소 좌표 단위. 시스템 규칙과 변수에서는 `셀`을 사용한다. |
| 점유 | 캐릭터 한 명이 특정 셀을 사용하고 있는 상태. 하나의 셀은 캐릭터 한 명만 점유할 수 있다. |
| 유효 셀 | 전투판 안에 있고 이동 가능한 셀이며 다른 캐릭터가 점유하지 않은 셀. |
| 초기 설치 가능 셀 | 레벨 데이터가 전투 시작 전 캐릭터 배치를 허용한 셀. 전투 시작을 위해서는 전투판 안·이동 가능·미점유 조건도 만족해야 한다. |
| 스킬 설치 가능 셀 | 설치형 스킬로 환경 요소를 생성할 수 있는 셀. 구체적인 셀 조건은 설치형 스킬 규칙에서 `[작성 필요]`다. |
| 이동 경로 | 캐릭터가 이동할 셀을 직교 방향으로 연결한 순서 목록. 대각선 이동은 허용하지 않는다. |
| 일반 이동 | 캐릭터가 자신의 이동력을 사용하여 계획된 경로를 따라 이동하는 행동. |
| 강제 이동 | 밀치기 또는 당기기로 대상의 위치가 바뀌는 처리. 일반 이동과 같은 셀 진입 가능 판정을 사용한다. |
| 충돌 | 이동할 다음 셀에 진입할 수 없어 직전 유효 셀에서 정지하는 처리. 일반 이동 중 발생하면 남은 경로와 해당 행동의 일반 공격·스킬을 취소하고, 강제 이동 중 발생하면 남은 강제 이동 거리만 폐기한다. |
| 위치 변경 계산 | 이동·밀치기·당기기와 실시간 셀 점유 변화가 이후 경로, 공격, 스킬 및 환경 요소에 미칠 결과를 계산하는 핵심 전투 요소. |

### 2.3 일반 공격과 스킬

| 용어 | 정의 |
|---|---|
| 일반 공격 | 캐릭터의 유효 공격력을 기본 피해로 사용하는 행동. 행동 1회에서 스킬과 함께 사용할 수 없다. |
| 스킬 | 캐릭터가 한 개씩 보유하는 쿨타임 기반 행동. 사용한 행동에서는 일반 공격을 사용할 수 없다. |
| 범위 내 타겟팅 | 이동했다면 계획한 이동 경로의 마지막 셀, 이동하지 않았다면 현재 셀을 기준점으로 삼아 범위 안의 캐릭터 한 명을 선택하고 별도 방향 선택 없이 시전하는 유형. |
| 셀 선택 일반 공격 | 행동 캐릭터를 기준으로 `방향 선택 → 범위 안 셀 선택` 순서로 지정하고 해당 영향 셀의 대상을 공격하는 일반 공격 유형. |
| 셀 선택 스킬 | 범위 안의 셀을 선택하고 해당 셀을 기준으로 즉시 효과를 처리하는 스킬 유형. 별도 방향을 선택하지 않는다. |
| 설치형 스킬 | 설치 가능한 범위 안의 셀을 선택하고 해당 셀에 환경 요소를 생성하는 스킬 유형. 상세 설치·유지·발동 규칙은 `[작성 필요]`다. |
| 방향성 | 이동했다면 이동 완료 위치, 이동하지 않았다면 현재 위치를 기준으로 상·하·좌·우 중 하나를 선택하여 해당 방향으로 시전하는 유형. |
| 범위 패턴 | 행동 캐릭터의 기준 위치에서 선택하거나 공격할 수 있는 셀의 배치 데이터. 방향성 유형은 선택 방향에 맞춰 회전한다. |
| 영향 셀 패턴 | 일반 공격 또는 스킬이 실제로 효과를 적용하는 셀의 배치 데이터. |
| 쿨타임 최대값 | 스킬 사용 후 설정되는 최대 쿨타임. 유효값은 1 이상이다. |
| 현재 쿨타임 | 스킬을 다시 사용할 수 있기까지 남은 턴 단위 값. 0일 때 스킬을 사용할 수 있으며, 사용한 턴에는 감소하지 않고 다음 `TurnSetup`부터 감소한다. |

### 2.4 상태이상과 피해

| 용어 | 정의 |
|---|---|
| 상태이상 | 밀치기·당기기·띄워짐·기절을 처리하는 효과 구분. 밀치기와 당기기는 즉시 처리하고, 띄워짐과 기절은 상태 인스턴스로 유지한다. |
| 밀치기 | 방향성 스킬의 선택 방향으로 대상을 N칸 강제 이동시키는 상태이상. |
| 당기기 | 방향성 스킬의 선택 방향과 반대 방향으로 대상을 N칸 강제 이동시키는 상태이상. |
| 띄워짐 | 대상이 공중에 떠 있는 지속형 상태이상. 대상의 다음 행동 시작 또는 적용된 턴 종료 중 먼저 발생한 시점까지 유지된다. |
| 기절 | 적용된 현재 턴에 대상의 행동 슬롯을 소비하고 패스시키는 지속형 상태이상. 해당 턴 종료 시 해제되며 대상이 이미 행동했다면 그 턴에는 전투상 효과가 없다. |
| 치명타 | 띄워짐 상태의 대상에게 적용하는 피해 판정. 일반 공격은 항상 적용하고 스킬은 해당 스킬의 치명타 적용 가능 여부에 따른다. |
| 치명타 피해율 | 치명타 판정 시 피해에 적용하는 캐릭터 파라미터. `100%`는 일반 피해와 같으며 초기에는 모든 캐릭터가 같은 값을 가지고 유물로 변경할 수 있다. |
| 타입 상성 | 기존 캐릭터 타입 간 피해 관계. 유리하면 피해가 50% 상승하고 불리하면 50% 감소한다. |

### 2.5 연계 시스템

| 용어 | 정의 |
|---|---|
| 유물 | 가방에서 캐릭터 장비창으로 드래그하여 장착하는 캐릭터 장착형 요소. 캐릭터 한 명당 최대 3개를 장착하며 같은 캐릭터에게 같은 유물을 중복 장착할 수 없다. |
| 트리거형 유물 | 전투 이벤트와 조건을 확인하여 효과를 발동하거나 누적 카운터를 변경하는 유물 유형. |
| 환경 요소 | 전투판의 지정 셀에서 진입·이동 종료·행동·턴 종료 등의 조건에 따라 피해 또는 효과를 발생시키는 시스템 요소. 상세 종류와 상호작용은 고도화 대상이다. |
| 적 행동 예고 | 적이 지정한 대상 캐릭터와 예정 이동 경로를 행동 설계 전에 플레이어에게 보여주는 정보. |
| 효과 큐 | 공격·스킬·상태이상·환경 요소·유물로 발생한 효과 요청을 등록하고 순서대로 처리하는 목록. 동일 우선순위의 처리 순서는 `[작성 필요]`다. |
| 효과 묶음 | 하나의 시작 효과와 그 효과로 연쇄 발생한 반응 효과를 승패 판정 전까지 처리하는 단위. |
| FSM | 전투 흐름, 행동 실행 및 캐릭터 표현 상태와 전이 조건을 관리하는 상태 구조. |

### 2.6 시간대 전환

| 용어 | 정의 |
|---|---|
| 시간 파편 | 전투 중 턴 경과·유효 공격·상태이상 콤보로 획득하여 회중시계에 보관하고 시간대 변경에 사용하는 전투 공용 자원. 기존 회중시계 충전량을 대체한다. |
| 현재 시간대 | 현재 전장에 적용 중인 `과거·현재·미래` 중 하나. 전투는 `현재`에서 시작한다. |
| 선택 시간대 | `Planning`에서 플레이어가 이번 턴에 적용하도록 선택한 시간대. `PlanLocked`에서 잠긴다. |
| 시간대 유지 | 선택 시간대와 현재 시간대가 같은 상태. 충전 비용과 전환 연출은 없지만 해당 시간대의 턴 시작 효과는 처리한다. |
| 시간대 변경 | 선택 시간대와 현재 시간대가 다른 상태. 현재 보유 시간 파편이 필요한 수량 이상일 때만 가능하다. |
| 유효 공격 충전 | 아군의 일반 공격 또는 피해 스킬이 적에게 1 이상의 직접 피해를 준 공격 행동 1회에 지급하는 충전. |
| 상태이상 콤보 충전 | 공격 행동 시작 시 기절 또는 띄워짐 상태인 적에게 유효 공격을 성공시켰을 때 기본 충전에 추가하는 충전. |
| 시간대 효과 | 현재 시간대에 따라 양 진영에 적용되는 타입 피해 강화 및 전장 공통 규칙. 캐릭터·스킬 원본 데이터와 분리한다. |
| `TimeShiftResolution` | 잠긴 선택 시간대를 실제 전투 상태에 반영하고 비용·유물·턴 시작 효과·연출 요청을 처리하는 `PlanLocked`와 `Executing` 사이 단계. |

### 3.2 시스템 의존성 도식

```text
전투 시스템
  → {초기 배치 시스템, 행동 순서 시스템, 행동 설계 시스템, 시간대 전환 시스템, FSM, 상태이상 시스템, 적 행동 시스템}
  → 정사각형 전투판 시스템 → {이동 시스템, 환경 요소 시스템}

정사각형 전투판 시스템 → 초기 배치 시스템
캐릭터 시스템 ↔ 초기 배치 시스템
초기 배치 시스템 → 행동 순서 시스템

행동 순서 시스템 → 행동 설계 시스템
행동 설계 시스템 → {이동 시스템, 공격·타겟팅 시스템, 스킬·쿨타임 시스템}
행동 설계 시스템 → 시간대 전환 시스템 → {공격·타겟팅 시스템, 유물 시스템, UI, 연출}

캐릭터 시스템 ↔ {전투, 행동 순서, 행동 설계, 이동, 공격·타겟팅, 스킬·쿨타임, 상태이상}
적 행동 시스템 ↔ {행동 순서, 이동, 공격·타겟팅, 스킬·쿨타임}
상태이상 시스템 ↔ {행동 순서, 이동, 공격·타겟팅, 스킬·쿨타임, 유물}

아웃게임 시스템 → {가방 시스템, 유물 시스템, 대화 시나리오 시스템}
가방 시스템 → 유물 시스템 → 캐릭터 시스템
유물 시스템 ↔ {전투 시스템, 행동 순서 시스템, 캐릭터 시스템, 이동 시스템, 공격·타겟팅 시스템, 스킬·쿨타임 시스템, 상태이상 시스템}
```

## 4. 변수 관리

같은 의미의 변수는 하나의 시스템에서만 원본을 정의한다. 다른 시스템은 원본 변수를 참조하거나 해당 시스템에 변경을 요청한다.

모든 수치 계산은 전체 계산을 완료한 최종 단계에서 반올림한다. 중간 계산 단계에서는 반올림하지 않는다.

| 변수 | 의미 | 정의·소속 시스템 | 값을 활용하는 시스템 | 연결 관계 |
|---|---|---|---|---|
| 최대 체력 | 캐릭터 체력의 상한 | 캐릭터 | 전투, 공격, 스킬, 상태이상, 유물, UI | 캐릭터 기본값 + 유물 보정 → 최대 체력 |
| 현재 체력 | 전투 중 남아 있는 체력 | 캐릭터 | 전투, 공격, 스킬, 상태이상, 승패 판정, UI | 피해 결과 → 현재 체력 → 전투 불능 판정 |
| 공격력 | 일반 공격 피해 | 캐릭터 | 공격·타겟팅, UI | 공격력 → 일반 공격 피해 |
| 이동력 | 이동할 수 있는 셀의 거리 | 캐릭터 | 이동, 행동 설계, 적 행동, UI | 이동력 → 이동 가능 경로·범위 |
| 치명타 피해율 | 공중에 떠 있는 상대를 공격할 때 적용되는 피해율 | 캐릭터 | 공격, 스킬, 상태이상, 유물, UI | 띄워짐 상태 + 치명타 적용 가능 공격 → 치명타 피해율 |
| 캐릭터 타입 | 기존 캐릭터 타입 | 캐릭터 | 공격·타겟팅, UI | 공격 주체 타입 + 피격 대상 타입 → 상성 판정 |
| 상성 피해 보정 | 상성에 따른 피해 50% 상승 또는 50% 감소 | 캐릭터 | 공격·타겟팅, 스킬, UI | 캐릭터 타입 상성 → 최종 피해 보정 |
| 전투 상태 | 전투 가능 또는 전투 불능 상태 | 캐릭터 | 전투, 행동 순서, 행동 설계, 이동, 전투판, UI | 체력 0 도달 → 전투 불능 → 셀 점유 해제 |
| 현재 위치 | 캐릭터가 점유하는 셀 | 캐릭터 | 이동, 전투판, 행동 설계, 공격, 스킬, 상태이상, 적 행동, UI | 이동 시스템의 위치 변경 요청 → 캐릭터 현재 위치·전투판 셀 점유 동시 갱신 |
| 초기 배치 가능 범위 | 해당 레벨에서 캐릭터를 처음 배치할 수 있는 셀 범위 | 레벨 | 초기 배치, 전투판, 캐릭터, UI | 레벨 설정 → 배치 가능 셀 표시·배치 검증 |
| 초기 배치 위치 | 전투 시작 시 캐릭터가 배치되는 셀 | 초기 배치 | 캐릭터, 전투판, 전투, UI | 플레이어 배치 → 캐릭터 현재 위치 |
| 초기 배치 완료 여부 | 모든 배치 조건을 만족했는지 여부 | 초기 배치 | 전투, UI | 캐릭터 배치 상태 → 전투 시작 가능 여부 |
| 선공 진영 | 현재 턴의 첫 행동 진영 | 행동 순서 | 전투, 행동 설계, 적 행동, UI | 동전 던지기 또는 다음 턴 교대 → 선공 진영 |
| 행동 번호 | 턴 안의 실행 순서 | 행동 순서 | 전투, 행동 설계, 적 행동, FSM, UI | 선공 진영 → 진영별 행동 번호 |
| 행동 배치 캐릭터 | 아군 행동 번호에 배치된 캐릭터 | 행동 설계 | 전투, 행동 순서, FSM, UI | 유저 선택 → 행동 번호별 캐릭터 |
| 이동 사용 여부 | 해당 행동에서 이동을 사용했는지 여부 | 행동 설계 | 이동, 공격, 스킬, FSM, UI | 이동 실행 → 이동 사용 여부 |
| 이동 실행 결과 | 경로 완료·충돌·전투 불능에 따른 이동 종료 결과 | 이동 | 행동 설계, FSM, 공격, 스킬, 환경 요소, UI | 셀 단위 경로 검사 → 이후 행동 실행·취소 |
| 충돌 셀 | 이동을 막은 셀 위치 | 이동 | FSM, 전투판, 애니메이션, UI | 다음 셀 진입 불가 → 충돌 처리 |

- 타입 상성 피해 보정값은 기존 시스템의 변수와 데이터 구조를 유지한다.
- 상성 피해 보정은 유리할 때 50% 상승, 불리할 때 50% 감소한다.
- 유물 보정 후 유효 최대 체력은 1 이상, 공격력·이동력·치명타 피해율은 0 이상으로 제한한다.
- 유효 스킬 최대 쿨타임은 1 이상으로 제한하고 현재 쿨타임은 `0~유효 최대 쿨타임`으로 제한한다.
- 피해 계산은 `기본 피해 → 타입 상성 → 시간대 타입 피해 보정 → 치명타(현재 시간대 보정 포함) → 기타 주는 피해 보정 → 받는 피해 보정(과거 포함) → 최종 반올림 → 0 이상 제한` 순서로 처리한다.
- 일반 공격의 기본 피해는 유효 공격력이며, 스킬의 기본 피해는 해당 `Damage` 효과에 작성된 값이다.
- 타입 상성 배율은 유리 `1.5`, 중립 `1.0`, 불리 `0.5`를 사용한다.
- 띄워짐 치명타 조건을 만족하면 상성 적용 결과에 `criticalDamageRatePercent ÷ 100`을 곱한다.
- 스킬은 `canCritical = true`인 경우에만 띄워짐 치명타 배율을 적용한다.
- 모든 피해 계산을 마친 뒤 한 번만 반올림하고 최종 피해를 0 이상으로 제한한다.

- 캐릭터 위치와 전투판 셀 점유는 반드시 하나의 처리 단위에서 함께 갱신한다.
- UI·애니메이션·연출 시스템은 원본 전투 변수를 직접 변경하지 않고 읽기 및 요청만 수행한다.
- 유물 보정은 기본 변수를 직접 덮어쓰지 않고 유효값 계산에 사용한다.
- 상태이상 인스턴스 목록은 캐릭터가 보관하지만 생성·변경·제거 권한은 상태이상 시스템이 가진다.

## 5. 시스템별 상세

### 5.1 캐릭터 시스템 [변경]

#### 캐릭터 파라미터

| 파라미터 | 정의 |
|---|---|
| 최대 체력 `maxHp` | 캐릭터 체력의 상한이 되는 기본 파라미터 |
| 현재 체력 `currentHp` | 전투 중 남아 있는 런타임 체력. 전투 시작 시 `maxHp`로 초기화 |
| 공격력 | 일반 공격 피해 |
| 이동력 | 이동할 수 있는 셀의 거리 |
| 치명타 피해율 | 공중에 떠 있는 상대를 공격할 때 적용되는 피해율 |

- 치명타 피해율은 모든 캐릭터가 초반에는 같은 값을 가진다.
- 치명타 피해율은 유물을 통해 변경할 수 있도록 캐릭터 파라미터에 포함한다.
- 캐릭터 타입과 상성은 현재 시스템을 유지한다.
- 캐릭터 타입 상성에 따라 피해가 50% 상승하거나 50% 감소한다.
- 체력이 0에 도달하면 전투 불능 상태가 된다.
- 전투 불능 상태가 되면 해당 캐릭터가 점유하던 셀의 점유를 해제한다.
- 캐릭터는 스킬을 1개씩 보유한다.
- 캐릭터는 지속 중인 상태이상 인스턴스 목록을 보관한다.
- 상태이상 인스턴스의 생성·변경·제거 권한은 상태이상 시스템이 가진다.

#### 캐릭터 기획 문법

모든 캐릭터는 다음 문법으로 작성한다. 실제 캐릭터 수치와 타입은 콘텐츠 설정에서 작성한다.

```text
CHARACTER <캐릭터ID> "<캐릭터명>"
TYPE <기존 캐릭터 타입>
MAX_HP <1 이상의 정수>
ATTACK_POWER <0 이상의 정수>
MOVE_RANGE <0 이상의 정수>
CRITICAL_DAMAGE_RATE_PERCENT <0 이상의 정수>
NORMAL_ATTACK <일반공격ID>
SKILL <스킬ID>
STATUS_IMMUNITY <NONE | 상태태그 목록>
```

작성 규칙:

1. 캐릭터 ID는 중복되지 않도록 작성한다.
2. 캐릭터는 일반 공격 정의 ID와 스킬 정의 ID를 각각 하나씩 참조한다.
3. `MAX_HP`는 1 이상, `ATTACK_POWER`와 `MOVE_RANGE`는 0 이상의 정수로 작성한다.
4. `CRITICAL_DAMAGE_RATE_PERCENT`에서 `100`은 일반 피해와 같은 배율이며 0 이상의 정수로 작성한다.
5. `MOVE_RANGE`는 상·하·좌·우 이동 거리이며 대각선 이동을 포함하지 않는다.
6. `TYPE`은 기존 캐릭터 타입과 상성 데이터에서 사용하는 값만 허용한다.
7. 면역이 없다면 `STATUS_IMMUNITY NONE`으로 작성한다.
8. 전투 시작 시 현재 체력은 유효 최대 체력으로 초기화한다.
9. 입력되지 않은 값은 임의로 채우지 않고 `[작성 필요]`로 표시한다.

### 5.2 전투 시스템 [변경]

- 턴제 전투를 유지한다.
- 전투는 정사각형 판에서 진행한다.
- 턴은 전투가 일어나는 단위이며 여러 행동으로 구성된다.
- 행동은 `적 → 아군 → 적`과 같은 교차 구조에서 한 진영이 한 번 행동하는 단위다.
- 선공 진영이 해당 턴의 첫 번째 행동을 맡는다.
- 플레이어는 아군 행동 번호에 어떤 캐릭터가 행동할지 배치하고, 해당 캐릭터의 행동을 결정한다.
- 모든 캐릭터가 행동 순서에 배치되고 플레이어가 `턴 종료`를 누르면 행동 설계를 종료한다.
- `턴 종료` 입력 이후에는 확정된 행동을 순서대로 실행한다.
- 모든 행동 실행과 턴 종료 처리가 완료되면 해당 턴이 종료된다.
- 행동 개수는 해당 턴에 행동 순서에 배치되는 캐릭터 수에 따라 결정된다.
- 행동 가능 캐릭터 수가 진영마다 다르면 교차 슬롯을 먼저 생성하고, 남은 진영의 행동 슬롯을 후순위에 연속으로 추가한다.

#### 승패 조건

- 모든 적이 전투 불능이면 승리한다.
- 모든 아군이 전투 불능이면 즉시 패배한다.
- 승리 및 패배 이후 처리: [작성 필요]

### 5.3 초기 배치 시스템 [유지]

- 전투에 처음 입장했을 때 사용하는 기존 캐릭터 배치 시스템을 유지한다.
- 각 레벨은 캐릭터를 초기 설치할 수 있는 범위를 정의한다.
- 플레이어는 레벨별 초기 설치 가능 범위 안에 캐릭터를 배치한다.
- 초기 배치에서도 하나의 셀은 캐릭터 한 명만 점유할 수 있다.
- 모든 출전 캐릭터가 전투판 안의 설치 가능하고 점유되지 않은 유효 셀에 배치되어야 전투를 시작할 수 있다.
- 배치를 완료한 뒤 전투 시작을 선택하면 전투를 시작한다.
- 초기 배치 단계에서는 행동 순서, 이동 경로, 일반 공격, 스킬 및 적 행동 예고를 표시하지 않는다.
- 전투 시작 이후 행동 순서 시스템과 행동 설계 시스템을 활성화한다.
- 초기 설치 가능 범위는 레벨 데이터의 `deployableCells`로 정의한다.
- 모든 출전 캐릭터가 서로 다른 유효 `deployableCells`에 배치되면 `isDeploymentComplete = true`로 설정한다.
- 초기 배치의 수정·취소·확정 조작: [작성 필요]

### 5.4 행동 순서 시스템 [변경]

#### 선공 결정

- 게임 시작 시 동전을 던져 최초 선공 진영을 결정한다.
- 최초 선공이 결정된 이후에는 양 진영이 돌아가면서 선공을 맡는다.
- 선공 교대 단위는 턴이다.

#### 행동 번호와 진영 배치

- 행동은 번호 순서대로 실행된다.
- 적이 선공이고 행동 번호가 1~6번이라면 적은 1·3·5번, 아군은 2·4·6번 행동을 맡는다.
- 플레이어는 아군에게 배정된 행동 번호에 어떤 캐릭터를 배치할지 결정한다.
- 플레이어는 `턴 종료`를 누르기 전까지 아군 행동 번호에 배치된 캐릭터의 순서를 자유롭게 변경할 수 있다.
- 선공과 교차 행동으로 결정된 진영별 행동 번호는 유지하며, 아군 캐릭터끼리 아군 행동 번호 사이에서 순서를 변경한다.
- 돌아가면서 행동하는 구조를 유지할 수 없는 경우 남은 진영의 행동 슬롯을 후순위에 연속으로 추가한다.
- 플레이어는 후순위를 포함한 아군 행동 슬롯에 어떤 아군 캐릭터를 배치할지 자유롭게 결정한다.
- 적 행동 시스템은 후순위를 포함한 적 행동 슬롯에 어떤 적 캐릭터를 배치할지 결정한다.
- 모든 행동 가능 캐릭터는 행동 순서에 정확히 한 번씩 배치되어야 하며 동일 캐릭터의 중복 배치는 허용하지 않는다.

### 5.5 행동 설계 시스템 [변경]

- 플레이어는 어떤 타이밍에 어떤 캐릭터가 행동할지 결정할 수 있다.
- 플레이어는 행동 번호에 캐릭터를 배치한 뒤 해당 캐릭터의 이동과 공격 또는 스킬을 결정한다.
- 캐릭터를 클릭하고 말판에 경로를 그려 이동을 결정한다.
- 이동 결정 이후 일반 공격 또는 스킬 사용을 결정할 수 있다.
- 행동 순서는 반드시 `이동 → 일반 공격 또는 스킬`이다.
- `일반 공격 또는 스킬 → 이동`으로 순서를 역전할 수 없다.
- 이동하지 않고 제자리에서 일반 공격 또는 스킬만 사용할 수 있다.
- 한 행동에서 이동은 1회, 일반 공격은 1회 사용할 수 있다.
- 스킬을 사용하면 같은 행동에서 일반 공격을 사용할 수 없다.
- 플레이어는 한 턴의 아군 행동을 `턴 종료` 입력 전에 설계한다.
- `턴 종료`를 누르기 전까지 캐릭터 배치 순서, 이동 경로, 일반 공격 및 스킬 선택을 자유롭게 수정할 수 있다.
- 앞선 행동을 수정하면 뒤에 배치된 행동의 위치·경로·공격 가능 여부를 다시 계산한다.
- `턴 종료`를 누르면 행동 순서와 행동 내용을 확정하고 더 이상 수정할 수 없다.
- 잠긴 이동 경로가 실행 중 막히면 충돌로 처리하며 해당 행동에 예약된 일반 공격·스킬을 취소한다.

### 5.6 이동 시스템 [변경]

- 이동력은 캐릭터가 이동할 수 있는 셀 거리다.
- 대각선 이동은 불가능하다.
- 플레이어는 캐릭터를 클릭한 뒤 말판에 경로를 그려 이동을 결정한다.
- 이동 경로는 정사각형 전투판의 셀을 기준으로 한다.
- 하나의 셀은 캐릭터 한 명만 점유할 수 있다.
- 다른 캐릭터가 점유한 셀에는 진입할 수 없으며 점유된 셀을 통과할 수도 없다.
- 이동 불가 셀과 전투판 밖에는 진입할 수 없다.
- 전투 불능 캐릭터는 즉시 셀 점유를 해제한다.
- 일반 이동과 밀치기·당기기 등의 강제 이동은 동일한 셀 진입 가능 판정을 사용한다.
- 이동 경로 수정 및 취소 규칙: [작성 필요]
- 이동하지 않음을 선택하는 방식: [작성 필요]
- 강제 위치 이동은 상태이상 시스템의 결과를 받아 처리한다.

#### 경로 실행 및 충돌

- 잠긴 이동 경로를 첫 번째 셀부터 순서대로 실행한다.
- 다음 경로 셀에 진입하기 직전에 해당 셀의 이동 가능 여부와 점유 상태를 확인한다.
- 다음 셀에 진입할 수 있으면 해당 셀로 이동하고 현재 위치와 셀 점유를 즉시 갱신한다.
- 다음 셀에 진입할 수 없으면 해당 셀에 들어가지 않고 마지막으로 이동한 유효 셀에서 멈춘다.
- 첫 번째 경로 셀부터 진입할 수 없으면 기존 위치에서 멈춘다.
- 진입 불가능한 셀을 `충돌 셀`로 기록하고 이동 결과를 `Collision`으로 설정한다.
- 충돌이 발생하면 남은 이동 경로를 폐기한다.
- 충돌이 발생하면 해당 행동에 예약된 일반 공격 또는 스킬을 취소한다.
- 충돌 전까지 실제로 진입한 셀의 환경 요소는 정상적으로 발동한다.
- 환경 피해로 이동 중 전투 불능이 되면 이동 결과를 `Incapacitated`로 설정하고 남은 이동과 이후 행동을 취소한다.
- 충돌 자체로 발생하는 별도 피해는 현재 정의하지 않는다.
- 밀치기·당기기 등의 강제 이동도 이동 경로를 셀 단위로 검사한다.
- 강제 이동 중 다음 셀에 진입할 수 없으면 마지막 유효 셀에서 멈추고 남은 강제 이동 거리를 폐기한다.
- 강제 이동 충돌 자체로 별도 피해를 적용하지 않는다.

```text
경로의 다음 셀 확인
├─ 진입 가능 → 이동·위치 갱신 → 환경 요소 확인 → 다음 셀
└─ 진입 불가 → 현재 셀 정지 → Collision → 남은 경로 폐기 → 공격·스킬 취소
```

### 5.7 공격·타겟팅 시스템 [변경]

- 공격에는 방향성이 존재한다.
- 일반 공격 유형은 `범위 내 타겟팅`, `셀 선택`, `방향성`으로 구분한다.
- 범위 내 타겟팅 일반 공격은 계획 단계에서 거리 제한 없이 캐릭터를 지정하고, 실행 시 공격 범위 안에 있으면 별도 방향 선택 없이 해당 대상을 그대로 공격한다.
- 셀 선택 일반 공격은 `방향 선택 → 셀 선택` 순서로 진행한다.
- 셀 선택 일반 공격의 방향은 행동 캐릭터의 현재 위치를 기준으로 선택한다.
- 셀 선택 일반 공격은 계획 단계에서 거리 제한 없이 셀을 지정하고 계획한 원래 셀을 유지하며, 실행 시 해당 셀의 현재 점유 상태를 기준으로 효과를 처리한다.
- 방향성 일반 공격은 이동했다면 이동 완료 위치, 이동하지 않았다면 현재 위치를 기준으로 상·하·좌·우 중 하나의 방향을 선택한다.
- 방향성 일반 공격의 범위와 영향 셀 패턴은 선택한 방향에 맞춰 회전한다.
- 일반 공격은 띄워짐 상태의 대상을 공격할 때 반드시 치명타 피해를 적용한다.
- 일반 공격 피해는 캐릭터의 공격력을 사용한다.
- 실행 시 범위 내 타겟팅은 행동 캐릭터의 현재 위치를 기준으로 범위를 다시 생성하고, 셀 선택은 행동 캐릭터의 현재 위치와 계획한 방향을 기준으로 범위를 다시 생성한다.
- 캐릭터 타겟팅형은 지정 타겟이 전투 불능이거나 실행 시 공격 범위 밖이면 일반 공격을 취소한다.
- 셀 선택형은 계획한 셀이 실행 시 공격 범위 밖이거나 전투판의 유효하지 않은 셀이면 일반 공격을 취소한다.
- 방향성은 이동 완료 위치에서 선택 방향을 기준으로 영향 셀을 생성하고 해당 셀의 현재 대상을 공격한다.
- 공격이 취소되어도 다른 캐릭터나 셀로 자동 재타겟팅하지 않는다.
- 범위 내 타겟팅은 지정한 캐릭터에게 효과를 적용하고, 셀 선택은 계획한 방향과 `affectedCellPatternId`로 실제 영향 셀을 결정한다.

#### 일반 공격 정의 데이터

```text
NormalAttackDefinition
- normalAttackId
- name
- targetingType: InRangeTarget / CellSelect / Directional
- rangePatternId
- affectedCellPatternId
- validTargetTeam: Enemy / Ally / All
- hitTargetRule: SelectedTarget / CharactersInAffectedCells
```

- 일반 공격 정의에는 별도 피해 수치를 두지 않고 행동 캐릭터의 유효 공격력을 기본 피해로 사용한다.
- 범위·영향 셀 패턴의 실제 좌표는 캐릭터 또는 일반 공격 설정별로 작성한다.
- `validTargetTeam`에 포함되지 않은 캐릭터는 선택할 수 없고 영향 셀 안에 있어도 피해를 받지 않는다.
- `SelectedTarget`은 선택한 캐릭터 한 명에게만 피해를 적용한다.
- `CharactersInAffectedCells`는 실제 영향 셀 안에서 `validTargetTeam` 조건을 만족하는 모든 캐릭터에게 피해를 적용한다.

#### 일반 공격 기획 문법

```text
NORMAL_ATTACK <일반공격ID> "<일반공격명>"
TARGETING <IN_RANGE_TARGET | CELL_SELECT | DIRECTIONAL>
RANGE_PATTERN <범위패턴ID>
AFFECTED_CELL_PATTERN <영향셀패턴ID | NONE>
VALID_TARGET_TEAM <ENEMY | ALLY | ALL>
HIT_TARGET_RULE <SELECTED_TARGET | CHARACTERS_IN_AFFECTED_CELLS>
```

작성 규칙:

1. 일반 공격 ID는 중복되지 않도록 작성한다.
2. `IN_RANGE_TARGET`은 범위 안의 캐릭터에게 별도 방향 선택 없이 공격한다.
3. `CELL_SELECT`는 행동 캐릭터를 기준으로 `방향 선택 → 범위 안 셀 선택` 순서로 공격한다.
4. `DIRECTIONAL`은 이동 완료 위치를 기준으로 방향을 선택하고 해당 방향으로 회전한 범위·영향 셀 패턴을 적용한다.
5. 일반 공격 피해는 캐릭터의 유효 공격력을 사용한다.
6. `IN_RANGE_TARGET`은 `HIT_TARGET_RULE SELECTED_TARGET`만 사용하고 `AFFECTED_CELL_PATTERN NONE`을 허용한다.
7. `CELL_SELECT`, `DIRECTIONAL`은 `HIT_TARGET_RULE CHARACTERS_IN_AFFECTED_CELLS`만 사용하고 `AFFECTED_CELL_PATTERN`을 반드시 작성한다.
8. `VALID_TARGET_TEAM`에 포함되지 않은 캐릭터는 선택하거나 피해를 적용할 수 없다.
9. 입력되지 않은 범위 패턴과 영향 셀 패턴은 임의로 채우지 않고 `[작성 필요]`로 표시한다.

### 5.8 스킬·쿨타임 시스템 [변경]

- 스킬은 쿨타임 방식으로 변경한다.
- 스킬 유형은 `범위 내 타겟팅`, `셀 선택`, `설치형`, `방향성`으로 구분한다.
- 범위 내 타겟팅 스킬은 계획 단계에서 거리 제한 없이 대상 캐릭터를 지정하고, 실행 시 범위 안에 있으면 별도 방향 선택 없이 해당 대상에게 그대로 시전한다.
- 셀 선택 스킬은 계획 단계에서 거리 제한 없이 셀을 지정하고, 실행 시 범위 안이면 해당 셀을 기준으로 즉시 효과를 시전한다.
- 설치형 스킬은 계획 단계에서 거리 제한 없이 셀을 지정하고, 실행 시 해당 셀이 설치 사거리와 설치 조건을 만족하면 설치물을 생성한다.
- 방향성 스킬은 이동했다면 이동 완료 위치, 이동하지 않았다면 현재 위치를 기준으로 상·하·좌·우 중 하나의 방향을 선택해 시전한다.
- 방향성 스킬의 범위 패턴은 선택한 방향에 맞춰 회전하며 해당 방향의 영향 셀에 효과를 적용한다.
- 설치형 스킬의 설치·유지·발동 규칙: [작성 필요]
- 쿨타임 단위는 턴이다.
- 스킬 최대 쿨타임은 최소 1 이상이다.
- 전투 시작 시 모든 스킬의 현재 쿨타임은 0으로 초기화한다.
- 스킬 사용 시 `cooldownRemaining`을 유효 `cooldownMax`로 설정한다.
- 스킬을 사용한 같은 턴에는 감소시키지 않고 다음 `TurnSetup`부터 1씩 감소한다.
- 스킬 사용 시 같은 행동에서 일반 공격을 사용할 수 없다.
- 띄워짐 상태의 대상을 공격할 때 치명타가 적용되는 스킬과 적용되지 않는 스킬이 존재한다.
- 각 스킬은 치명타 적용 가능 여부를 가진다.
- 상태이상 스킬은 상태이상 시스템에 적용을 요청한다.
- 실행 시 행동 캐릭터의 이동 완료 위치를 스킬 범위의 기준점으로 사용한다.
- 캐릭터 타겟팅형은 지정 타겟이 전투 불능이거나 실행 시 스킬 범위 밖이면 스킬을 취소한다.
- 셀 선택형은 계획한 셀이 실행 시 스킬 범위 밖이거나 전투판의 유효하지 않은 셀이면 스킬을 취소한다.
- 설치형은 계획한 셀이 실행 시 설치 불가능하면 스킬을 취소한다.
- 방향성은 이동 완료 위치에서 선택 방향을 기준으로 범위 패턴을 생성하고 영향 셀의 현재 대상을 처리한다.
- 취소된 스킬은 다른 캐릭터나 셀로 자동 재타겟팅하지 않으며 쿨타임을 발생시키지 않는다.
- 스킬이 정상 실행되어 첫 효과가 효과 큐에 등록되는 시점에 쿨타임을 적용한다.

#### 스킬 정의 데이터

```text
SkillDefinition
- skillId
- name
- description
- targetingType: InRangeTarget / CellSelect / Install / Directional
- rangePatternId
- affectedCellPatternId
- cooldownMax
- canCritical
- effects: List<SkillEffectData>
```

```text
SkillEffectData
- effectType: Damage / Push / Pull / Airborne / Stun / Install
- targetScope: SelectedTarget / SelectedCell / AffectedCells / Self
- validTargetTeam: Enemy / Ally / All
- value
- distance
- statusEffectId
- environmentId
```

- 스킬은 `SkillEffectData`를 1개 이상 가진다.
- 효과는 스킬 기획 문법에 작성된 순서대로 효과 큐에 등록한다.
- 사용하지 않는 효과 필드는 효과 유형에 따라 비워둔다.
- `Damage`의 `value`는 스킬 기본 피해로 사용한다.
- `validTargetTeam`에 포함되지 않은 캐릭터는 해당 효과의 적용 대상에서 제외한다.
- 방향성 스킬의 `Push`는 선택 방향으로 대상을 이동시킨다.
- 방향성 스킬의 `Pull`은 선택 방향의 반대 방향으로 대상을 이동시킨다.
- `Push`, `Pull` 효과를 사용하는 스킬은 `Directional` 타겟팅 유형을 사용한다.
- `Airborne`, `Stun`은 상태이상 시스템에 적용을 요청한다.
- `Install`은 선택 셀에 `environmentId`의 환경 요소 설치를 요청한다.

#### 스킬 기획 문법

모든 스킬은 다음 문법으로 작성한다. 실제 스킬 수치와 범위 패턴은 콘텐츠 설정에서 작성한다.

```text
SKILL <스킬ID> "<스킬명>"
DESCRIPTION "<설명>"
TARGETING <IN_RANGE_TARGET | CELL_SELECT | INSTALL | DIRECTIONAL>
RANGE_PATTERN <범위패턴ID>
AFFECTED_CELL_PATTERN <영향셀패턴ID | NONE>
COOLDOWN <1 이상의 정수>
CAN_CRITICAL <true | false>

EFFECT DAMAGE <SELECTED_TARGET | SELECTED_CELL | AFFECTED_CELLS> TARGET_TEAM <ENEMY | ALLY | ALL> VALUE <피해값>
EFFECT PUSH <SELECTED_TARGET | AFFECTED_CELLS> TARGET_TEAM <ENEMY | ALLY | ALL> DISTANCE <N>
EFFECT PULL <SELECTED_TARGET | AFFECTED_CELLS> TARGET_TEAM <ENEMY | ALLY | ALL> DISTANCE <N>
EFFECT AIRBORNE <SELECTED_TARGET | AFFECTED_CELLS> TARGET_TEAM <ENEMY | ALLY | ALL>
EFFECT STUN <SELECTED_TARGET | AFFECTED_CELLS> TARGET_TEAM <ENEMY | ALLY | ALL>
EFFECT INSTALL SELECTED_CELL ENVIRONMENT <환경요소ID>
```

작성 규칙:

1. 스킬 ID는 중복되지 않도록 작성한다.
2. `COOLDOWN`은 1 이상의 정수로 작성한다.
3. `DIRECTIONAL` 스킬만 행동 캐릭터 기준의 상·하·좌·우 방향을 선택한다.
4. `DIRECTIONAL` 스킬은 이동 완료 위치를 기준점으로 사용하고 `RANGE_PATTERN`을 선택 방향에 맞춰 회전한다.
5. `EFFECT`는 1개 이상 작성하고 위에서 아래 순서대로 효과 큐에 등록한다.
6. `DAMAGE`에 치명타를 허용하려면 `CAN_CRITICAL true`를 작성한다.
7. 방향성 스킬의 `PUSH`는 선택 방향, `PULL`은 선택 방향의 반대 방향으로 처리한다.
8. 상태이상 효과는 상태이상 시스템에, 설치 효과는 환경 요소 시스템에 처리 요청을 전달한다.
9. 정의되지 않은 효과 유형과 타겟 범위는 사용하지 않는다.
10. 작성되지 않은 수치는 임의로 채우지 않고 `[작성 필요]`로 표시한다.
11. `IN_RANGE_TARGET`은 범위 안의 캐릭터에게 즉시 시전하고 별도 방향을 선택하지 않는다.
12. `CELL_SELECT`는 범위 안의 선택 셀을 기준으로 즉시 효과를 처리한다.
13. `INSTALL`은 범위 안의 선택 셀에 설치물을 생성한다.
14. `PUSH`, `PULL` 효과를 사용하는 스킬은 `TARGETING DIRECTIONAL`로 작성한다.
15. `AFFECTED_CELLS`를 사용하는 스킬은 `AFFECTED_CELL_PATTERN`을 반드시 작성한다.
16. 단일 대상, 선택 셀 하나 또는 설치형 스킬은 `AFFECTED_CELL_PATTERN NONE`을 허용한다.
17. 캐릭터에게 적용되는 각 효과는 `TARGET_TEAM`을 반드시 작성한다.

### 5.9 상태이상 시스템 [변경]

상태이상 종류는 밀치기, 당기기, 띄우기, 기절이다.

#### 데이터 구조

상태이상 데이터는 `상태이상 정의 데이터 → 상태이상 적용 요청 → 캐릭터 상태이상 인스턴스`의 세 단계로 관리한다.

##### 상태이상 정의 데이터

상태이상의 공통 규칙을 상태이상 시스템에서 정의하고 소유한다.

```text
StatusEffectDefinition
- 상태이상 ID
- 이름
- 처리 유형: 즉시형 / 지속형
- 상태 태그
- 적용 대상 조건
- 지속 종료 조건
- 중첩 규칙
- 처리 우선순위
- UI 연결 ID
- 애니메이션 연결 ID
- 이펙트 연결 ID
```

| 상태이상 | 처리 유형 | 핵심 데이터 |
|---|---|---|
| 밀치기 | 즉시형 | 선택한 스킬 사용 방향, 이동 거리 N |
| 당기기 | 즉시형 | 선택한 스킬 사용 방향의 반대 방향, 이동 거리 N |
| 띄워짐 | 지속형 | 치명타 조건 제공, 종료 조건 |
| 기절 | 지속형 | 적용된 턴 동안 행동 슬롯 패스, 해당 턴 `TurnCleanup`에서 해제 |

##### 상태이상 적용 요청

스킬·유물·환경 요소는 상태이상을 직접 처리하지 않고 상태이상 시스템에 적용을 요청한다.

```text
StatusEffectRequest
- 상태이상 ID
- 적용 주체 캐릭터 ID
- 적용 대상 캐릭터 ID
- 발생 스킬 ID
- 적용 시점
- 이동 거리 N
- 기준 위치
- 대상 위치
- 방향
```

요청에 사용되지 않는 항목은 상태이상 종류에 따라 비워둔다. 밀치기·당기기의 위치 계산에는 스킬 사용자가 선택한 상·하·좌·우 방향과 이동 거리 N을 사용한다.

##### 캐릭터 상태이상 인스턴스

지속 중인 상태이상은 캐릭터에 인스턴스로 보관한다. 캐릭터 시스템은 목록을 보관하고 상태이상 시스템만 인스턴스를 생성·변경·제거한다.

```text
StatusEffectInstance
- 상태이상 ID
- 적용 주체 ID
- 적용 대상 ID
- 적용된 턴
- 적용된 행동 번호
- 중첩 수
- 활성 상태
- 종료 조건
```

- 밀치기와 당기기는 즉시 처리 후 종료되므로 지속 인스턴스를 남기지 않는다.
- 띄워짐과 기절은 캐릭터의 상태이상 인스턴스 목록에 보관한다.
- 띄워짐은 `Airborne` 상태 태그를 사용한다.
- 띄워짐은 대상의 다음 `ActionBegin` 또는 현재 턴의 `TurnCleanup` 시작 중 먼저 충족되는 조건에 종료한다.

##### 데이터 소유권 및 활용

| 데이터·책임 | 정의 및 소유 | 활용 시스템 |
|---|---|---|
| 상태이상 정의 | 상태이상 시스템 | 스킬, 유물, 환경 요소, UI, 애니메이션, 연출 |
| 상태이상 적용 요청 | 요청을 생성한 스킬·유물·환경 요소 | 상태이상 시스템 |
| 상태이상 인스턴스 생성·변경·제거 | 상태이상 시스템 | 캐릭터, 행동 순서, FSM, 공격·타겟팅, 스킬, UI, 애니메이션, 연출 |
| 활성 인스턴스 목록 보관 | 캐릭터 시스템 | 상태이상 시스템 |
| 지속 및 종료 시점 전달 | 행동 순서 시스템 | 상태이상 시스템 |
| 행동 제한 반영 | FSM | 행동 설계, 캐릭터, UI |
| 치명타 조건 확인 | 공격·타겟팅 및 스킬·쿨타임 시스템 | 전투, UI, 연출 |
| 상태 표시 | UI·애니메이션·스킬 이펙트 및 연출 시스템 | 플레이어 표시 |

#### 밀치기

- 스킬 사용자는 자신의 현재 위치를 기준으로 상·하·좌·우 중 하나의 사용 방향을 선택한다.
- 밀치기는 선택한 스킬 사용 방향으로 대상을 N칸 이동시킨다.
- 아군 캐릭터에게도 적용할 수 있다.
- 아군 캐릭터는 해당 스킬의 피해를 받지 않는다.
- 방향이 먼저 확정되므로 밀치기 결과의 후보 셀은 하나의 직선 경로로 결정되며 후보 셀 동률은 발생하지 않는다.
- 결과 셀까지의 강제 이동 경로를 셀 단위로 검사하며, 진입 불가능한 셀을 만나면 직전 유효 셀에서 멈추고 남은 이동 거리를 폐기한다.

#### 당기기

- 스킬 사용자는 자신의 현재 위치를 기준으로 상·하·좌·우 중 하나의 사용 방향을 선택한다.
- 당기기는 선택한 스킬 사용 방향의 반대 방향으로 대상을 N칸 이동시킨다.
- 아군 캐릭터에게도 적용할 수 있다.
- 아군 캐릭터는 해당 스킬의 피해를 받지 않는다.
- 방향이 먼저 확정되므로 당기기 결과의 후보 셀은 하나의 직선 경로로 결정되며 후보 셀 동률은 발생하지 않는다.
- 결과 셀까지의 강제 이동 경로가 막히면 직전 유효 셀에서 멈추고 남은 이동 거리를 폐기한다.

#### 띄우기 / 띄워짐

- 띄우기는 대상을 `띄워짐` 상태로 만든다.
- 띄워짐 상태는 다음 자기 행동 또는 턴 종료 시까지 유지된다.
- 띄워짐 상태의 대상은 치명타 조건을 충족한다.
- 일반 공격은 띄워짐 상태의 대상에게 반드시 치명타 피해를 적용한다.
- 스킬은 스킬별 치명타 적용 가능 여부에 따라 치명타 피해 적용 여부를 결정한다.
- 띄워짐은 대상의 다음 `ActionBegin` 또는 현재 턴의 `TurnCleanup` 시작 중 먼저 발생하는 시점에 해제한다.

#### 기절

- 기절은 적용된 현재 턴 동안 대상 캐릭터가 행동하지 못하게 한다.
- 기절한 캐릭터의 행동 슬롯이 실행되면 해당 슬롯을 소비하고 즉시 패스한다.
- 패스된 행동에서는 이동, 일반 공격, 스킬을 모두 실행하지 않는다.
- 기절은 적용된 현재 턴의 `TurnCleanup`에서 해제한다.
- 캐릭터가 자신의 행동을 마친 뒤 같은 턴에 기절하면 이미 완료된 행동에는 영향을 주지 않으며, 해당 기절로 패스할 남은 행동 슬롯이 없으면 전투상 효과가 없다.

#### 공통 상태이상 규칙

- 밀치기·당기기는 즉시 처리하므로 중첩하지 않는다.
- 띄워짐을 이미 보유한 대상에게 다시 적용하면 중첩 수를 늘리지 않고 종료 조건을 새 적용 시점 기준으로 갱신한다.
- 기절을 이미 보유한 대상에게 다시 적용해도 추가 행동 슬롯을 패스하지 않으며, 적용된 현재 턴의 `TurnCleanup`에서 함께 해제한다.
- 아군에게 적용할 수 있는 상태이상은 밀치기·당기기로 제한한다.
- 아군에게 띄워짐과 기절을 적용할 수 없다.
- 캐릭터는 상태이상 면역 태그를 가질 수 있다.
- 대상이 해당 상태이상의 면역 태그를 가지면 상태이상 적용만 실패하고 같은 스킬의 피해와 다른 효과는 정상 처리한다.
- 상태이상 면역으로 적용이 실패해도 다른 상태이상이나 대상으로 자동 변경하지 않는다.

### 5.11 정사각형 전투판 시스템 [유지]

- 전투 불능 처리와 동시에 해당 캐릭터의 `occupiedCell`과 전투판의 `cellOccupants`를 함께 해제한다.

### 5.12 FSM [변경]

FSM은 하나의 거대한 상태 머신으로 만들지 않고 `전투 흐름 FSM`, `행동 실행 FSM`, `캐릭터 실행 FSM`의 3계층으로 분리한다.

```text
BattleFlowFSM
  → ActionExecutionFSM
      → CharacterExecutionFSM
```

#### FSM 책임 구분

| FSM | 소유 책임 | 소유하지 않는 책임 |
|---|---|---|
| 전투 흐름 FSM | 전투 진입, 초기 배치, 턴 준비, 행동 설계, 실행, 정산, 승패 종료 | 개별 공격·스킬·상태이상 계산 |
| 행동 실행 FSM | 행동 슬롯 1개의 이동·공격·스킬·효과 처리 순서 | 캐릭터 파라미터와 콘텐츠 데이터 |
| 캐릭터 실행 FSM | 캐릭터의 이동·공격·스킬·반응·전투 불능 표현 상태 | 턴 순서, 상태이상 지속시간, 승패 조건 |

#### 전투 흐름 FSM

```text
EnterBattle
→ Deployment
→ BattleStart
→ TurnSetup
→ EnemyIntentPlanning
→ Planning
→ PlanValidation
→ PlanLocked
→ TimeShiftResolution
→ Executing
→ TurnCleanup
→ TurnSetup 또는 BattleEnd
```

| 상태 | 진입 조건 | 처리 | 종료 조건·다음 상태 |
|---|---|---|---|
| `EnterBattle` | 레벨 진입 | 레벨·전투판·캐릭터 데이터 준비 | 준비 완료 → `Deployment` |
| `Deployment` | 전투 진입 완료 | 레벨별 초기 설치 가능 범위 표시, 캐릭터 배치. 행동 정보는 표시하지 않음 | 배치 완료 및 전투 시작 입력 → `BattleStart` |
| `BattleStart` | 전투 시작 입력 | 동전 던지기로 최초 선공 결정, 현재 시간대 `Present`와 회중시계 전투 시작 충전 초기화, 전투 시작 이벤트 전달 | 선공 확정 → `TurnSetup` |
| `TurnSetup` | 최초 전투 시작 또는 이전 턴 정산 완료 | 턴 번호·쿨타임·유물 카운터 갱신, 행동 슬롯 생성 | 준비 완료 → `EnemyIntentPlanning` |
| `EnemyIntentPlanning` | 행동 슬롯 생성 완료 | 적 행동 시스템에 행동 계획 요청, 타겟·예고 경로 결과 수신 | 적 계획 데이터 생성 → `Planning` |
| `Planning` | 적 행동 예고 완료 | 아군 캐릭터 순서·이동·공격·스킬과 선택 시간대 설계 및 자유 수정 | 턴 종료 입력 → `PlanValidation` |
| `PlanValidation` | 턴 종료 입력 | 모든 캐릭터 배치·행동 데이터·선택 시간대·보유 시간 파편과 필요 수량 유효성 검사 | 유효 → `PlanLocked`, 무효 → `Planning` |
| `PlanLocked` | 설계 검증 성공 | 행동 순서·행동 내용·선택 시간대·적용 비용 잠금, 입력 차단 | 잠금 완료 → `TimeShiftResolution` |
| `TimeShiftResolution` | 행동 계획과 시간대 잠금 완료 | 비용 소비, 현재 시간대·전역 보정·유물 활성 갱신, 미래 회복, 시간대 이벤트와 연출 요청 | 승패 없음 → `Executing`, 승패 확정 → `BattleEnd` |
| `Executing` | 행동 계획 잠금 완료 | 행동 슬롯을 1번부터 `ActionExecutionFSM`으로 실행 | 모든 슬롯 완료 → `TurnCleanup`, 승패 확정 → `BattleEnd` |
| `TurnCleanup` | 모든 행동 슬롯 완료 | 환경·상태이상·유물 턴 종료 처리, 선공 교대 | 승패 없음 → `TurnSetup`, 승패 확정 → `BattleEnd` |
| `BattleEnd` | 승리 또는 패배 확정 | 결과 잠금, 남은 행동·트리거 중지, 결과 연출 및 아웃게임 전달 | 결과 화면 |

`턴 종료` 버튼은 실제 턴을 즉시 종료하는 것이 아니라 `Planning → PlanValidation → PlanLocked` 전이를 요청한다. 실제 턴 종료는 `TurnCleanup` 완료 시점이다.

#### TurnSetup 처리 순서

```text
turnIndex 갱신
→ 스킬 쿨타임 감소
→ 유물 내부 쿨타임 감소
→ 행동당·턴당 런타임 값 초기화
→ selectedTimePeriod를 currentTimePeriod로 초기화하고 시간대 잠금 해제
→ OnTurnStart 이벤트
→ OnTurnStart 유물 트리거·카운터 처리

→ 선공 진영 기준 교차 배치
```

- 최초 턴의 `turnIndex`는 1이다.
- 스킬 및 유물 내부 쿨타임은 사용·발동한 같은 턴에 감소시키지 않고 다음 `TurnSetup`에서 감소한다.

#### 행동 실행 FSM

```text
ActionBegin
→ ValidateActor
→ ResolvePreAction
→ PrepareAction
→ RevalidateAction
→ ResolveMove
→ ResolveEnvironmentTrigger
→ ResolveMainAction
→ ResolveEffectQueue
→ UpdateIncapacitated
→ CheckBattleResult
→ ResolvePostAction
→ ActionEnd
```

| 상태 | 처리 |
|---|---|
| `ActionBegin` | 현재 행동 슬롯과 행동 캐릭터 설정, 행동당 카운터 초기화, `OnOwnerActionStart` 전달 |
| `ValidateActor` | 전투 불능·상태이상에 따른 행동 가능 여부 확인 |
| `ResolvePreAction` | 행동 시작 상태이상과 유물 트리거 처리 |
| `PrepareAction` | 아군은 잠긴 계획 확인. 적은 적 행동 시스템에 타겟·경로 재검증 요청 |
| `RevalidateAction` | 현재 전투판의 위치·셀 점유와 타겟 생존 여부를 확인해 잠긴 행동의 실행을 준비. 경로·타겟·셀은 자동 변경하지 않음 |
| `ResolveMove` | 경로를 셀 단위로 실행하며 셀 진입마다 위치·점유 갱신과 `OnEnterCell` 환경 확인. 강제 이동은 환경 요소의 `reactToForcedMovement`가 `true`일 때 포함. 진입 불가능 셀을 만나면 충돌 처리 |
| `ResolveEnvironmentTrigger` | 이동 종료 위치의 `OnEndMovement` 환경 효과와 이동 중 등록된 환경 피해 큐 처리 |
| `ResolveMainAction` | 이동 완료 위치를 기준으로 일반 공격·스킬의 범위와 타겟·셀을 최종 재검증한 뒤 실행. 무효하면 자동 재타겟팅 없이 취소 |
| `ResolveEffectQueue` | 피해·상태이상·강제 이동·환경 피해·유물 트리거를 큐로 처리하고 아군 직접 공격 피해 묶음 완료 후 공격·콤보 충전 판정 |
| `UpdateIncapacitated` | 체력 0 캐릭터를 전투 불능으로 전환하고 셀 점유 해제 |
| `CheckBattleResult` | 모든 적 전투 불능 또는 모든 아군 전투 불능 확인 |
| `ResolvePostAction` | 행동 종료 버프·디버프 카운트, 유물 이벤트·카운터 처리 |
| `ActionEnd` | 행동당 환경·유물 카운터 초기화 후 다음 행동 슬롯 요청 |

`ResolveMove` 결과 분기:

```text
Completed
→ ResolveMainAction

Collision
→ 현재 셀에서 정지
→ 남은 경로 폐기
→ cancelMainAction = true
→ ResolveMainAction 건너뜀
→ ResolveEffectQueue

Incapacitated
→ 남은 경로 폐기
→ cancelMainAction = true
→ UpdateIncapacitated
→ CheckBattleResult
```

```text
→ 이동 계속 또는 행동 종료
```

- 경로 이동은 셀마다 진입 가능 여부를 확인한다.
- 진입 불가능 셀을 만나면 마지막 유효 셀에서 멈추고 충돌로 처리한다.
- 충돌 이후 해당 행동의 일반 공격·스킬은 취소한다.

- `OnEnterCell`: 해당 셀에 진입할 때 확인한다.
- `OnEndMovement`: 이동을 마친 셀에서 확인한다.
- 밀치기·당기기로 셀에 들어간 경우 `reactToForcedMovement`가 `true`인 환경 요소만 `OnEnterCell`을 확인한다.
- `OnOwnerActionStart`·`OnOwnerActionEnd`: 해당 캐릭터 행동의 시작·종료에 확인한다.
- `OnTurnEnd`: `TurnCleanup`에서 확인한다.
- 환경 피해로 체력이 0이 되면 전투 불능·셀 점유 해제·승패 판정을 즉시 이어서 처리한다.

#### TurnCleanup 처리 순서

```text
OnTurnEnd 환경 피해 등록·처리
→ 전투 불능 처리
→ 승패 판정
→ 버프·디버프 OnTurnEnd 효과 처리
→ CurrentTurn 상태 해제
→ FullTurns 카운트 감소 및 만료 상태 제거
→ OnTurnEnd 유물 트리거 처리
→ 환경 요소 remainingTurns 감소
→ 만료 환경 요소 제거
→ 턴당 환경·유물 카운터 초기화
→ 승패가 없으면 턴 경과 시간 파편 지급
→ 선공 진영 교대
→ 다음 TurnSetup
```

- 환경 요소는 생성된 턴에는 `remainingTurns`를 감소시키지 않는다.
- 환경 피해의 `remainingActivationCount`는 피해가 실제 적용되었을 때만 감소한다.
- 환경 요소 수명과 피해 발동 횟수는 별도로 관리한다.
- 각 단계의 계산 결과에 소수점이 발생하면 최종 결과를 반올림한다.

#### 버프·디버프 지속시간 처리

| 지속 유형 | 갱신 시점 |
|---|---|
| `CurrentTurn` | 현재 `TurnCleanup`에서 해제 |
| `FullTurns N` | 적용된 턴을 제외하고 이후 `TurnCleanup`에서 감소 |
| `OwnerActions N` | 대상 캐릭터의 `ResolvePostAction`에서 감소 |
| `UntilEvent` | 지정 이벤트 발생 시 해제 |
| `Battle` | `BattleEnd`에서 해제 |

- 띄워짐은 대상의 다음 `ActionBegin` 또는 현재 턴의 `TurnCleanup` 시작 중 먼저 발생한 조건에 해제한다.
- 기절한 캐릭터의 행동 슬롯은 소비 후 패스하며, 기절은 적용된 현재 턴의 `TurnCleanup`에서 해제한다.

#### 승패 판정

```text
allyAliveCount = 전투 가능한 아군 수
enemyAliveCount = 전투 가능한 적 수

if allyAliveCount == 0:
    Defeat
else if enemyAliveCount == 0:
    Victory
else:
    InProgress
```

- 모든 적이 전투 불능이면 승리한다.
- 모든 아군이 전투 불능이면 즉시 패배한다.
- 같은 효과 묶음에서 아군과 적이 모두 전투 불능이 되면 패배한다.
- 승패 확정 시 남은 행동 슬롯과 추가 트리거 처리를 중지한다.

#### 캐릭터 실행 FSM

```text
Idle
├─ Moving
├─ NormalAttacking
├─ SkillCasting
├─ Reacting
│   ├─ Hit
│   ├─ Pushed
│   ├─ Pulled
│   ├─ Launched
│   └─ Collided
└─ Incapacitated
```

- 기절과 띄워짐은 캐릭터 실행 FSM이 아니라 상태이상 시스템이 소유한다.
- 캐릭터 실행 FSM은 상태이상 결과에 따른 행동 제한과 표현 요청만 반영한다.
- 밀치기·당기기·띄우기는 `Reacting` 표현 상태를 사용한다.
- 체력 0 도달 시 `Incapacitated`로 전환한다.

#### 입력 및 연출 분리

- 사용자 입력은 `Deployment`와 `Planning`에서만 허용한다.
- `PlanLocked` 이후에는 행동 순서와 행동 내용을 수정할 수 없다.
- FSM은 게임 규칙 결과를 먼저 확정하고 애니메이션·이펙트 연출 명령을 생성한다.
- 규칙 판정은 애니메이션 프레임 이벤트에 의존하지 않는다.
- 빠른 연출의 세부 속도는 `[추후 구현]`하며 현재는 빠른 느낌을 목표로 한다.

### 5.14 유물 시스템 [변경]

#### 기본 장착 구조

- 유물 시스템은 캐릭터 장착형으로 변경한다.
- 캐릭터마다 유물 슬롯 3개를 가진다.
- 획득한 유물은 `가방 → 캐릭터 장비창 → 장비 슬롯 드래그` 순서로 장착한다.
- 장착 시 유물 보정값을 허용된 캐릭터·스킬 변수에 적용한다.
- 장착을 해제하면 해당 유물 보정값을 제거하고 유물을 가방의 미장착 상태로 되돌린다.

#### 장착 조작 추천안 [제안]

- 유물 장착과 해제는 아웃게임의 캐릭터 장비창에서만 가능하도록 한다.
- 하나의 유물 인스턴스는 동시에 한 캐릭터에게만 장착할 수 있다.
- 같은 `relicId`를 가진 유물 인스턴스 여러 개를 한 캐릭터에게 중복 장착할 수 없다.
- 빈 슬롯에 드래그하면 즉시 장착한다.
- 장착된 슬롯에 다른 유물을 드래그하면 기존 유물과 교체한다.
- 장착 유물을 가방으로 드래그하면 장착을 해제한다.
- 장착 대상 캐릭터가 같은 `relicId`의 유물을 이미 장착 중이면 장착 요청을 거부하고 기존 장착 상태를 유지한다.
- 장착·해제 시 저장 시점: [작성 필요]

#### 기본값과 유효값 분리 [제안]

유물은 캐릭터나 스킬의 기본값을 직접 변경하지 않는다. 기본값과 장착 유물의 보정값을 분리하고, 전투에서는 계산된 유효값을 사용한다.

```text
기본값
→ 같은 변수의 모든 고정 보정 합산
→ 같은 변수의 모든 비율 보정 합산 적용
→ 최종 반올림
→ 변수별 허용 범위 제한
= 전투에서 사용하는 유효값
```

- 유물을 교체해도 캐릭터와 스킬의 원본 데이터는 유지한다.
- 유효값은 장착·해제·교체 시 다시 계산한다.
- 고정 보정은 `기본값 + 모든 FlatAdd의 합`으로 계산한다.
- 비율 보정은 고정 보정 결과에 `1 + 모든 PercentAdd의 합 ÷ 100`을 곱한다.
- 유물 슬롯이나 장착 순서에 따라 계산 결과가 달라지지 않도록 같은 연산의 보정값을 먼저 합산한다.
- 모든 보정을 적용한 뒤 한 번만 반올림하고 변수별 허용 범위로 제한한다.

#### 변경 가능 변수 추천안 [제안]

초기 유물은 이미 정의된 수치 변수만 변경하도록 제한한다. 핵심 턴 규칙이나 타겟팅 방식을 바꾸는 유물은 시스템 검증 이후 별도로 논의한다.

| 변경 대상 | 추천 보정 방식 | 권장 수준 | 연결 시스템 | 비고 |
|---|---|---|---|---|
| 최대 체력 `maxHp` | 고정값 또는 비율 | 기본 허용 | 캐릭터 | 유효값 1 이상. 감소 시 초과 현재 체력 삭제 |
| 공격력 `attackPower` | 고정값 또는 비율 | 기본 허용 | 캐릭터·공격 | 일반 공격 피해 변경 |
| 이동력 `moveRange` | 정수 고정값 | 제한적 허용 | 캐릭터·이동 | 셀 단위이므로 비율 보정 미사용 권장 |
| 치명타 피해율 `criticalDamageRatePercent` | 퍼센트포인트 고정값 | 기본 허용 | 캐릭터·공격·스킬 | 기존에 확정된 유물 변경 대상 |
| 스킬 최대 쿨타임 `cooldownMax` | 정수 고정값 | 제한적 허용 | 스킬·쿨타임 | 유효값 1 이상 |

```text

- MoveRange

- SkillCooldownRemaining
```

#### 트리거형 유물 추천안 [제안]

유물 효과를 `상시 보정형`과 `트리거형`으로 구분한다.

| 유형 | 처리 방식 |
|---|---|

```text

→ 발동 제한·내부 쿨타임 확인

→ 발동 횟수 및 내부 쿨타임 갱신
```

##### 누적 카운터 데이터

```text

- initialValue
- minValue
- maxValue
- scope
- resetEvents

RelicRuntimeState
- relicInstanceId
- runtimeCounters
- activationCountThisTurn
- activationCountThisBattle

```

- 누적 카운터는 유물 인스턴스별로 보관한다.
- 같은 유물의 인스턴스가 여러 개라면 각 인스턴스가 독립된 카운터를 가진다.
- `activationCountThisTurn`과 `activationCountThisBattle`은 발동 횟수 제한에 사용한다.
- `runtimeCounters`는 유물 효과의 누적 조건에 사용한다.

| 공격력 보정 | 장착 캐릭터 | 해당 행동 종료 / 턴 종료 / 전투 종료 |
| 이동력 보정 | 장착 캐릭터 | 다음 행동 / 턴 종료 |
| 치명타 피해율 보정 | 장착 캐릭터 | 다음 공격 / 해당 행동 종료 / 턴 종료 |
| 스킬 현재 쿨타임 증감 | 장착 캐릭터의 스킬 | 즉시 |

##### 발동 제한과 처리 안전 규칙 [제안]

- 트리거마다 행동당·턴당·전투당 발동 횟수를 설정할 수 있도록 한다.
- 기본 추천값은 `턴당 1회`이며 유물별로 변경 가능하도록 한다.
- 반복 발동이 필요한 유물은 내부 쿨타임을 별도로 설정한다.
- 트리거 효과가 다시 같은 트리거를 발생시키는 연쇄 발동은 기본적으로 허용하지 않는다.
- `allowTriggeredEffectChain`이 명시된 유물만 다른 트리거형 유물을 연쇄 발동할 수 있다.
- 동시에 여러 트리거가 발생하면 `triggerPriority → 유물 슬롯 번호 → 유물 인스턴스 ID` 순서로 처리한다.
- 발동한 임시 보정값은 지속시간 종료 시 제거하고 기본값 및 상시 보정값으로 복구한다.
- 카운터의 모든 값은 정수로 관리한다.
- 카운터 증감 결과는 정의된 최솟값과 최댓값을 벗어나지 않도록 제한한다.

##### 체력 조건 유물 예시 형식 [제안]

실제 수치는 콘텐츠 기획에서 작성한다.

```text
조건: 장착 캐릭터의 체력이 N% 이하로 내려감
발동: OnHpThresholdCrossed
효과: 지정 변수에 M 보정
대상: 장착 캐릭터
지속시간: [작성 필요]
발동 제한: 턴당 또는 전투당 [작성 필요]
내부 쿨타임: [작성 필요]
```

#### 변경 제외 변수 추천안 [제안]

아래 항목은 코어 규칙의 예외와 조합 폭증을 막기 위해 초기 유물의 변경 대상에서 제외한다.

- 캐릭터 타입 및 상성 관계
- 상성 피해 50% 상승·감소 규칙
- 캐릭터당 스킬 1개 제한
- 유물 슬롯 3개 제한
- 턴당 행동 배치 횟수와 행동 순서
- 선공 교대 규칙
- 이동 후 공격·스킬 순서
- 일반 공격·스킬의 타겟팅 유형
- 띄워짐 종료 조건
- 초기 배치 가능 범위

#### 변수별 추가 결정

- 유물 장착·해제·교체로 유효 최대 체력이 감소하면 현재 체력은 `min(currentHp, effectiveMaxHp)`로 제한하고 초과 체력은 삭제한다.
- 유물 장착 결과 유효 최대 체력이 0 이하가 되면 해당 유물은 장착할 수 없다.
- 장착 불가 판정 시 장착 요청을 거부하고 기존 유물 장착 상태와 체력 값을 유지한다.
- 유효 공격력과 유효 이동력은 0 이상으로 제한한다.
- 유효 치명타 피해율은 0 이상으로 제한한다.
- 유효 스킬 최대 쿨타임은 1 이상으로 제한한다.
- 스킬 현재 쿨타임은 유효 스킬 최대 쿨타임 변경 후 `0~effectiveCooldownMax` 범위로 제한한다.
- 전투 시작 시 스킬 현재 쿨타임은 0으로 초기화한다.

#### 유물 기획 문법

모든 유물은 아래 문법으로 작성한다. 상시형과 트리거형의 필드 구조를 통일하여 콘텐츠 기획 내용을 시스템 데이터로 바로 옮길 수 있도록 한다.

##### 공통 문법

```text
RELIC <유물ID> "<유물명>"
TYPE <PASSIVE | TRIGGER>
DESCRIPTION "<설명>"
```

##### 상시 보정형 문법

```text
RELIC <유물ID> "<유물명>"
TYPE PASSIVE
DESCRIPTION "<설명>"
MODIFIER <대상> <연산> <값>
```

예시 형식:

```text
RELIC relic_passive_001 "[작성 필요]"
TYPE PASSIVE
DESCRIPTION "최대 체력을 증가시킨다."
MODIFIER Owner.MaxHp FLAT_ADD N
```

##### 트리거형 문법

```text
RELIC <유물ID> "<유물명>"
TYPE TRIGGER
DESCRIPTION "<설명>"
TRIGGER <이벤트>
WHEN <조건 대상> <비교 연산> <기준값>
DO <효과 대상> <연산> <효과값>
DURATION <지속시간>
LIMIT <발동 제한 단위> <횟수>
INTERNAL_COOLDOWN <턴 수>
CHAIN <true | false>
PRIORITY <정수>
```

체력 비율 트리거 예시 형식:

```text
RELIC relic_low_hp_001 "[작성 필요]"
TYPE TRIGGER
DESCRIPTION "체력이 N% 이하로 내려가면 공격력이 증가한다."
TRIGGER OnHpThresholdCrossed
WHEN Owner.HpPercent <= N
DO Owner.AttackPower PERCENT_ADD M
DURATION TurnEnd
LIMIT PER_TURN 1
INTERNAL_COOLDOWN 0
CHAIN false
PRIORITY 0
```

##### 누적 카운터 문법

```text
COUNTER <카운터ID> INIT <초기값> MIN <최솟값> MAX <최댓값>
ON <이벤트>
COUNTER_ADD <카운터ID> <값>
COUNTER_SUBTRACT <카운터ID> <값>
COUNTER_SET <카운터ID> <값>
WHEN Counter.<카운터ID> <비교 연산> <기준값>
DO <효과 대상> <연산> <효과값>
AFTER_TRIGGER <카운터ID> <KEEP | RESET | CONSUME 값>
RESET <카운터ID> ON <이벤트>
```

누적 후 초기화 예시 형식:

```text
RELIC relic_counter_001 "[작성 필요]"
TYPE TRIGGER
DESCRIPTION "스킬을 사용할 때마다 카운트가 증가하고 N회째 효과가 발동한다."

COUNTER SkillUseCount INIT 0 MIN 0 MAX N

ON OnSkillUsed
COUNTER_ADD SkillUseCount 1

WHEN Counter.SkillUseCount >= N
DO Owner.AttackPower PERCENT_ADD M
DURATION TurnEnd
AFTER_TRIGGER SkillUseCount RESET

RESET SkillUseCount ON OnBattleEnd
LIMIT PER_TURN 1
INTERNAL_COOLDOWN 0
CHAIN false
PRIORITY 0
```

##### 허용 카운터 연산

```text
COUNTER_ADD       # 지정 값 증가
COUNTER_SUBTRACT  # 지정 값 감소
COUNTER_SET       # 지정 값으로 변경
COUNTER_RESET     # 초기값으로 복구
COUNTER_CONSUME   # 발동 후 지정 값 차감
```

##### 허용 대상

```text
Owner.MaxHp
Owner.AttackPower
Owner.MoveRange
Owner.CriticalDamageRatePercent
Owner.SkillCooldownMax
Owner.SkillCooldownRemaining
```

##### 허용 연산

```text
FLAT_ADD       # 고정값 증감
PERCENT_ADD    # 비율 증감
```

##### 허용 비교 연산

```text
<
<=
==
>=
>
```

##### 허용 지속시간


##### 작성 규칙

1. 유물 ID는 중복되지 않도록 작성한다.
2. 하나의 줄에는 하나의 조건 또는 효과만 작성한다.
3. 변경 대상은 허용 대상 목록에 있는 변수만 사용한다.
4. 밀치기 거리와 당기기 거리는 유물 변경 대상에 포함하지 않는다.
5. 모든 효과값과 비율값은 정수로 작성한다.
6. 계산 중 소수점이 발생하면 모든 계산을 마친 최종 결과를 반올림한다.
7. 트리거 효과의 연쇄 발동은 `CHAIN false`를 기본값으로 사용한다.
8. 입력되지 않은 값은 임의로 채우지 않고 `[작성 필요]`로 표시한다.
9. 발동 횟수 제한과 효과 누적 카운터는 서로 다른 데이터로 작성한다.
10. 카운터 초기화 조건이 있는 유물은 반드시 `RESET` 또는 `AFTER_TRIGGER`를 작성한다.
11. 같은 `relicId`의 유물을 한 캐릭터에게 중복 장착할 수 없다.
12. 장착 후 유효 최대 체력이 0 이하가 되는 유물은 장착할 수 없다.
13. 유물 장착·해제·교체로 유효 최대 체력이 감소하면 현재 체력을 새 유효 최대 체력 이하로 제한하고 초과 체력은 삭제한다.
14. 같은 변수의 모든 고정 보정을 합산한 뒤 모든 비율 보정의 합을 적용한다.
15. 유효 공격력·이동력·치명타 피해율은 0 이상으로 제한한다.
16. 유효 스킬 최대 쿨타임은 1 이상, 현재 쿨타임은 `0~유효 최대 쿨타임`으로 제한한다.

### 5.15 환경 요소 시스템 [유지]

- 최소 1회 이상 검토 및 업데이트를 권장한다.
- 환경 요소 종류와 위치 변경 상호작용은 `[고도화]` 예정이다.
- 환경 요소의 유지 턴 수와 피해 발동 횟수는 서로 다른 카운트로 관리한다.

#### 환경 피해 데이터

```text
EnvironmentDamageDefinition
- environmentId
- triggerEvent
- baseDamage
- durationTurns
- maxActivationCount
- activationScope
- perTargetLimit
- reactToForcedMovement

EnvironmentDamageInstance
- environmentInstanceId
- affectedCells
- createdTurnIndex
- remainingTurns
- remainingActivationCount
- affectedTargetsThisAction
- affectedTargetsThisTurn
```

#### 환경 피해 발동 이벤트

| 이벤트 | 발동 시점 |
|---|---|
| `OnEnterCell` | 캐릭터가 해당 셀에 들어올 때 |
| `OnEndMovement` | 해당 셀에서 이동을 끝냈을 때 |
| `OnOwnerActionStart` | 해당 셀의 캐릭터가 행동을 시작할 때 |
| `OnOwnerActionEnd` | 해당 셀의 캐릭터가 행동을 끝낼 때 |
| `OnTurnEnd` | 턴 종료 시 해당 셀에 있을 때 |
| `OnInstalled` | 환경 요소가 설치되는 순간 |

일반 이동은 항상 `OnEnterCell` 확인 대상이다. 강제 이동은 환경 요소별 `reactToForcedMovement` 값이 `true`일 때만 `OnEnterCell` 확인 대상에 포함한다.

#### 유지 턴과 발동 횟수

- `remainingTurns`는 환경 요소가 전투판에 남는 기간이다.
- 환경 요소를 생성한 턴에는 `remainingTurns`를 감소시키지 않는다.
- 이후 `TurnCleanup`마다 1 감소하고 0이 되면 환경 요소를 제거한다.
- `remainingActivationCount`는 실제 환경 피해가 적용되었을 때만 1 감소한다.
- 피해 조건을 만족한 대상이 없으면 발동 횟수는 감소하지 않는다.
- `remainingActivationCount`가 0이 되면 추가 피해 발동을 중지한다.

#### 다수 대상 처리

| 발동 범위 | 처리 |
|---|---|
| `PerTarget` | 조건을 만족한 캐릭터마다 피해를 각각 적용 |
| `PerEnvironment` | 환경 요소 전체에서 한 번만 피해 적용 |

- 기본 발동 범위는 `PerTarget`이다.
- `PerEnvironment`에서 대상이 여러 명인 경우의 대상 선택 기준: [작성 필요]

#### 중복 피해 제한

```text
OncePerAction
OncePerTurn
OncePerEntry
Unlimited
```

- 일반 장판: `OncePerAction` [제안]
- 진입 함정: `OncePerEntry` [제안]
- 턴 종료 장판: `OncePerTurn` [제안]
- 실제 제한은 환경 요소별로 정의한다.

#### 환경 피해 처리 결과

- 환경 피해 계산 결과에 소수점이 발생하면 최종 결과를 반올림한다.
- 환경 피해로 체력이 0에 도달하면 즉시 전투 불능으로 전환한다.
- 전투 불능 캐릭터는 셀 점유를 해제한다.
- 이동 중 환경 피해로 전투 불능이 되면 남은 이동을 중지한다.
- 전투 불능 처리 후 승패를 판정한다.
- 환경 피해에 캐릭터 타입 상성과 치명타가 적용되는지 여부: [작성 필요]

#### 환경 요소 기획 문법

```text
ENVIRONMENT <환경ID> "<환경명>"
CELLS <적용 셀>
TRIGGER <발동 이벤트>
DAMAGE <피해량>
DURATION FullTurns <N>
ACTIVATIONS <횟수 | UNLIMITED>
SCOPE <PER_TARGET | PER_ENVIRONMENT>
LIMIT <ONCE_PER_ACTION | ONCE_PER_TURN | ONCE_PER_ENTRY | UNLIMITED>
FORCED_MOVE <true | false>
```

예시 형식:

```text
ENVIRONMENT environment_damage_001 "[작성 필요]"
CELLS [작성 필요]
TRIGGER OnEnterCell
DAMAGE N
DURATION FullTurns 3
ACTIVATIONS 2
SCOPE PER_TARGET
LIMIT ONCE_PER_ACTION
FORCED_MOVE true
```

#### 환경 기획 문법과 변수 매핑

| 기획 문법 | 저장 변수 | 변환 규칙 |
|---|---|---|
| `ENVIRONMENT` | `environmentId` | 중복되지 않는 문자열 ID로 저장 |
| `CELLS` | `affectedCells` | `HashSet<Vector2Int>`로 변환 |
| `TRIGGER` | `triggerEvent` | `EnvironmentTriggerEvent` 값으로 변환 |
| `DAMAGE` | `baseDamage` | 0 이상의 정수로 저장 |
| `DURATION FullTurns N` | `durationTurns`, `remainingTurns` | 두 값 모두 N으로 초기화. 생성 턴에는 감소하지 않음 |
| `ACTIVATIONS N` | `maxActivationCount`, `remainingActivationCount` | 두 값 모두 N으로 초기화 |
| `ACTIVATIONS UNLIMITED` | `maxActivationCount`, `remainingActivationCount` | 두 값 모두 `null`로 저장하고 감소하지 않음 |
| `SCOPE` | `activationScope` | `PER_TARGET` → `PerTarget`, `PER_ENVIRONMENT` → `PerEnvironment` |
| `LIMIT` | `perTargetLimit` | 행동당·턴당·진입당·무제한 enum으로 변환 |
| `FORCED_MOVE` | `reactToForcedMovement` | `true` 또는 `false` |

- 문법 파싱 결과는 환경 요소 정의 데이터에 저장한다.
- 전투에서 환경 요소가 생성되면 정의 데이터를 이용해 `EnvironmentDamageInstance`를 생성한다.
- `affectedTargetsThisAction`은 `ActionEnd`, `affectedTargetsThisTurn`은 `TurnCleanup`에서 초기화한다.

- 고도화 대상 환경 요소의 실제 종류·피해량·지속시간·발동 횟수는 [작성 필요]다.
- 환경 요소 고도화의 구현 시점: [작성 필요]

### 5.16 UI 시스템 [고도화]

아래 전투 조작 UI는 시스템 검증에 필요한 최소 구현 범위로 분류한다.

- 초기 배치 단계에서는 레벨별 초기 설치 가능 범위와 캐릭터 배치 상태를 표시한다.
- 초기 배치 단계에서는 행동 순서·이동 경로·일반 공격·스킬·적 행동 예고를 표시하지 않는다.
- 초기 배치 완료 후 전투 시작 입력을 제공한다.
- 행동 번호와 진영 배치를 표시한다.
- 플레이어가 행동 번호에 캐릭터를 배치할 수 있어야 한다.
- 플레이어가 턴 종료 전까지 아군 캐릭터의 행동 순서를 자유롭게 변경할 수 있어야 한다.
- 이동 경로를 그려서 결정할 수 있어야 한다.
- 일반 공격의 범위 내 타겟, 셀 선택형의 방향·셀, 방향성 공격의 방향·영향 셀을 표시한다.
- 캐릭터·셀·설치 타겟팅은 전장 전체를 지정할 수 있게 하고, 현재 이동 완료 예정 위치 기준 시전 가능 여부를 별도로 표시한다.
- 이동 완료 예정 위치와 지정점은 시전 가능 시 파란 실선, 사거리 밖이면 주황 점선으로 연결한다.
- 경로 변경으로 `범위 안 → 범위 밖`이 되면 연결 파괴 연출, `범위 밖 → 범위 안`이 되면 연결 융합 연출을 표시한다.
- 연결선에는 색상과 함께 `시전 가능` 또는 `사거리 밖` 문구를 표시한다.
- 방향성 스킬은 이동 완료 위치를 기준으로 방향과 영향 셀을 표시한다.
- 스킬 쿨타임을 표시한다.
- 적의 타겟 캐릭터와 예고 경로를 표시한다.
- 상태이상과 띄워짐 여부를 표시한다.
- 현재·선택 시간대, 현재·최대 보유 시간 파편과 전환에 필요한 파편 수량을 표시한다.

### 5.20 회중시계 기반 시간대 전환 시스템 [신규]

#### 시스템 목적

시간대 전환은 위치와 행동 순서를 설계하는 기존 전투 위에 **이번 턴의 전장 공통 규칙 선택**을 추가한다. 플레이어는 전투 중 시간 파편을 획득해 회중시계에 보관하고, 필요한 파편을 사용하여 과거·현재·미래를 선택한 뒤 같은 행동 계획의 피해·치명타·회복·유물 결과를 바꾼다.

- 시간 파편은 기존 `회중시계 충전량`을 대체하는 동일한 전투 자원이며 별도의 두 번째 자원이 아니다.

- 전투는 `현재` 시간대에서 시작한다.
- 시간대 선택은 캐릭터 행동 슬롯을 소비하지 않는다.
- 시간대 변경은 행동 실행 중이 아니라 `Planning`에서만 선택한다.
- 시간대는 턴 전체에 하나만 적용하며 행동 슬롯 사이에는 변경하지 않는다.
- 시간대가 바뀌어도 캐릭터 위치·체력·상태이상·행동 슬롯·잠긴 계획은 유지한다.
- P0에서는 시간대에 따라 이동 가능 셀·장애물·적·환경 요소를 바꾸지 않는다. 해당 변화는 P2로 분리한다.
- `[선택 필요]` 현재에서 시간 파편을 사용해 과거 또는 미래로 변경했을 때 `2턴 적용 후 현재로 자동 복귀`할지, `플레이어가 다시 변경할 때까지 계속 유지`할지 결정해야 한다. 현재 상세 규칙은 계속 유지하는 방식을 임시 기준으로 작성한다.

#### 턴 단위 이용 흐름

```text
현재 시간대·보유 시간 파편 확인
→ 적 행동 예고 확인
→ 아군 행동 순서·이동·공격·스킬 설계
→ 시간대별 효과·유물 활성 상태·예상 시간 파편 확인
→ 이번 턴 시간대 선택
→ 행동 계획·선택 시간대·보유 시간 파편 검증
→ 행동 계획과 시간대 잠금
→ 잠긴 수량의 시간 파편 사용 및 효과 확정
→ 시간대 턴 시작 효과 처리
→ 행동 실행
→ 직접 공격·콤보 시간 파편 즉시 누적
→ 턴 정산 및 턴 경과 시간 파편 지급
```

#### 선택·잠금·시간 파편 사용 규칙

- `Planning` 진입 시 `selectedTimePeriod = currentTimePeriod`로 초기화한다.
- 플레이어는 턴 종료 전까지 선택 시간대를 자유롭게 바꿀 수 있다.
- 같은 시간대를 유지하면 시간 파편을 사용하지 않고 전환 연출도 재생하지 않는다.
- 다른 시간대를 선택하면 `PlanValidation`에서 현재 보유 시간 파편이 필요한 수량 이상인지 검사한다.
- 검증 성공 시 행동 계획·선택 시간대·사용할 시간 파편 수량을 함께 잠근다.
- 실제 시간 파편 차감과 `currentTimePeriod` 변경은 `TimeShiftResolution`에서 하나의 처리 단위로 수행한다.
- 계획 검증 실패, 비용 부족, `PlanLocked` 이후 재선택, 승패 확정 상태에서는 변경할 수 없다.
- 검증 실패 시 시간 파편을 차감하지 않고 `Planning`으로 돌아간다.
- 이번 턴 실행에서 얻을 예상 시간 파편은 현재 선택 가능 여부에 포함하지 않는다. 실행 중 획득한 파편은 누적 즉시 HUD에 반영하지만 다음 `Planning`부터 사용할 수 있다.
- 계획 검증에 실패하거나 시간대 변경 전에 전투 결과가 확정되면 시간 파편을 차감하지 않는다.
- `TimeShiftResolution`에서 시간 파편 차감과 시간대 변경 중 하나라도 실패하면 둘 다 반영하지 않는다.
- 시간대 변경에 성공한 뒤 사용한 시간 파편은 복구하지 않는다.
- 시간 파편을 시간대 변경 이외의 용도로 사용하는 규칙은 현재 정의하지 않는다.
- P0 필요 파편은 출발·도착 시간대와 무관한 공통 고정 수량을 우선 사용한다. 실제 수량은 `[작성 필요]`다.

#### 시간 파편 획득 규칙

| 조건 | 획득량 | 판정·지급 시점 |
|---|---:|---|
| 턴 경과 | `N_turn`개 | 승패가 확정되지 않은 `TurnCleanup`의 마지막 단계 |
| 유효 공격 | `N_attack`개 | 아군의 직접 공격 피해 묶음 처리 완료 후 |
| 상태이상 콤보 | `N_combo`개 추가 | 공격 행동 시작 시 기절·띄워짐이었던 적에게 유효 공격 성공 후 |

- 아군의 일반 공격 또는 피해 스킬이 적에게 1 이상의 최종 피해를 주면 유효 공격으로 판정한다.
- 다단 공격·광역 공격도 공격 행동 1회당 기본 파편은 최대 1회 지급한다.
- 공격 행동 시작 시 피해 대상 후보 중 한 명 이상이 기절 또는 띄워짐 상태였고, 그 대상에게 1 이상의 최종 피해를 주면 콤보로 판정한다.
- 상태이상을 처음 적용한 같은 행동은 콤보가 아니다. 상태가 유지되는 동안 실행되는 이후 공격부터 콤보다.
- 다단·광역 공격으로 여러 콤보 대상을 공격해도 행동 1회당 추가 파편은 최대 1회다.
- 빗나감·취소·0 피해·아군 대상 피해는 시간 파편을 지급하지 않는다.
- 상태이상·환경 요소·유물·시간대 효과의 간접 피해는 공격 및 콤보 파편 획득에서 제외한다.
- 콤보 성립 시 `N_attack + N_combo`를 함께 지급한다.
- 시간 파편은 최대 보유량을 초과할 수 없으며 초과 획득분은 버린다.
- 승패를 확정한 피해 묶음에서 발생한 직접 공격 파편은 결과에 영향을 주지 않으므로 지급하지 않는다.
- 전투 시작 보유량과 전투 종료 시 남은 시간 파편의 처리 방식은 `[작성 필요]`다.

#### 시간대별 전투 효과 [제안][미확정]

시간대 효과는 아군과 적군 모두에게 동일하게 적용한다. 타입 피해 강화도 해당 타입을 가진 양 진영 캐릭터에게 적용한다. 캐릭터·공격·스킬 원본 값을 직접 변경하지 않고 현재 시간대의 별도 보정 계층으로 제공한다.

| 시간대 | 강화 타입 | 타입 피해 보정 | 전장 공통 효과 | 전투 성격 |
|---|---|---:|---|---|
| 과거 | 계승자 | 주는 피해 `+30%` | 모든 생존 캐릭터가 받는 최종 피해 `×2` | 고위험·고화력 |
| 현재 | 각성자 | 주는 피해 `+30%` | 모든 생존 캐릭터의 치명타 피해율 `+30%p` | 띄우기·치명타 연계 |
| 미래 | 기술자 | 주는 피해 `+30%` | 행동 실행 전 모든 생존 캐릭터가 유효 최대 체력의 `7%` 회복 | 유지력·장기전 |

공통 계산 규칙:

```text
기본 피해
→ 타입 상성 배율
→ 현재 시간대의 강화 타입 피해 배율
→ 치명타 배율과 현재 시간대 치명타 보정
→ 기타 주는 피해 보정
→ 대상의 받는 피해 보정과 과거 ×2
→ 최종 반올림
→ 0 이상 제한
```

- 시간대 타입 피해 `+30%`는 해당 타입 캐릭터가 주는 직접 피해에 `1.3`을 곱한다.
- 과거의 받는 피해 `×2`는 타입·치명타·주는 피해 보정 이후 적용한다.
- 현재의 치명타 피해율 증가는 원래 치명타 피해율에 `30%p`를 더한다. 예를 들어 `150%`는 현재 시간대에서 `180%`가 된다. 치명타가 성립하지 않은 공격에는 적용하지 않는다.
- 미래 회복량은 `유효 최대 체력 × 0.07`을 계산한 뒤 반올림한다.
- 미래 회복은 미래로 변경한 턴과 미래를 유지한 턴 모두 `TimeShiftResolution`에서 1회 처리한다.
- 미래에서 다른 시간대로 변경한 턴에는 회복하지 않는다.
- 전투 불능 캐릭터는 회복하지 않으며 부활하지 않는다. 현재 체력은 유효 최대 체력을 초과하지 않는다.
- 미래 회복은 시간대 한정 상시 유물 활성 상태와 유효 최대 체력을 먼저 갱신한 뒤 계산한다.
- 회복 때문에 승패가 번복되는 상황을 막기 위해 `TimeShiftResolution` 진입 전 전투 결과가 확정된 경우 이 단계를 실행하지 않는다.

#### `TimeShiftResolution` 처리 순서

```text
잠긴 선택 시간대·비용 재확인
→ 변경 시 잠긴 수량의 시간 파편 차감
→ currentTimePeriod 갱신
→ 시간대 전역 보정 갱신
→ 시간대 한정 상시 유물 활성 상태 재계산
→ 유효 파라미터 재계산 및 현재 체력 상한 제한
→ 변경 시 OnTimePeriodChanged → OnTimePeriodEntered, 유지 시 OnTimePeriodMaintained 이벤트
→ 미래 시간대라면 생존 캐릭터 회복
→ 회복 및 시간대 진입 유물 효과 큐 처리
→ 전투 불능·승패 판정
→ 배경·조명·BGM·회중시계 연출 요청
→ Executing
```

- 규칙 결과를 먼저 확정하고 연출을 요청한다. 애니메이션 프레임·오디오 재생 성공 여부는 전투 계산에 영향을 주지 않는다.
- 동일 시간대 유지 시에도 유물 활성 상태와 턴 시작 효과를 재확인한다.
- 시간대 변경으로 유효 최대 체력이 감소하면 `currentHp = min(currentHp, effectiveMaxHp)`로 제한한다.
- 시간대 진입·회복 유물 효과로 양 진영이 동시에 전투 불능이 되면 기존 승패 규칙에 따라 패배한다.

#### 시간대 한정 유물

- 유물은 `allowedTimePeriods`를 0개 이상 가진다. 비어 있으면 모든 시간대에서 작동한다.
- 상시 보정형 유물은 현재 시간대가 조건에 포함될 때만 유효값 계산에 포함한다.
- 트리거형 유물은 트리거 발생 시점의 현재 시간대가 조건과 일치할 때만 발동한다.
- 비활성화되어도 장착 상태·누적 카운터·내부 쿨타임은 유지한다.
- 시간대를 벗어나기 전에 효과 큐에 들어간 효과는 취소하지 않는다.
- 시간대 전환 연계를 위해 `OnTimePeriodChanged`, `OnTimePeriodEntered`, `OnTimePeriodMaintained`, `OnFutureTurnHeal` 이벤트를 유물 트리거 허용 목록에 추가한다. `[제안]`
- 한 유물은 과거·현재·미래 중 하나 이상의 시간대를 지정할 수 있으며 복수 시간대 지정을 허용한다.
- 시간대 고착은 특정 시간대의 기본 효과와 유물 조합이 항상 가장 유리해 전투 상황과 무관하게 같은 시간대만 반복 선택하는 현상을 뜻한다. 이를 줄이기 위해 단순 상시 강화뿐 아니라 `시간대 진입`, `서로 다른 시간대 연속 선택`, `시간대를 변경한 턴`에 보상하는 유물을 함께 검토한다.

```text
RelicTimeCondition
- allowedTimePeriods: List<TimePeriod>
```

#### 배경·BGM·연출

| 시간대 | 전장 프리셋 | BGM |
|---|---|---|
| 과거 | 이예프 성벽 | 과거 전용 BGM `[사운드 디자인 필요]` |
| 현재 | 고원지대 | 현재 전용 BGM `[사운드 디자인 필요]` |
| 미래 | 메리디에스 | 미래 전용 BGM `[사운드 디자인 필요]` |

- 전투 시작 시 현재 시간대의 고원지대 프리셋과 현재 BGM을 적용한다.
- 시간대 변경 시 배경·조명·환경 연출·BGM을 하나의 프리셋으로 교체한다.
- 같은 시간대를 유지하면 프리셋과 BGM을 다시 로드하지 않는다.
- BGM의 전환 방식, 페이드 시간, 시간대 재방문 시 처음부터 재생할지 이전 위치에서 이어갈지는 사운드 디자이너의 설계·검증 항목으로 둔다.
- 전환 연출이 실패하거나 지연되어도 전투 규칙은 잠긴 시간대로 정상 실행한다.

#### UI 필수 정보

- 현재 시간대와 이번 턴 선택 시간대를 구분하여 표시한다.
- 현재·최대 보유 시간 파편, 전환에 필요한 파편, 부족한 파편과 사용 후 남는 파편을 표시한다.
- `현재 사용 가능 시간 파편`과 `이번 턴 예상 획득 시간 파편`을 다른 색과 문구로 분리한다.
- 과거·현재·미래의 강화 타입과 공통 효과를 한 화면에서 비교한다.
- 선택 시간대에서 강화되는 아군·적군과 활성·비활성 유물을 표시한다.
- 미래 회복 예상량, 현재 치명타 보정, 과거 받는 피해 배율 등 계획에 직접 영향을 주는 값을 표시한다.
- 시간 파편이 부족한 시간대는 비활성화하고 필요한 파편과 부족한 파편을 표시한다.
- `PlanLocked` 이후에는 선택 시간대가 잠겼음을 표시한다.
- 위치 변경 예상 결과 UI는 추가하지 않지만 시간대 효과에 따른 수치 변화는 표시한다.

## 6. 전투 진행 예시

전투 진입 및 초기 배치:

```text
레벨 진입
→ 레벨별 초기 설치 가능 범위 표시
→ 캐릭터 배치
→ 배치 완료
→ 전투 시작 입력
→ 동전 던지기로 최초 선공 결정
→ 행동 순서 및 행동 설계 정보 활성화
```

적이 선공이고 한 턴에 행동 번호가 1~6번까지 있는 경우:

```text
1번 행동: 적
2번 행동: 아군 — 플레이어가 행동 캐릭터와 행동 내용 결정
3번 행동: 적
4번 행동: 아군 — 플레이어가 행동 캐릭터와 행동 내용 결정
5번 행동: 적
6번 행동: 아군 — 플레이어가 행동 캐릭터와 행동 내용 결정
```

턴 설계 및 실행:

```text
행동 순서 슬롯 생성
→ 모든 캐릭터를 행동 순서에 배치
→ 플레이어가 아군 캐릭터의 순서와 행동을 설계
→ 턴 종료 전까지 순서·경로·공격·스킬을 자유롭게 수정
→ 모든 캐릭터 배치 완료
→ 턴 종료 입력
→ 행동 순서 및 행동 내용 잠금
→ 1번 행동부터 빠르게 실행
→ 모든 행동 실행 후 턴 종료 처리
```

아군 캐릭터 행동:

```text
캐릭터 선택
→ 이동 경로 그리기 또는 제자리 유지
→ 일반 공격 또는 스킬 선택
→ 필요한 경우 방향·대상·셀 선택
→ 행동 확정
→ 빠른 연출로 실행
```

적 캐릭터 행동:

```text
캐릭터 1명 타겟팅
→ 접근 경로 예고
→ 적 행동 시점에 접근 가능 경로 확인
→ 접근 가능: 타겟에게 이동 후 가능한 방향으로 공격
→ 접근 불가능: 가장 가까운 곳까지 이동 후 공격
```

## 7. 개발 우선순위

1. **P0 — 캐릭터 시스템:** 캐릭터 파라미터와 전투 객체 규격 확정.
2. **P0 — 전투·초기 배치·행동 순서 시스템:** 전투 진입, 초기 배치, 턴, 행동, 선공, 행동 번호 및 승패 규칙 확정.
3. **P0 — 전투판·행동 설계·이동 시스템:** 배치 범위, 경로 작성, 직선 이동, 행동 순서와 위치 정보 확정.
4. **P0 — 공격·타겟팅·스킬·쿨타임 시스템:** 일반 공격과 스킬의 선택 및 실행 규격 확정.
5. **P1 — 상태이상 시스템:** 밀치기·당기기·띄우기·기절과 치명타 연결 규칙 확정.
6. **P1 — 적 행동 인터페이스:** FSM과 적 행동 시스템 사이의 계획 요청·재검증·실행 계약만 구현. 적 AI 세부 기획은 추후 진행.
7. **P0 — 시간대 전환 시스템:** 시간 파편 획득·보유·사용, 시간대 선택·잠금·`TimeShiftResolution`·시간대 전역 보정과 미래 회복 구현.
8. **P0 — FSM·최소 전투 UI:** 확정된 전투 흐름과 행동 슬롯·경로·공격·스킬·시간대 선택·턴 종료 입력 및 필수 표시 연결.
9. **P1 — 가방·유물 장착·시간대 조건:** 가방 보유, 캐릭터당 3슬롯, 드래그 장착, 변수 보정, 시간대 활성 조건 구현.
10. **P2 — 애니메이션·스킬 이펙트·시간 전환 연출:** 빠른 전투 연출과 난투 분위기, 회중시계·배경·BGM 전환 고도화.
11. **P1/P2 — 환경 요소·아웃게임·대화 시나리오:** 선행 시스템에 맞춰 검토 및 업데이트. 세부 우선순위 [작성 필요].

### 10.2 논의 필요

#### 핵심 논의 필요

- 위치 계산의 가독성: 핵심 재미인 위치 변경 계산에서 적 경로 재계산, 실시간 셀 점유 변경, 충돌에 따른 이후 공격·스킬 취소가 함께 발생할 때 플레이어가 예상 결과 UI 없이 최종 결과를 충분히 예측하고 실패 원인을 이해할 수 있는지 검증 및 논의가 필요하다.
- 시간대 선택의 판단 밀도: 행동 순서·경로·공격 설계에 시간대 비교까지 추가했을 때 모바일 턴 설계 시간이 과도하게 늘어나지 않는지 검증이 필요하다.
- 시간대 고착 검증: 특정 시간대의 기본 효과와 유물 조합이 항상 가장 유리해 전투 상황과 무관하게 같은 시간대만 반복 선택하는 현상이 발생하는지 플레이테스트로 확인해야 한다.

#### 기타 논의 필요

- 시간대 유지·복귀 방식을 `과거·미래 2턴 적용 후 현재 자동 복귀`와 `플레이어가 변경할 때까지 계속 유지` 중에서 선택한다. 자동 복귀를 선택하면 턴 계산 시작점·복귀 처리 시점·적용 중 재전환 가능 여부·자동 복귀 비용도 함께 확정한다.
- 시간대 전환 비용을 공통 고정값으로 유지할지 시간대별 차등 비용으로 확장할지 결정한다.
- 적 행동 예고에 시간대 변경 후 예상 피해까지 표시할지 결정한다. P0에서는 경로·타겟은 유지하고 수치 강조만 갱신하는 안을 권장한다.

## 12. 유저 시나리오

### 12.1 전체 진행 흐름

`메인 메뉴 → 도전 모드 입장 → 타일 선택 → 전투 입장 → 초기 배치 → 선공 결정 → 행동 설계 → 턴 실행 → 승리/패배`

| 단계 | 유저 행동 | 시스템 처리 및 표시 |
|---|---|---|
| 메인 메뉴 | 도전 모드를 선택한다. | 도전 모드 화면으로 이동한다. 메인 메뉴의 기타 구성은 기존 시스템을 유지한다. |
| 도전 모드 | 도전할 타일을 확인한다. | 선택 가능한 타일을 표시한다. 타일의 종류·상태·해금 조건·표시 정보는 `[작성 필요]`다. |
| 타일 선택 | 전투 타일을 선택하고 입장한다. | 선택 타일의 전투로 진입한다. 입장 확인 절차와 표시 정보는 `[작성 필요]`다. |
| 전투 입장 | 레벨별 초기 설치 가능 범위에 캐릭터를 배치한다. | 초기 배치 단계에서는 설치 가능 셀만 안내하고 행동 순서·이동 경로·공격·스킬·적 의도를 표시하지 않는다. |
| 전투 시작 | 배치를 마치고 전투 시작을 선택한다. | 동전 던지기로 첫 턴의 선공 진영을 결정하고 행동 슬롯을 생성한다. |
| 행동 설계 | 아군 행동 슬롯에 캐릭터를 배치하고 이동·공격 또는 스킬을 정한다. | 턴 종료 전까지 캐릭터 배치 순서와 각 행동 계획을 자유롭게 수정할 수 있다. |
| 턴 실행 | 모든 아군 캐릭터를 행동 순서에 배치한 뒤 턴 종료를 누른다. | 계획을 잠근 뒤 아군과 적군 행동을 정해진 순서대로 빠르게 실행한다. |
| 다음 턴 | 생존 진영의 행동을 다시 설계한다. | 상태이상·쿨타임·환경 요소·유물 카운트를 정산하고 선공 진영을 교대한다. |
| 승리 | 모든 적을 전투 불능으로 만든다. | 즉시 승리를 판정하고 승리 결과 화면으로 이동한다. 결과 화면의 상세 구성은 `[작성 필요]`다. |
| 패배 | 모든 아군이 전투 불능이 된다. | 즉시 패배를 판정하고 패배 결과 화면으로 이동한다. 결과 화면의 상세 구성은 `[작성 필요]`다. |

1. 유저가 선택한 타일의 전투에 입장한다.
2. 시스템은 해당 레벨에 정의된 정사각형 전투판과 초기 설치 가능 범위를 불러온다.
3. 유저는 설치 가능 범위 안에 출전 캐릭터를 배치한다.
4. 시스템은 설치 가능한 셀, 선택한 캐릭터, 현재 점유 상태를 갱신한다.
5. 이 단계에서는 행동 순서, 이동 경로, 공격, 스킬, 적의 타겟과 예정 경로를 표시하지 않는다.
6. 유저가 전투 시작을 선택하면 현재 배치를 확정하고 전투 시작 단계로 이동한다.
7. 모든 출전 캐릭터가 서로 다른 유효 설치 가능 셀에 배치되면 배치가 완료되고 전투 시작 버튼이 활성화된다.

#### 12.2.2 선공 결정 및 행동 슬롯 구성

1. 첫 턴 시작 시 시스템이 동전을 던져 선공 진영을 결정한다.
2. 선공 진영은 첫 번째 행동 슬롯을 배정받는다.
3. 이후 행동 슬롯은 `선공 진영 → 후공 진영 → 선공 진영 → 후공 진영` 순서로 교차 배치된다.
4. 적 선공이고 행동 슬롯이 6개라면 적군은 1·3·5번, 아군은 2·4·6번 슬롯을 사용한다.
5. 양 진영의 행동 가능 캐릭터 수가 다르면 교차 슬롯을 먼저 생성한 뒤 남은 진영의 행동 슬롯을 후순위에 연속 추가한다. 아군 후순위 슬롯은 플레이어가, 적 후순위 슬롯은 적 행동 시스템이 배치한다.
6. 다음 턴부터 선공 진영은 턴마다 교대한다.

#### 12.2.3 적 행동 예고

1. 전투가 시작되면 시스템은 적 AI 행동 계획을 요청한다.
2. 적은 공격할 아군 캐릭터 한 명을 타겟으로 지정한다.
3. 타겟팅 스킬이 아니더라도 공격 대상 캐릭터 한 명을 지정해 예고한다.
4. 시스템은 적이 지정한 타겟과 예정 이동 경로를 표시한다.
5. 유저는 해당 정보를 확인하고 아군의 위치와 행동 순서를 설계한다.
6. 적 AI의 타겟 선정·행동 평가·스킬 선택 기준은 `[추후 기획]`이다.

#### 12.2.4 아군 행동 순서 설계

1. 유저는 아군 행동 슬롯마다 행동할 캐릭터를 배치한다.
2. 턴에 참여하는 모든 아군 캐릭터가 행동 슬롯에 정확히 한 번씩 포함되어야 하며 중복 배치는 허용하지 않는다.
3. 유저는 턴 종료 전까지 슬롯에 배치한 캐릭터의 순서를 자유롭게 변경할 수 있다.
4. 유저는 이미 작성한 이동 경로·일반 공격·스킬 계획도 턴 종료 전까지 다시 선택하거나 취소할 수 있다.

#### 12.2.5 캐릭터 이동 설계

1. 유저가 행동 슬롯에 배치할 캐릭터를 선택한다.
2. 유저는 말판 위에 경로를 그려 이동 경로를 지정한다.
3. 경로는 상·하·좌·우로만 연결하며 대각선 이동은 불가능하다.
4. 경로 길이는 해당 캐릭터의 이동력 이하로 제한한다.
5. 제자리에서 공격 또는 스킬만 사용할 경우 이동 경로를 지정하지 않는다.
6. 위치 변경의 예상 결과를 미리 계산해 보여주는 UI는 제공하지 않는다.

#### 12.2.6 일반 공격 및 스킬 설계

1. 이동을 정한 뒤 일반 공격 또는 스킬 중 하나를 선택한다.
2. 공격·스킬의 사거리 기준점은 계획한 이동 경로의 마지막 셀이다. 이동하지 않았다면 현재 셀을 기준점으로 사용한다.
3. 이동 경로를 작성하거나 수정하면 시스템은 새 마지막 셀을 기준으로 실제 시전 범위와 지정 대상의 실행 가능 여부를 즉시 다시 표시한다.
4. 일반 공격은 `범위 내 타겟팅`, `셀 선택`, `방향성` 중 하나의 유형을 사용한다.
5. 셀 선택형 일반 공격은 `방향 선택 → 셀 선택` 순서로 지정한다.
6. 방향성 일반 공격은 이동 완료 위치를 기준으로 방향을 선택해 시전한다.
7. 스킬은 `범위 내 타겟팅`, `셀 선택`, `설치형`, `방향성` 중 하나의 유형을 사용한다.
8. 범위 내 타겟팅은 거리 제한 없이 캐릭터를 지정하고, 실행 시 이동 완료 위치 기준 범위 안이면 별도 방향 선택 없이 시전한다.
9. 셀 선택은 거리 제한 없이 셀을 지정하고, 실행 시 이동 완료 위치 기준 범위 안이면 해당 셀을 기준으로 효과를 시전한다.
10. 설치형은 거리 제한 없이 셀을 지정하고, 실행 시 이동 완료 위치 기준 범위 및 설치 조건을 만족하면 설치물을 생성한다.
11. 방향성은 이동 완료 위치를 기준으로 방향을 선택해 시전한다.
12. 캐릭터는 스킬 한 개를 보유하며, 스킬은 쿨타임이 0일 때만 사용할 수 있다.
13. 한 행동에서 이동은 최대 1회, 일반 공격은 최대 1회 사용할 수 있다.
14. 스킬을 선택한 행동에서는 일반 공격을 사용할 수 없다.
15. 행동 순서는 `이동 → 일반 공격/스킬`만 가능하다. 일반 공격이나 스킬 후 이동으로 순서를 바꿀 수 없다.
16. 이동 없이 제자리에서 일반 공격 또는 스킬을 사용하는 것은 가능하다.

#### 12.2.7 계획 검증 및 확정

1. 유저가 모든 캐릭터를 행동 슬롯에 배치하고 턴 종료를 누른다.
2. 유저는 턴 종료 전 현재 보유 시간 파편과 시간대 효과를 비교하여 이번 턴 시간대를 선택한다. 이번 턴 예상 획득 파편은 표시하지만 선택 가능 여부에는 포함하지 않는다.
3. 시스템은 캐릭터 누락·중복 배치, 이동력, 경로 연결, 공격·스킬 사용 조건, 쿨타임, 타겟·셀 지정 여부, 선택 시간대와 보유 시간 파편을 검증한다.
4. 유효하지 않은 계획이 있으면 턴 실행으로 넘어가지 않고 수정이 필요한 항목을 표시한다.
5. 검증이 완료되면 현재 계획·선택 시간대·전환 비용을 잠근다.
6. 다른 시간대를 선택했다면 비용을 소비하고 시간대 효과·유물 활성 상태를 갱신한다. 미래에서 실행할 턴이면 생존 캐릭터를 회복한 뒤 실행 단계로 이동한다.
7. 계획이 잠긴 뒤에는 해당 턴의 행동 순서·행동 계획·시간대를 수정할 수 없다.
8. 행동 설계와 확정에 필요한 최소 UI는 우선 구현하고, 드래그 연출·상세 툴팁·입력 편의 기능은 `[추후 구현]`한다.

#### 12.2.8 행동 실행

각 행동 슬롯은 다음 순서로 처리한다.

1. 행동 캐릭터가 전투 불능인지 확인한다. 전투 불능이면 해당 행동을 종료한다.
2. 행동 시작 시점에 적용할 상태이상, 환경 요소, 유물 트리거를 처리한다.
3. 기절 상태인지 확인한다. 기절 상태라면 해당 행동 슬롯을 소비하고 이동·일반 공격·스킬을 모두 패스한다.
4. 적 행동이면 예고한 타겟의 현재 위치를 기준으로 이동 경로와 공격 가능 방향을 다시 계산한다.
5. 타겟에게 접근할 수 있으면 공격 가능한 위치까지 이동한다.
6. 접근할 수 없으면 타겟과 가장 가까운 도달 가능 위치까지 이동한 뒤 공격 가능 여부를 판정한다.
7. 아군과 적군 모두 확정된 경로를 한 셀씩 이동한다. 위치와 셀 점유 정보는 각 셀 진입 시 실시간으로 갱신한다.
8. 다음 셀이 다른 캐릭터 또는 진입 불가능한 대상으로 점유되어 있으면 현재 셀에서 멈추고 충돌 처리한다.
9. 충돌 시 남은 이동 경로를 폐기하고 이후 예정된 일반 공격 또는 스킬을 취소한다. 충돌 자체의 피해는 없다.
10. 이동 중 진입한 셀에 환경 요소가 있으면 해당 환경 요소의 발동 조건에 따라 효과를 처리한다.
11. 환경 피해로 이동 중 체력이 0이 되면 즉시 전투 불능으로 만들고 셀 점유를 해제하며 남은 행동을 취소한다.
12. 이동이 정상 완료되고 사용 조건을 만족하면 계획한 일반 공격 또는 스킬을 실행한다.
13. 피해, 밀치기, 당기기, 띄우기, 기절, 환경 요소 생성, 유물 트리거를 효과 큐 순서에 따라 처리한다.
14. 아군의 직접 공격이 적에게 1 이상의 피해를 주면 공격 행동당 1회 회중시계 기본 충전을 지급한다. 공격 시작 시 기절·띄워짐 상태였던 적에게 유효 피해를 주면 추가 콤보 충전을 지급한다.
15. 밀치기·당기기로 위치가 바뀔 때도 논리 셀과 점유 정보를 즉시 갱신한다.
16. 아군에게 밀치기·당기기를 적용할 수 있지만 해당 스킬의 피해는 아군에게 적용하지 않는다.
17. 띄워짐 대상은 일반 공격에 항상 치명타 피해를 받는다. 스킬은 스킬별 치명타 적용 가능 여부에 따라 판정한다.
18. 모든 최종 소수점 수치는 전체 계산이 끝난 뒤 반올림한다.
19. 체력이 0이 된 캐릭터는 즉시 전투 불능으로 만들고 해당 셀 점유를 해제한다.
20. 효과 처리가 끝날 때마다 승리·패배 조건을 검사한다.
21. 승패가 결정되지 않으면 다음 행동 슬롯을 빠르게 이어서 실행한다.

#### 12.2.9 턴 정산 및 다음 턴

1. 모든 행동 슬롯의 실행이 끝나면 턴 종료 정산을 시작한다.
2. 턴 종료 시 발동하는 환경 요소 피해와 효과를 처리한다.
3. 상태이상 지속시간과 환경 요소의 남은 턴·남은 발동 횟수를 갱신한다.
4. 유물의 누적 카운트, 초기화 조건, 턴당 발동 제한을 갱신한다.
5. 사용한 스킬은 다음 턴 준비 단계부터 쿨타임을 감소시킨다.
6. 띄워짐은 대상의 다음 `ActionBegin` 또는 현재 턴의 `TurnCleanup` 시작 중 먼저 발생하는 시점에 해제한다.
7. 전투가 계속되면 선공 진영을 교대하고 새 행동 슬롯을 구성한다.
8. 승패가 없으면 턴 경과 시간 파편을 지급한다.
9. 유저는 다음 턴의 아군 행동 순서·행동·시간대를 다시 설계한다.

#### 12.2.10 승리 및 패배

- 모든 적 캐릭터가 전투 불능이면 즉시 승리한다.
- 모든 아군 캐릭터가 전투 불능이면 즉시 패배한다.
- 승리 또는 패배가 확정되면 남은 행동 슬롯과 효과 실행을 중단하고 결과 화면으로 전환한다.
- 아군과 적군이 같은 효과 처리에서 모두 전투 불능이 되면 패배한다.
- 결과 화면에 표시할 정보, 보상, 재도전 및 다음 이동 방식은 `[작성 필요]`다.

## 13. 디자인 필요 항목

유지 대상인 디자인과 UI도 최소 1회 이상 검토하고 필요한 업데이트를 진행한다. 아래 항목은 현재 시스템 기획을 시각적으로 구현하기 위해 필요한 디자인 범위이며, 확정되지 않은 콘텐츠나 기능을 자의적으로 추가하지 않는다.

### 13.1 공통 화면 및 표현 기준

- [유지·검토] 기존 디자인 무드, 디자인 에셋, 배경의 유지 가능 범위 검토
- [작성 필요] 3D 기반 2.5D 쿼터뷰의 카메라 각도, 캐릭터 비율, 셀 크기, 가림 처리 규격
- [작성 필요] 모바일 화면 비율별 안전 영역과 최소 터치 영역
- [작성 필요] 아군·적군·선택 상태·행동 가능 상태의 공통 색상 및 외곽선 규칙
- [작성 필요] 시스템 공통 팝업, 확인, 취소, 비활성, 오류 표시 규격
- [방향 유지] 행동 설계 단계는 정보를 명확하게 읽을 수 있도록 구성하고, 실행 단계는 빠른 난투의 느낌을 전달한다.
- [제외] 위치 변경 예상 결과 UI는 제작하지 않는다.

- [필요] 도전 모드 화면의 타일 배치 영역
