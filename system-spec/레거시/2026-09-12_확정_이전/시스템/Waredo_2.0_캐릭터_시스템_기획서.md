## 시스템 브리핑

캐릭터 시스템은 전투에 참여하는 캐릭터의 분류, 시간대 태그, 기본 파라미터, 일반 공격, 일반 스킬·궁극기, 상태이상 면역과 관련 변수의 소유권을 정의한다. 아군 캐릭터의 시간대 태그는 `과거` 또는 `미래`만 사용하며 태그 사이의 상성은 없다.

최대 체력·치명타 피해율·이동력은 캐릭터 원본 파라미터로 관리한다. 모든 캐릭터의 초기 치명타 피해율은 임시로 `120%`를 공통 사용한다. 일반 공격 피해는 캐릭터가 아니라 일반 공격 정의의 `normalAttackDamage`가 소유하고, 스킬 피해는 개별 `Damage` 효과의 `damageEffectValue`가 소유한다. 현재 체력은 게임 최초 시작 시 최대 체력으로 초기화하며, 이후에는 스테이지 사이에 저장·유지한다. 최대 체력이 변경되어 현재 체력이 이를 초과할 때만 초과분을 절삭한다.

일반 공격은 `Directional`, `SelfCentered`, `TileSelect` 세 방식을 사용하고, 스킬은 여기에 `SelfBuff`를 더한 네 방식을 사용한다. `Directional`은 상·하·좌·우 중 한 방향을 선택하고, `SelfCentered`는 실행 시점의 자신을 기준으로 정해진 범위에 피해를 주며, `TileSelect`는 절대 셀 좌표 대신 시전자 기준 상대 방향·거리를 저장한다. `SelfBuff`는 별도 목표를 지정하지 않고 시전자 자신에게 버프 효과를 적용한다. 설치형 스킬과 캐릭터 직접 지정형은 사용하지 않는다. 캐릭터 시스템은 공격·스킬의 원본 데이터와 계산에 필요한 값을 제공하며, 실제 타겟 재검증, 피해 적용, 상태이상, 반격, 강제 이동, 전투 불능과 실행 실패 처리는 전투 시스템이 담당한다.

아군 캐릭터는 일반 스킬과 그에 대응하는 궁극기 스킬을 하나씩, 총 2개 보유한다. 현재 시간대가 캐릭터의 시간대 태그와 일치하면 스킬 슬롯의 일반 스킬이 궁극기로 교체되고, 일치하지 않으면 일반 스킬을 사용한다. 이 전환은 동일 스킬 슬롯의 `cooldownRemaining`을 초기화하거나 변경하지 않는다. 적 캐릭터는 프로토타입 기준으로 시간대 태그와 궁극기를 사용하지 않는다.

문서 하단 `4-1-10. 콘텐츠 기획 문법`은 캐릭터·일반 공격·스킬 콘텐츠에 필요한 필드를 정의한다. 개별 캐릭터의 실제 최대 체력·이동력·일반 공격·스킬·면역 값은 별도의 캐릭터 콘텐츠 테이블에서 작성하고 관리한다.

## [확인 필요 목록]

1. `[추후 작성]` 일반 공격과 스킬이 참조하는 실제 범위 패턴·영향 셀 패턴 좌표.
2. `[보류]` 일반 공격과 스킬의 직접 지정 대상 사이에 다른 캐릭터·환경 요소·장애물이 있을 때 사선을 차단하는지 여부.
3. `[확정]` 현재 시간대와 캐릭터 시간대 태그가 일치할 때 궁극기로 교체되는 판정은 시간대 전환 즉시 다시 산출한다. UI 연출 세부는 애니메이션·이펙트·연출 콘텐츠에서 작성한다.
4. `[개발팀 결정]` 캐릭터 이름을 캐릭터 원본 데이터의 필수값으로 관리할지 별도 콘텐츠·로컬라이징 데이터에서 관리할지 여부.
5. `[추후 확장]` 반격 외 자가 버프 효과의 종류·중첩·해제 규칙.

## 유의사항

- 이 문서는 캐릭터의 원본 정보, 시간대 태그, 기본·유효 파라미터, 상태이상 면역 데이터, 일반 공격 정의, 일반 스킬·궁극기 정의와 변수 소유권을 다룬다.
- 상태이상 적용·유지·해제·중첩, 면역의 실제 판정, 반격 상태와 반응 공격, 밀치기·당기기 실행, 강제 이동, 전투 불능, 공격·스킬 실행 재검증, 실패·취소, 효과 큐와 최종 피해·회복 반영은 전투 시스템 범위로 둔다.
- 캐릭터 시스템은 전투 시스템이 판정에 사용할 원본값·참조 ID·보정 전후의 유효값을 제공하지만 전투 FSM과 행동 결과를 직접 결정하지 않는다.
- 시간대·파편·전환 비용·시간대 버프는 [시간대 전환 시스템 기획서](Waredo_2.0_시간대_전환_시스템_기획서.md)를 원본으로 사용하고, 이전 제안 GDD는 적용 기준으로 사용하지 않는다.
- `currentHp`는 게임 최초 시작 시 `effectiveMaxHp`로 초기화한다. 이후에는 스테이지 종료 시 저장하고 다음 스테이지 시작 시 그대로 불러오는 지속 상태값이며, 일반적인 스테이지 시작을 이유로 다시 회복하거나 초기화하지 않는다.
- 제안 GDD의 캐릭터 공격력 소유 규칙은 적용하지 않는다. 사용자 결정에 따라 일반 공격 피해 원본은 일반 공격 정의의 `normalAttackDamage`가 소유한다.
- 기존 프로토타입의 `공격력` 유물 효과는 개편안에 이전하지 않고 제거한다. `flatDamageBonus`는 그 유물과 무관하게 다른 유효 보정 출처가 필요할 때만 사용한다.
- 캐릭터 위치의 단일 원본은 전투판 시스템의 `cellOccupants`로 둔다. 캐릭터별 `occupiedCell`은 이 데이터에서 조회하는 파생값이며 별도로 저장하지 않는다.
- 상태이상 인스턴스 목록인 `activeStatusEffects`는 전투 상태이상 시스템이 소유한다. 캐릭터 시스템은 면역 원본인 `statusImmunityTags`만 제공한다.
- 유물과 시간대 시스템은 캐릭터 원본값을 직접 덮어쓰지 않고 보정값 또는 별도 전투 보정 계층을 제공한다.
- 일반 공격·스킬의 방향, 자기 기준 범위, 상대 방향·거리가 실행 시점에도 유효한지 확인하는 절차와 취소 결과는 전투 시스템에서 정의한다.
- `[확인 필요 목록]`의 항목이 확정되기 전에는 관련 수치·범위·예외를 임의로 추가하지 않는다.

# 1. 기획의도

캐릭터마다 체력, 이동력, 시간대 태그, 일반 공격과 일반 스킬·궁극기의 차이를 부여하여 플레이어가 행동 순서·이동 경로·공격 방식을 서로 다르게 설계하도록 한다. 일반 공격별 `normalAttackDamage`, 공격 범위, 스킬 효과와 시간대에 따른 스킬 교체는 위치 계산 중심의 전투와 시간대 선택에 필요한 판단 근거를 제공한다.

# 2. 개발 목적

- 캐릭터 원본 데이터와 전투 중 변경되는 상태값을 구분하여 콘텐츠 수정과 전투 계산의 기준을 일관되게 유지한다.
- 일반 공격과 스킬을 ID·타겟팅 유형·범위 패턴·효과 데이터로 정의하여 캐릭터 콘텐츠를 같은 규칙으로 제작할 수 있게 한다.
- 유물과 시간대 보정이 원본 파라미터를 직접 변경하지 않도록 기본값과 유효값을 분리한다.
- 캐릭터·전투·전투판·유물·시간대·UI 시스템 사이의 변수 소유권과 조회·변경 요청 관계를 명확히 한다.
- 전투 시스템이 캐릭터 데이터를 이용해 치명타, 이동 가능 거리, 면역, 시간대별 활성 스킬과 스킬 사용 가능 여부를 동일한 기준으로 판정할 수 있게 한다.

## 2.1 시스템 개요: 어떤 시스템인가

캐릭터 시스템은 전투에 참여하는 캐릭터가 어떤 시간대 태그와 파라미터를 가지며, 어떤 일반 공격과 일반 스킬·궁극기를 사용할 수 있는지를 정의하는 시스템이다. 플레이어가 행동 설계 단계에서 캐릭터를 선택하면 전투 시스템은 이 문서의 이동력, 일반 공격 유형, 현재 시간대에 맞는 활성 스킬과 범위 참조를 사용해 선택 가능한 행동 정보를 제공한다. 실제 이동·피해·상태이상·전투 불능 결과는 전투 시스템이 처리하고, 캐릭터 시스템은 그 처리에 필요한 원본 데이터와 유효 파라미터를 제공한다.

## 2.2 사용자가 한 사이클 동안 하는 일

한 사이클은 행동 설계 단계에서 캐릭터 한 명의 행동을 계획하는 과정으로 본다.

1. 플레이어가 행동 슬롯에 배치된 캐릭터를 확인한다.
2. 시스템은 캐릭터의 `effectiveMoveRange`와 현재 전투 상태를 전투 시스템에 제공한다.
3. 플레이어가 이동 경로를 정하면 전투 시스템이 경로 가능 여부를 처리한다.
4. 플레이어는 캐릭터가 보유한 일반 공격 또는 현재 스킬 슬롯에 활성화된 스킬 중 하나를 선택한다.
5. 시스템은 선택한 행동의 타겟팅 유형, 범위 패턴, 영향 셀 패턴, 대상 진영과 쿨타임 정보를 제공한다.
6. 플레이어가 상·하·좌·우 방향, 자기 기준 범위 확정, 타일의 상대 방향·거리 또는 자기 자신 중 해당 유형에 필요한 입력을 지정한다.
7. 전투 시스템이 계획을 저장·검증·잠그며, 실행 단계에서 실제 위치와 상태를 기준으로 다시 판정한다.
8. 실행 결과로 현재 체력·쿨타임·상태이상 목록 등이 변경되면 각 변수의 소유 모듈이 결과를 갱신한다.

플레이어의 세부 클릭·드래그·터치 조작과 표시 우선순위는 UI 시스템 범위다.

## 2.3 핵심 작동 방식

캐릭터 콘텐츠에는 변경되지 않는 원본 파라미터와 일반 공격·스킬 참조를 저장한다. 전투에서는 유물과 현재 시간대의 보정을 원본과 분리하여 유효 파라미터를 산출한다. 전투 시스템은 유효값을 이용해 이동 가능 거리와 공격 결과를 판정한다.

일반 공격과 스킬은 타겟팅 유형에 따라 방향, 자기 기준 범위 또는 상대 방향·거리를 입력받고, 자가 버프형 스킬은 자기 자신을 확정한다. 타일 선택형의 실제 목표 셀은 실행 시점의 시전자 위치에 저장된 상대 방향·거리를 다시 적용해 산출하므로 시전자가 이동하면 목표 셀도 같은 만큼 이동한다. 계획 단계의 선택 결과는 실행 결과를 보장하지 않는다. 실제 실행 시점의 위치·대상·상태에 대한 재검증과 실패·취소 처리는 전투 시스템이 맡는다.

상태이상 면역은 캐릭터가 보유하는 태그 데이터다. 캐릭터 시스템은 면역 태그 목록을 제공하고, 상태이상 적용 요청을 받은 전투 시스템이 대응 태그를 조회하여 적용 여부를 결정한다.

## 2.4 실제 처리 예시

방향성 일반 공격을 보유한 캐릭터가 행동을 계획하는 경우의 예시다.

1. 캐릭터 정의에서 `characterNormalAttackId`를 조회한 뒤 대응 일반 공격 정의의 `normalAttackDamage`를 조회한다.
2. 일반 공격 정의에서 타겟팅 유형이 `Directional`인지 확인한다.
3. 플레이어는 상·하·좌·우 중 하나를 선택한다.
4. 일반 공격 정의는 캐릭터 기준 위쪽 방향으로 작성된 범위 패턴과 영향 셀 패턴을 전투 시스템에 제공한다.
5. 전투 시스템은 계획을 저장하고, 행동 실행 시 실제 이동 완료 위치를 기준으로 패턴을 선택 방향에 맞춰 회전한 뒤 현재 셀 점유를 판정한다.
6. 유효 대상에게 피해가 발생하면 일반 공격 정의의 `normalAttackDamage`를 `baseDamage`로 사용한다.
7. 시간대 보정, `Airborne`·`Stun` 대상 치명타, 기타 주는 피해 보정과 반올림은 전투 시스템이 정해진 피해 계산 순서로 처리한다. 시간대 태그에 따른 상성 배율은 적용하지 않는다.

실제 범위 패턴 좌표와 캐릭터별 공격 수치는 제공되지 않았으므로 예시에 임의 수치를 사용하지 않는다.

## 2.5 시스템이 직접 정의하는 것

캐릭터 시스템이 직접 정의하고 소유하는 항목은 다음과 같다.

- 캐릭터 ID, 캐릭터 분류, 시간대 태그, 기본 파라미터, 일반 공격 참조, 일반 스킬·궁극기 참조와 상태이상 면역 태그
- 기본 파라미터와 유물 보정으로 산출하는 유효 파라미터의 계산 규칙
- 일반 공격의 ID, 이름, 타겟팅 유형, 범위·영향 패턴 참조, 대상 진영과 피격 대상 규칙
- 스킬의 ID, 이름, 설명, 타겟팅 유형, 범위·영향 패턴 참조, 효과 목록과 최대 쿨타임
- 캐릭터 관련 변수의 단일 원본, 상태, 파생값과 외부 참조의 경계

전투 시스템은 상태이상·면역·전투 불능·공격·스킬을 실제로 판정하고 실행한다. 전투판 시스템은 셀 점유 원본을, 이동 시스템은 위치 변경 요청을, 유물 시스템은 유물 장착 상태와 보정 데이터를, 시간대 시스템은 현재 시간대와 시간대 보정을 소유한다.

# 4. 시스템 상세 구조

## 4-1. 캐릭터 시스템

### 4-1-1. 캐릭터 정의 모듈

**사용 변수·용어**

| 변수·용어 | 이 모듈에서의 의미 | 값 형태 | 소유·성격 |

| `criticalDamageRatePercent` | 치명타 성립 시 사용하는 기본 피해율 | 비율 | 캐릭터 정의·원본 |
| `characterNormalAttackId` | 캐릭터가 보유한 일반 공격 정의 참조 | ID | 캐릭터 정의·원본 |
| `characterSkillId` | 캐릭터가 보유한 일반 스킬 정의 참조 | ID | 캐릭터 정의·원본 |

| `statusImmunityTags` | 캐릭터가 적용을 거부하는 상태 태그 목록 | 목록 | 캐릭터 정의·원본 |

#### 4-1-1-1. 목적과 책임

캐릭터 콘텐츠의 단일 원본을 관리하고 다른 모듈이 캐릭터를 같은 ID와 시간대 태그로 조회할 수 있게 한다.

#### 4-1-1-2. 입력·처리·출력

- 입력: 캐릭터 ID, 캐릭터 분류, 시간대 태그, 기본 파라미터, 일반 공격 ID, 일반 스킬 ID, 궁극기 ID, 상태이상 면역 태그 목록
- 처리: ID 중복, 허용 시간대 태그, 파라미터 범위, 스킬 쌍과 필수 참조 존재 여부를 검증한다.
- 출력: 검증된 캐릭터 정의와 일반 공격·일반 스킬·궁극기 참조를 제공한다.
- 소유 데이터: `characterId`, `characterCategory`, `timeTag`, `maxHp`, `moveRange`, `criticalDamageRatePercent`, `characterNormalAttackId`, `characterSkillId`, `characterUltimateSkillId`, `statusImmunityTags`
- 참조 데이터: 일반 공격 정의, 스킬 정의, 현재 시간대
- 실패·예외: 필수값 누락, ID 중복, 허용 범위 위반 또는 존재하지 않는 참조 ID가 있으면 콘텐츠 등록을 거부한다.

#### 4-1-1-3. 캐릭터 원본 규칙

- `characterId`는 캐릭터 정의를 식별하며 중복될 수 없다.
- `characterCategory`는 `NormalEnemy`, `BossEnemy`, `Ally` 중 하나를 사용한다.
- `NormalEnemy`와 `BossEnemy`는 대상 진영 판정에서 적군으로, `Ally`는 아군으로 처리한다.
- 일반 적과 보스 적의 세부 전투 규칙 차이는 전투·보스 시스템이 `characterCategory`를 조회하여 처리한다.
- 아군의 `timeTag`는 `Past` 또는 `Future` 중 하나를 사용한다. 표시명은 각각 `과거`, `미래`다.
- 프로토타입 기준으로 적군의 `timeTag`는 `None`이며 궁극기 교체 대상이 아니다.
- 시간대 태그는 궁극기 활성 조건으로만 사용하며 공격자·피격자 사이의 유리·중립·불리 관계나 피해 배율을 만들지 않는다.
- `maxHp`는 1 이상의 정수다.
- `moveRange`는 0 이상의 정수다.
- `moveRange`는 상·하·좌·우 이동 거리를 의미하며 대각선 거리를 포함하지 않는다.
- `criticalDamageRatePercent`는 0 이상의 백분율 정수이며 `100`은 일반 피해와 같은 배율이다. 모든 캐릭터의 공통 초기값은 임시로 `120`을 사용한다.
- 캐릭터별 최대 체력·이동력·일반 공격·스킬·면역을 포함한 실제 콘텐츠 값은 캐릭터 콘텐츠 테이블에서 작성하고 관리한다.
- 아군 캐릭터는 일반 공격 정의 ID 하나와 일반 스킬·궁극기 정의 ID를 각각 하나씩 참조한다. 따라서 아군 캐릭터가 보유하는 스킬 정의는 총 2개다.
- 적 캐릭터는 일반 스킬 ID 하나를 참조하며 궁극기 ID는 `None`으로 둔다.
- 일반 스킬과 궁극기는 하나의 스킬 슬롯과 하나의 `cooldownRemaining` 상태를 공유한다.
- 면역이 없는 캐릭터는 빈 면역 목록 또는 콘텐츠 문법의 `NONE`으로 작성한다.

### 4-1-2. 파라미터 모듈

#### 4-1-2-1. 목적과 책임

캐릭터 기본 파라미터를 보존하고 유물·시간대·전투 보정을 원본과 분리하여 전투가 사용할 유효값을 제공한다.

#### 4-1-2-2. 기본 파라미터 정의

**체력:**

- `maxHp`는 캐릭터 콘텐츠에 저장하는 최대 체력의 원본값이다.
- `flatMaxHpBonus`는 `maxHp`에 직접 더하는 정수형 보정이고, `maxHpRateBonus`는 정수형 보정 합산 이후 적용하는 비율형 보정이다.
- `effectiveMaxHp`는 다음 계산식으로 산출하는 파생값이다.

```text
effectiveMaxHp = max(
    1,
    반올림(
        (maxHp + ΣflatMaxHpBonus)
        × max(0, 1 + ΣmaxHpRateBonus)
    )
)
```

- 모든 `flatMaxHpBonus`를 먼저 합산한 뒤 모든 `maxHpRateBonus`를 합산하여 배율로 변환한다.
- `maxHpRateBonus`의 합산 배율은 0 미만으로 내려가지 않는다.
- 중간 계산에서는 소수점을 유지하고 최종 결과를 한 번만 반올림한 뒤 `effectiveMaxHp`를 1 이상으로 제한한다.
- `currentHp`는 전투 중 실제로 남아 있는 체력 상태값이며 스테이지가 종료되어도 저장한다.
- 게임 최초 시작 시 `currentHp`는 `effectiveMaxHp`와 같은 값으로 초기화하여 최대 체력 상태로 시작한다.
- 다음 스테이지 시작 시 저장된 `currentHp`를 그대로 불러오며 `effectiveMaxHp`로 초기화하지 않는다.
- 스테이지 사이의 체력 회복은 별도의 회복 효과나 명시된 회복 규칙이 있을 때만 `currentHp`에 반영한다.
- 유물 효과로 생존 캐릭터의 `effectiveMaxHp`가 증가하면 증가량만큼 `currentHp`도 함께 증가한다. `maxHpDelta = newEffectiveMaxHp - oldEffectiveMaxHp`가 양수이면 `currentHp = min(newEffectiveMaxHp, currentHp + maxHpDelta)`로 정리한다. `currentHp <= 0`인 전투불능 캐릭터는 유물 효과 대상에서 제외한다.
- 유물 외 원인으로 `effectiveMaxHp`가 증가할 때의 `currentHp` 처리는 해당 보정 제공 시스템의 명시된 규칙을 따르며, 별도 규칙이 없으면 기존 `currentHp`를 유지한다.
- `effectiveMaxHp`가 감소하면 기존 `currentHp`가 새 `effectiveMaxHp`를 초과하는 부분만 절삭한다. 감소량만큼 현재 체력을 강제로 빼지 않는다.
- 최대 체력 증감에 따른 `currentHp` 조정은 별도의 피해 또는 회복 효과로 취급하지 않는다.
- `currentHp`의 허용 범위는 `0~effectiveMaxHp`다.
- 피해·회복에 따른 `currentHp` 변경과 체력 0 이하의 전투 불능 판정은 전투 시스템이 처리한다.

**공격력:**

- 캐릭터는 공통 공격력 원본을 소유하지 않는다.
- 일반 공격의 공격력 원본은 해당 일반 공격 정의가 소유하는 `normalAttackDamage`다.
- 스킬의 공격력 원본은 해당 스킬의 개별 `Damage` 효과가 소유하는 `damageEffectValue`다.
- `baseDamage`는 현재 실행 중인 일반 공격 또는 스킬에서 공격력 원본을 선택해 사용하는 비저장 파생 입력이다.
- `flatDamageBonus`는 하나의 유물·시간대·전투 효과가 `baseDamage`에 직접 더하는 개별 상수형 피해 보정값이다.
- 피해 3 증가 유물과 피해 4 증가 유물이 함께 적용되면 두 유물이 각각 `flatDamageBonus = 3`, `flatDamageBonus = 4`를 제공하며 `ΣflatDamageBonus`는 7이다.
- 각 보정값은 동일한 `flatDamageBonus` 변수명을 사용하고, 제공 출처별 개별 값으로 보관한다.
- `dealtDamageRateBonus`는 공격자가 주는 피해에 적용되는 비율형 보정이며, 적용 가능한 값을 모두 합산한 뒤 배율로 변환한다.
- 최종 공격 피해는 적용 가능한 피해 보정과 치명타를 반영하여 `finalDamage`로 산출한다. 시간대 태그에 따른 상성 배율은 없다.

**치명타 피해율:**

- `criticalDamageRatePercent`는 치명타가 성립했을 때 적용할 기본 피해율 원본이다.
- 모든 캐릭터의 `criticalDamageRatePercent` 초기값은 임시로 `120`을 사용한다.
- `criticalDamageRateBonus`는 유물·시간대·전투 조건이 제공하는 치명타 피해율 보정값이다.
- `effectiveCriticalDamageRatePercent`는 `criticalDamageRatePercent + ΣcriticalDamageRateBonus`로 산출하는 파생값이며 0 이상으로 제한한다.
- `isCritical = false`인 피해에는 `effectiveCriticalDamageRatePercent`를 적용하지 않고 배율 1을 사용한다.
- `isCritical = true`인 피해에만 `effectiveCriticalDamageRatePercent ÷ 100`을 피해 배율로 적용한다.

**이동력:**

- `moveRange`는 캐릭터 콘텐츠에 저장하는 한 행동당 기본 이동 가능 셀 거리다.
- 이동력은 고정형 보정만 허용하며 비율형 보정은 사용하지 않는다.
- `flatMoveRangeBonus`는 `moveRange`에 직접 더하는 개별 고정형 이동력 보정이다.
- `effectiveMoveRange`는 다음 계산식으로 산출하는 파생값이다.

```text
effectiveMoveRange = max(
    0,
    moveRange + ΣflatMoveRangeBonus
)
```

- `effectiveMoveRange`는 0 이상으로 제한하며 상·하·좌·우 이동 거리를 의미한다.
- 실제 이동 가능 셀은 `effectiveMoveRange`만으로 확정하지 않는다. 전투판의 점유, 이동 불가 셀과 경로 규칙을 전투·이동 시스템이 함께 판정한다.

**스킬 쿨타임:**

- `cooldownMax`는 스킬 정의가 소유하는 최대 쿨타임 원본값이다.
- 스킬 최대 쿨타임은 고정형 보정만 허용하며 비율형 보정은 사용하지 않는다.
- `flatCooldownMaxBonus`는 `cooldownMax`에 직접 더하는 개별 고정형 최대 쿨타임 보정이다.
- `effectiveCooldownMax`는 다음 계산식으로 산출하는 파생값이다.

```text
effectiveCooldownMax = max(
    1,
    cooldownMax + ΣflatCooldownMaxBonus
)
```

- `effectiveCooldownMax`에는 별도의 최댓값을 두지 않고 최소값 `1`만 적용한다.

- `cooldownRemaining`은 전투 중 남은 쿨타임 상태값이며 `0~effectiveCooldownMax` 범위로 제한한다.

#### 4-1-2-3. 유효값 공통 산출 규칙

파라미터 보정은 각 변수에 허용된 보정 종류만 사용하며 다음 순서로 계산한다.

```text
기본값
→ 허용된 모든 고정형 보정 합산
→ 해당 파라미터가 비율형 보정을 허용하는 경우에만 비율형 보정 합산 적용
→ 최종 반올림
→ 변수별 허용 범위 제한
= 유효값
```

- `effectiveMaxHp`는 1 이상으로 제한한다.
- `effectiveMoveRange`, `effectiveCriticalDamageRatePercent`는 0 이상으로 제한한다.
- `effectiveMoveRange`는 `moveRange + ΣflatMoveRangeBonus`로 산출하며 비율형 보정을 적용하지 않는다.
- `effectiveCriticalDamageRatePercent`는 `criticalDamageRatePercent + ΣcriticalDamageRateBonus`로 산출한다.
- `effectiveCooldownMax`는 1 이상으로 제한한다.
- `effectiveCooldownMax`는 `cooldownMax + ΣflatCooldownMaxBonus`로 산출하며 비율형 보정을 적용하지 않는다.
- `cooldownRemaining`은 `0~effectiveCooldownMax` 범위로 제한한다.
- 모든 수치 계산은 전체 계산을 완료한 최종 단계에서 한 번만 반올림한다.
- 시간대·치명타·회복 보정의 실제 적용은 전투 시스템에서 처리한다.

#### 4-1-2-4. 피해 계산 연결 규칙

일반 공격 정의 모듈은 `normalAttackDamage`, 스킬 정의 모듈은 `damageEffectValue`, 파라미터 모듈은 `effectiveCriticalDamageRatePercent`를 제공한다. 전투 시스템은 다음 순서로 `finalDamage`를 처리한다.

```text
최종 피해 = max(
    0,
    반올림(
        (baseDamage + ΣflatDamageBonus)
        × max(0, 1 + ΣdealtDamageRateBonus)
        × (isCritical이면 effectiveCriticalDamageRatePercent ÷ 100, 아니면 1)
    )
)
```

- 일반 공격의 `baseDamage`는 `normalAttackDamage`다.
- 스킬의 `baseDamage`는 해당 `Damage` 효과의 `damageEffectValue`다.
- 비율형 보정은 같은 계층의 값을 먼저 모두 합산한 뒤 하나의 배율로 변환한다.
- 비율형 보정의 합산 결과로 계산된 배율은 음수가 될 수 없으며 `0` 미만으로 내려가지 않는다.
- 미래 시간대에는 시간대 시스템이 아군 일반 공격에만 `flatDamageBonus = 3`을 제공하고, 피해 계산은 다른 적용 가능한 상수형 보정과 함께 합산한다. 스킬과 기타 피해에는 이 보정을 적용하지 않는다.
- 시간대 시스템은 치명타 피해율 보정을 제공하지 않는다.
- `isCritical`은 피해 적용 직전 대상의 상태를 사용해 전투 시스템이 판정하며 캐릭터 시스템에는 저장하지 않는다.
- 대상의 `activeStatusEffects`에 `Airborne` 또는 `Stun`이 있으면 일반 공격·스킬·기타 피해 구분과 관계없이 `isCritical = true`로 처리한다.
- 상태 기반 치명타에는 스킬별 치명타 허용값을 두지 않는다.
- `timeTag`는 캐릭터 시스템이 소유하는 `Past` 또는 `Future` 값이다. 시간대 전환 시스템이 제공하는 현재 시간대와 비교하여 일반 스킬과 궁극기를 교체하는 조건이며, 자체 피해 배율이나 상성을 제공하지 않는다.
- 중간 계산에서는 소수점을 유지하고 모든 피해 보정과 치명타를 적용한 최종 결과를 한 번만 반올림한다.
- 반올림한 최종 피해는 `0` 이상으로 제한한다.

### 4-1-3. 시간대 태그·스킬 교체 모듈

**사용 변수·용어**

| 변수·용어 | 이 모듈에서의 의미 | 값 형태 | 소유·성격 |
|---|---|---|---|
| `timeTag` | 아군에 지정된 시간대 태그 | `Past` 또는 `Future` | 캐릭터 정의·원본 |
| `currentTimePeriod` | 현재 전투가 위치한 시간대 | `Past`, `Present`, `Future` | 시간대 전환 시스템 참조 |
| `characterSkillId` | 평상시에 사용하는 일반 스킬 ID | ID | 캐릭터 정의·원본 |
| `characterUltimateSkillId` | 태그 일치 시간대에 사용하는 궁극기 ID | ID | 캐릭터 정의·원본 |
| `activeSkillId` | 현재 스킬 슬롯에 활성화된 정의 ID | ID | 비교 결과·파생 |
| `cooldownRemaining` | 일반 스킬과 궁극기가 공유하는 남은 쿨타임 | 정수 | 전투 스킬 쿨타임 모듈·상태 참조 |

#### 4-1-3-1. 목적과 책임

현재 시간대와 캐릭터의 시간대 태그를 비교해 스킬 슬롯에 사용할 일반 스킬 또는 궁극기를 결정한다.

#### 4-1-3-2. 시간대 태그와 스킬 교체 규칙

- `currentTimePeriod = timeTag`이면 `activeSkillId = characterUltimateSkillId`다.
- 현재가 캐릭터의 태그와 일치하지 않으면 `activeSkillId = characterSkillId`다. `Present`와 일치하는 캐릭터 태그는 없다.
- 시간대가 바뀌면 계획·실행 화면에서 참조할 `activeSkillId`를 즉시 다시 산출한다.
- 일반 스킬과 궁극기는 같은 스킬 슬롯과 `cooldownRemaining`을 공유한다.
- 일반 스킬이 쿨타임 중인 상태에서 궁극기로 교체되거나 궁극기가 일반 스킬로 돌아가도 `cooldownRemaining`은 그대로 유지한다. 시간대 전환 자체는 쿨타임을 초기화·증가·감소시키지 않는다.
- 한 쌍의 일반 스킬과 궁극기는 동일한 `cooldownMax`를 사용한다. 두 정의의 값이 다르면 콘텐츠 검증에 실패한다.
- 시간대 태그에는 상성이 없으며 태그 비교만으로 피해 배율을 변경하지 않는다.

### 4-1-4. 면역 데이터 모듈

**사용 변수·용어**

| 변수·용어 | 이 모듈에서의 의미 | 값 형태 | 소유·성격 |
|---|---|---|---|
| `statusImmunityTags` | 캐릭터가 적용을 거부하는 상태 태그 목록 | 목록 | 캐릭터 정의·원본 참조 |
| `statusTag` | 상태이상과 면역을 대응시키는 식별 태그 | 열거값 | 전투 상태이상 정의 참조 |

#### 4-1-4-1. 목적과 책임

캐릭터가 상태이상 적용을 거부할 수 있도록 캐릭터별 면역 태그 목록을 제공한다.

#### 4-1-4-2. 면역 데이터 규칙

- 캐릭터는 0개 이상의 상태이상 면역 태그를 가질 수 있다.
- GDD가 현재 사용하는 면역 대상 상태는 밀치기, 당기기, 띄워짐과 기절이다.
- 면역 데이터는 캐릭터 원본에 저장한다.
- 면역 태그와 상태이상 태그의 일치 여부, 해당 효과만 실패시키는 규칙과 이후 효과 처리는 전투 시스템이 담당한다.
- 면역이 발생해도 다른 상태이상·대상·셀로 자동 변경하지 않는 실행 규칙은 전투 시스템에 둔다.

### 4-1-5. 일반 공격 정의 모듈

**사용 변수·용어**

| 변수·용어 | 이 모듈에서의 의미 | 값 형태 | 소유·성격 |
|---|---|---|---|
| `normalAttackId` | 일반 공격 정의 식별값 | ID | 일반 공격 정의·원본 |
| `normalAttackTargetingType` | 방향성·자기 기준·타일 선택 중 일반 공격의 입력 방식 | 열거값 | 일반 공격 정의·원본 |
| `normalAttackRangePatternId` | 공격 가능한 셀 범위 패턴 참조 | ID | 일반 공격 정의·원본 |
| `normalAttackAffectedCellPatternId` | 실제 피해 대상을 찾는 영향 셀 패턴 참조 | ID | 일반 공격 정의·원본 |
| `normalAttackValidTargetTeam` | 선택·피격을 허용하는 대상 진영 | 열거값 | 일반 공격 정의·원본 |
| `normalAttackDamage` | 일반 공격이 소유하는 보정 전 기본 피해값 | 수치 | 일반 공격 정의·원본 |
| `targetDirection` | 방향성 일반 공격 계획에서 받은 상·하·좌·우 방향 | 방향 | 전투 시스템 > 행동 모듈 소유·참조 |
| `relativeTargetOffset` | 타일 선택형 계획에서 받은 시전자 기준 상대 방향·거리 | 상대 변위 `(Δx, Δy)` | 전투 시스템 > 행동 모듈 소유·참조 |

#### 4-1-5-1. 목적과 책임

캐릭터가 보유한 일반 공격의 타겟 선택 방식, 범위와 실제 피격 대상 판정에 필요한 원본 데이터를 제공한다.

#### 4-1-5-2. 일반 공격 유형

| 유형 | 플레이어 입력 | 정의 규칙 |
|---|---|---|
| `Directional` | 상·하·좌·우 방향 선택 | 계획 단계에서 `targetDirection`을 저장한다. 이동을 마친 예정 도착 셀에서 저장한 방향을 바라보고, 위쪽 기준 패턴을 해당 방향에 맞춰 회전하여 공격한다. |
| `SelfCentered` | 자기 기준 범위 확정 | 별도 대상 좌표를 저장하지 않는다. 실행 시점의 캐릭터 현재 셀을 중심으로 고정 범위를 펼쳐 범위 안의 유효 대상에게 피해를 준다. |
| `TileSelect` | 타일 1개 선택 | 계획된 이동 도착 셀에서 선택 타일까지의 `relativeTargetOffset`만 저장한다. 이동 계획이 없으면 현재 셀을 계획 원점으로 사용한다. 실행 시점의 시전자 현재 셀에 이 상대 방향·거리를 더해 실제 목표 셀을 다시 산출한다. |

#### 4-1-5-3. 일반 공격 정의 규칙

- 일반 공격 ID는 중복될 수 없다.
- 일반 공격 정의는 `normalAttackDamage`를 직접 소유하며 캐릭터 정의에는 일반 공격 피해값을 저장하지 않는다.
- `Directional`은 계획 단계에서 `targetDirection`을 저장하고, 이동을 마친 행동 캐릭터의 예정 도착 셀을 패턴 원점으로 사용한다.
- `Directional`의 `normalAttackRangePatternId`와 `normalAttackAffectedCellPatternId`는 캐릭터 기준 위쪽 방향을 바라보는 형태로 작성한다. 전투 시스템은 이 원본 패턴을 상·하·좌·우 각 방향에 맞춰 회전하여 사용한다.
- 회전된 서로 다른 방향 패턴에 같은 셀이 포함되면 해당 셀을 어느 한 방향에서 제외하지 않는다. 겹친 셀은 두 방향의 범위에 모두 포함된다.
- `SelfCentered`는 실행 시점 캐릭터의 실제 위치를 원점으로 `normalAttackAffectedCellPatternId`를 펼친다. 별도 대상 캐릭터·타일·방향은 저장하지 않는다.
- `TileSelect`는 계획 당시의 절대 셀 좌표를 저장하지 않는다. 계획된 이동 도착 셀을 원점으로 사용하고, 이동 계획이 없으면 현재 셀을 원점으로 사용한다. 이 원점에서 선택 타일까지의 상대 변위인 `relativeTargetOffset = (targetX - originX, targetY - originY)`만 저장한다.
- `TileSelect`의 실행 목표 셀은 `실행 시점 시전자 셀 + relativeTargetOffset`으로 산출한다. 시전자가 계획 이후 이동하거나 이동이 중단되어 위치가 달라지면 목표 셀도 같은 방향·거리 관계를 유지한 채 함께 이동한다.
- `TileSelect`의 실행 목표 셀이 전투판 밖이거나 실행 범위를 벗어나면 공격에 실패한다. 다른 셀로 자동 보정하거나 재타겟팅하지 않는다.
- 세 유형 모두 영향 셀 안의 유효 캐릭터를 실제 피격 대상으로 사용하고 `normalAttackAffectedCellPatternId`를 반드시 참조한다.
- `normalAttackValidTargetTeam`에 포함되지 않은 캐릭터는 실제 피격 대상으로 판정하지 않는다.

#### 4-1-6-1. 목적과 책임

캐릭터가 보유한 스킬의 타겟팅, 범위, 효과 목록과 쿨타임을 정의한다. 상태이상으로 발생하는 치명타 여부는 스킬 정의가 아니라 전투 시스템이 판정한다.

#### 4-1-6-2. 스킬 유형

| 유형 | 플레이어 입력 | 정의 규칙 |
|---|---|---|
| `Directional` | 상·하·좌·우 방향 선택 | 계획 단계에서 `targetDirection`을 저장한다. 이동을 마친 예정 도착 셀에서 저장한 방향을 바라보고, 위쪽 기준 패턴을 해당 방향에 맞춰 회전하여 효과 범위를 산출한다. |
| `SelfCentered` | 자기 기준 범위 확정 | 별도 대상 좌표를 저장하지 않는다. 실행 시점의 캐릭터 현재 셀을 중심으로 고정 범위를 펼쳐 범위 안의 유효 대상에게 피해와 부가 효과를 적용한다. |
| `TileSelect` | 타일 선택 | 계획된 이동 도착 셀에서 선택 타일까지의 `relativeTargetOffset`만 저장한다. 이동 계획이 없으면 현재 셀을 계획 원점으로 사용한다. 실행 시점의 시전자 현재 셀에 상대 방향·거리를 더해 목표 셀을 다시 산출한다. |
| `SelfBuff` | 시전자 자신을 확정 | 별도 대상 캐릭터·타일·방향을 저장하지 않는다. 실행 시점의 시전자 자신에게 버프 효과를 적용한다. |

#### 4-1-6-3. 스킬 타겟팅 규칙

- `Directional`은 계획 단계에서 `targetDirection`을 저장하고, 이동을 마친 행동 캐릭터의 예정 도착 셀을 패턴 원점으로 사용한다.
- `Directional`의 `skillRangePatternId`와 `skillAffectedCellPatternId`는 캐릭터 기준 위쪽 방향을 바라보는 형태로 작성한다. 전투 시스템은 이 원본 패턴을 상·하·좌·우 각 방향에 맞춰 회전하여 사용한다.
- 회전된 서로 다른 방향 패턴에 같은 셀이 포함되면 해당 셀을 어느 한 방향에서 제외하지 않는다. 겹친 셀은 두 방향의 범위에 모두 포함된다.
- `SelfCentered`는 실행 시점 캐릭터의 실제 위치를 원점으로 `skillAffectedCellPatternId`를 펼치며 별도 대상 정보를 저장하지 않는다.
- `TileSelect`는 계획된 이동 도착 셀을 원점으로 `relativeTargetOffset`을 계산하며, 이동 계획이 없으면 현재 셀을 원점으로 사용한다. 절대 셀 좌표는 저장하지 않는다. 실행 목표 셀은 `실행 시점 시전자 셀 + relativeTargetOffset`으로 다시 계산한다.
- `TileSelect`의 실행 목표 셀이 전투판 밖이거나 실행 범위를 벗어나면 스킬 행동을 취소하며 다른 셀로 자동 보정하거나 재타겟팅하지 않는다.
- `SelfBuff`는 시전자 자신을 적용 대상으로 사용하고 타겟 데이터를 저장하지 않는다. 계획 단계의 자기 자신 재선택 또는 UI의 행동 확정 입력은 같은 확정 결과로 처리한다.
- `SelfBuff`는 `skillAffectedCellPatternId = None`을 허용하며, 효과 범위가 필요한 반응형 버프는 별도의 범위 패턴 ID를 효과 데이터로 참조할 수 있다.

#### 4-1-6-4. 스킬 효과 정의

- 스킬은 하나 이상의 효과를 가진다.
- 효과는 콘텐츠에 작성된 순서대로 전투 시스템의 효과 큐에 등록된다.
- 허용 효과는 `Damage`, `Push`, `Pull`, `Airborne`, `Stun`, `Counter`다.
- 각 캐릭터 대상 효과는 `Enemy`, `Ally`, `All` 중 유효 대상 진영을 가진다.
- `Damage`는 `damageEffectValue`를 가진다.
- `SelfCentered` 스킬은 자기 기준 범위에 피해를 주기 위해 `Damage` 효과를 하나 이상 포함한다.
- `Push`·`Pull`은 이동 거리 N을 가지며 `Directional` 스킬에서 사용한다.
- `Airborne`·`Stun`은 상태이상 정의 ID를 참조한다.
- `Counter`는 `SelfBuff` 스킬에서만 사용하며 시전자 자신에게 반격 상태를 적용한다. 반격 범위·발동·중복 방지·피해·중단 규칙은 전투 시스템의 반격 모듈이 소유한다.
- 효과의 실제 성공·실패, 면역, 강제 이동, 중단과 전투 불능 처리는 전투 시스템이 담당한다.

#### 4-1-6-5. 쿨타임 정의

- `cooldownMax`는 1 이상이다.
- 한 캐릭터의 일반 스킬과 궁극기는 동일한 `cooldownMax`를 사용한다.
- `effectiveCooldownMax`는 최소값 `1`만 적용하며 별도의 최댓값은 두지 않는다.
- 전투 시작 시 `cooldownRemaining`은 0이다.
- 일반 스킬과 궁극기는 하나의 `cooldownRemaining`을 공유한다.
- 활성 스킬 사용 시 공유 `cooldownRemaining`을 `effectiveCooldownMax`로 설정한다.
- 스킬을 사용한 같은 턴에는 감소하지 않고 다음 `TurnSetup`부터 1씩 감소한다.
- 시간대 진입·이탈로 일반 스킬과 궁극기가 교체되어도 `cooldownRemaining`은 그대로 유지한다.
- 저장한 방향 또는 상대 방향·거리로 산출한 목표 셀이 실행 범위를 벗어나 스킬이 실패하면 사용으로 처리하지 않는다. 이 경우 `cooldownRemaining`을 `effectiveCooldownMax`로 설정하지 않고 기존 값을 유지한다.
- 범위 검증에 성공해 스킬 사용을 시작하면 `cooldownRemaining`을 `effectiveCooldownMax`로 설정한다.

#### 4-1-7-3. 변수 관리 원칙

- 같은 의미의 값을 둘 이상의 시스템에 중복 저장하지 않는다.
- 유물은 캐릭터 기본값을 직접 변경하지 않고 보정값을 제공한다.
- 파생값은 원본·상태·현재 조건으로 다시 계산할 수 있으므로 저장하지 않는다.
- UI·애니메이션·연출 시스템은 원본 전투 변수를 직접 수정하지 않고 조회하거나 변경을 요청한다.
- `occupiedCell`은 `cellOccupants`로부터 얻는 파생값이므로 별도 상태로 저장하거나 함께 갱신하지 않는다.
- 전투 시스템이 소유하는 실행 임시값과 효과 큐를 캐릭터 시스템에 중복 저장하지 않는다.

### 4-1-8. 캐릭터 시스템 처리 순서

```mermaid
flowchart TD
    A([4-1-8-1. 캐릭터 정의 조회 요청]) --> B[4-1-8-2. 캐릭터 원본·참조 ID 검증]
    B --> C{4-1-8-3. 정의가 유효한가?}
    C -- 아니요 --> D([4-1-8-4. 조회·등록 실패 반환])
    C -- 예 --> E[4-1-8-5. 유물·시간대 보정 조회]
    E --> F[4-1-8-6. 유효 파라미터 산출]
    F --> G[4-1-8-7. 시간대별 활성 스킬·공격·면역 데이터 제공]
    G --> H[4-1-8-8. 전투 시스템이 계획·실행 판정]
    H --> I{4-1-8-9. 상태값 변경 요청이 있는가?}
    I -- 아니요 --> J([4-1-8-10. 조회 사이클 종료])
    I -- 예 --> K[4-1-8-11. 소유 모듈이 상태값 갱신]
    K --> L[4-1-8-12. 갱신 결과 제공]
    L --> J
```

| 번호 | 처리 내용 |
|---|---|
| 4-1-8-1 | 캐릭터 ID를 기준으로 캐릭터 정의 조회를 요청한다. |
| 4-1-8-2 | 캐릭터 원본 파라미터, 시간대 태그, 일반 공격 ID, 일반 스킬·궁극기 ID와 면역 태그를 검증한다. |
| 4-1-8-3 | 필수값·허용 범위·참조 ID가 유효한지 판정한다. |
| 4-1-8-4 | 유효하지 않으면 캐릭터 등록 또는 조회 실패를 반환한다. |
| 4-1-8-5 | 유효하면 현재 적용 가능한 유물 보정과 시간대 보정 계층을 조회한다. |
| 4-1-8-6 | 기본값과 보정값으로 유효 파라미터를 산출한다. |
| 4-1-8-7 | 현재 시간대와 태그를 비교해 활성 스킬을 산출하고 일반 공격 정의, 활성 스킬 정의와 면역 데이터를 전투 시스템에 제공한다. |
| 4-1-8-8 | 전투 시스템이 이동·타겟·효과·피해·상태이상과 실행 결과를 판정한다. |
| 4-1-8-9 | 판정 결과에 현재 체력·쿨타임·상태이상·위치 변경 요청이 있는지 확인한다. |
| 4-1-8-10 | 변경 요청이 없으면 현재 조회 사이클을 종료한다. |
| 4-1-8-11 | 변경 요청이 있으면 해당 데이터의 단일 원본 소유 모듈이 값을 갱신한다. |
| 4-1-8-12 | 변경된 상태와 파생값 재조회 결과를 전투·UI 시스템에 제공한다. |

### 4-1-10. 콘텐츠 기획 문법

아래 문법은 캐릭터 콘텐츠 테이블과 일반 공격·스킬 콘텐츠에 필요한 필드 구성을 나타낸다. 실제 캐릭터별 값은 이 문서 본문에 나열하지 않고 콘텐츠 테이블에서 관리한다.

#### 4-1-10-1. 캐릭터 문법

```text
CHARACTER <캐릭터ID> "<캐릭터명>"
CATEGORY <NORMAL_ENEMY | BOSS_ENEMY | ALLY>
TIME_TAG <PAST | FUTURE | NONE>
MAX_HP <1 이상의 정수>
MOVE_RANGE <0 이상의 정수>
CRITICAL_DAMAGE_RATE_PERCENT <0 이상의 정수>
NORMAL_ATTACK <일반공격ID>
SKILL <일반스킬ID>
ULTIMATE_SKILL <궁극기ID | NONE>
STATUS_IMMUNITY <NONE | 상태태그 목록>
```

`<캐릭터명>`은 기획 문서에서 콘텐츠를 식별하기 위한 표기다. 런타임 캐릭터 원본의 필수값으로 저장할지 로컬라이징 데이터에서 관리할지는 개발팀이 결정한다.

작성 규칙:

1. `CATEGORY ALLY`는 `TIME_TAG PAST` 또는 `TIME_TAG FUTURE`와 `ULTIMATE_SKILL`을 반드시 작성한다.
2. 프로토타입 기준 `NORMAL_ENEMY`와 `BOSS_ENEMY`는 `TIME_TAG NONE`, `ULTIMATE_SKILL NONE`을 사용한다.
3. 아군의 `SKILL`과 `ULTIMATE_SKILL`이 참조하는 두 스킬 정의는 동일한 `COOLDOWN`을 사용한다.

#### 4-1-10-2. 일반 공격 문법

```text
NORMAL_ATTACK <일반공격ID> "<일반공격명>"
DAMAGE <0 이상의 정수>
TARGETING <DIRECTIONAL | SELF_CENTERED | TILE_SELECT | SELF_BUFF>
RANGE_PATTERN <범위패턴ID>
AFFECTED_CELL_PATTERN <영향셀패턴ID | NONE>
VALID_TARGET_TEAM <ENEMY | ALLY | ALL>
```

작성 규칙:

1. 세 타겟팅 유형 모두 영향 셀 안의 유효 캐릭터를 피격 대상으로 사용하고 영향 셀 패턴을 반드시 작성한다.
2. 일반 공격의 `normalAttackDamage`는 `DAMAGE`에 작성하고 캐릭터 문법에는 중복 작성하지 않는다.
3. 실제 범위·영향 셀 좌표는 대응 패턴 콘텐츠에서 작성한다.
4. `TILE_SELECT`는 절대 좌표가 아니라 계획 원점 기준 `relativeTargetOffset`을 저장한다.

#### 4-1-10-3. 스킬 문법

```text
SKILL <스킬ID> "<스킬명>"
DESCRIPTION "<설명>"
TARGETING <DIRECTIONAL | SELF_CENTERED | TILE_SELECT>
RANGE_PATTERN <범위패턴ID>
AFFECTED_CELL_PATTERN <영향셀패턴ID>
COOLDOWN <1 이상의 정수>
CAN_CRITICAL <true | false>

EFFECT DAMAGE <SELECTED_CELL | AFFECTED_CELLS> TARGET_TEAM <ENEMY | ALLY | ALL> VALUE <0 이상의 피해값>
EFFECT PUSH <AFFECTED_CELLS> TARGET_TEAM <ENEMY | ALLY | ALL> DISTANCE <0 이상의 N>
EFFECT PULL <AFFECTED_CELLS> TARGET_TEAM <ENEMY | ALLY | ALL> DISTANCE <0 이상의 N>
EFFECT AIRBORNE <AFFECTED_CELLS> TARGET_TEAM <ENEMY | ALLY | ALL>
EFFECT STUN <AFFECTED_CELLS> TARGET_TEAM <ENEMY | ALLY | ALL>
EFFECT COUNTER <SELF> RANGE_PATTERN <반격범위패턴ID> APPLY_STUN <true | false>
```

작성 규칙:

1. 스킬은 `EFFECT`를 1개 이상 작성한다.
2. 효과는 문서에 작성된 위에서 아래 순서로 처리 요청을 등록한다.
3. `EFFECT DAMAGE`의 `VALUE`에는 해당 효과의 `damageEffectValue`를 작성한다.
4. `PUSH`와 `PULL`을 사용하는 스킬은 `TARGETING DIRECTIONAL`을 사용한다.
5. `AFFECTED_CELLS`를 사용하는 스킬은 영향 셀 패턴을 반드시 작성한다.
6. `DIRECTIONAL`, `SELF_CENTERED`, `TILE_SELECT` 공격 스킬은 영향 셀 패턴을 작성한다.
7. 캐릭터에게 적용되는 효과는 `TARGET_TEAM`을 반드시 작성한다.
8. 실제 효과 적용·실패·면역·강제 이동·전투 불능·남은 효과 중단 규칙은 전투 시스템 문법과 처리 규칙을 따른다.
9. `TILE_SELECT`는 절대 좌표를 저장하지 않고 계획 원점 기준 `relativeTargetOffset`만 저장한다.
10. 같은 캐릭터의 일반 스킬과 궁극기는 동일한 `COOLDOWN`을 작성한다.
11. `SELF_BUFF`는 `AFFECTED_CELL_PATTERN NONE`을 허용하고 효과 적용 대상을 `SELF`로 작성한다.
12. `EFFECT COUNTER`는 `TARGETING SELF_BUFF`에서만 사용하며 반격 범위 패턴과 기절 적용 여부를 반드시 작성한다.
