화면의 번호와 요소 정의, 조작별 동작을 연결한 구현 검토용 문서다. 화면별로 무엇을 표시하고, 어떤 입력을 받으며, 처리 후 어디로 돌아가는지 정의한다. 화면 구성, 상태별 표시, 데이터 원본과 갱신, 입력 결과를 함께 정의한다.
문서 읽는 법
B는 전투, I는 가방 화면 ID다. 예를 들어 B04-03은 B04 화면의 03번 요소다. 같은 화면 안의 선택 전·후는 상태로 구분한다. 이미지의 숫자는 구성·데이터·조작 표에서 동일하게 사용한다. B01-01~03의 공통 표시 정의는 전투의 다른 화면에서도 따른다.
[화면]은 와이어프레임·연결 관찰, [기획]은 시스템 규칙, [연출]은 타임라인 요구사항, [제안]은 작성자가 보충한 미확정안이다. 확정된 입력 규칙에는 협의 태그를 붙이지 않는다. [보완안·협의]는 작성자가 제시한 미확정 구현안이며, 해당 문장에 한해 협의가 필요하다는 뜻이다. 미정 또는 자료 간 차이는 [확인 필요]로 표시했다. 여러 근거를 합친 화면은 각 절의 근거를 함께 읽는다.

공통 표시 데이터 읽는 법
화면에 보이는 값은 고정 문구, 콘텐츠에서 가져오는 값, 플레이 중 바뀌는 상태, 원본에서 계산한 표시값으로 나눈다. 각 화면의 데이터 표는 같은 요소 번호를 사용해 원본과 갱신 시점을 연결한다.

화면 간 데이터 유지
같은 캐릭터의 이름·초상·수치·선택 강조는 characterInstanceId를 기준으로 함께 갱신한다. 예를 들어 B02에서 대상을 바꾸면 이름만 바뀌고 HP가 이전 대상 값으로 남지 않도록 한다. 정보 화면을 닫으면 저장된 계획·행동 순서는 유지하고 실제 HP·위치는 최신 상태를 조회한다.
[보완안·협의] 데이터 로딩이 끝나지 않았을 때 임의의 0이나 다른 대상 데이터를 표시하지 않고 입력을 잠그는 처리만 미확정안이다. 로딩 중 표시 형태와 오류 시 복귀 방식은 개발 협의가 필요하다.
전투에서는 characterId가 캐릭터 종류, characterInstanceId가 이번 전투의 개체다. 체력·위치·계획은 개체 ID로 연결한다. 가방에서는 relicId가 유물 정의이며, 현재 기획상 동일 ID 중복 보유가 금지된다.
확인된 영문 필드는 기존 기획서 명칭이다. 여기서 요구하는 UI 선택·복귀·재생 상태와 리소스 연결은 구현 API가 확정됐다는 뜻이 아니다. 별도 연출 리소스 명세는 리소스 제작 기준으로 사용하고, 본 문서는 표시 조건·입력 허용·완료 후 상태를 정의한다.
참조 기준: Figma 전투 상태 화면·시스템 기획서·연출 타임라인 v1.2.0. 사용자 결정은 해당 규칙에 우선 적용한다.

주 행동 지정 공통 입력 규칙
B04·B05에 공통 적용하는 확정 규칙이다. 취소는 지정 진입 전 계획을 보존하고, 철회는 지금 지정 중인 행동 종류의 저장 계획만 삭제한다.

취소 입력 영역
취소 입력 영역은 행동 범위·방향 선택부·확정·철회·정보 UI·반대 행동 전환 버튼을 제외한 전장 영역이다. 이 영역을 터치하면 임시 입력만 버리고 B03으로 복귀한다. 비활성 버튼 터치는 취소 입력으로 전달하지 않는다. 세부 터치 영역은 와이어프레임에 표시한다.
철회 활성 조건과 지정 중 입력 제한
공격만 저장된 상태에서 B05 스킬 지정에 들어가면 철회는 비활성이다. 스킬 지정을 취소하면 기존 공격 계획은 그대로 남는다. 반대 경우도 같다. 같은 종류의 저장 계획이 있을 때만 철회를 활성화한다. 지정 중 캐릭터 변경은 차단한다. 다른 캐릭터를 고르려면 취소 입력 영역으로 나간다. 공격↔스킬은 반대 행동 버튼으로 직접 전환할 수 있다. 전환할 행동을 사용할 수 없으면 그 버튼만 딤·비활성이다. [보완안·협의] 전환 시 임시 방향·대상만 정리하고 이동·저장 주 행동 계획은 보존한다. 새 행동 확정 시 기존 주 행동을 대체한다. 취소·철회는 이동 계획·HP·파편·쿨타임을 변경하지 않는다.

B01 03 링과 이동 표시 규격

불투명도 계산

75%는 해당 캐릭터의 계획 표시 묶음에 한 번만 곱한다. 상위 그룹과 하위 요소에 중복 적용하지 않는다. 실제 캐릭터·HP에는 이 감쇠를 적용하지 않는다. 이동 발자국에도 같은 75% 감쇠를 적용한다. 이동 경로선은 선택 아군에게만 표시하며 선택 해제 시 숨긴다.
B01 03 주 행동 계획 표시

범위와 화살표 색상

주 행동 범위는 각 셀마다 테두리를 그린다. 이동 가능 영역의 전체 외곽선과 구별한다. 범위 셀과 방향 화살표의 색상은 같은 규칙이다. 아군·적군 카드 배경색과 계획 표시 테두리색은 서로 다른 값이다. 미선택 시 앞 절의 75% 감쇠를 적용한다.
주 행동 기준 셀과 실제 실행
주 행동 기준 셀은 범위를 계산하는 기준 위치다. 이동 계획이 있으면 이동 도착 셀, 없으면 실제 현재 셀이다. 이동 도착 셀은 movePath의 마지막 셀을 뜻한다. 표시된 범위는 예정 범위다. 실제 턴 실행에서는 이동 종료 후 실제 위치에서 범위를 다시 판정한다. 이 재판정은 계획 화면에서 피해·이동을 미리 적용한다는 뜻이 아니다.
자기버프형 사례: 아르제나는 자신에게 반격 상태를 부여한다. 즉시 영향 셀 패턴은 9(범위 없음)이지만, COUNTER 효과의 반격 범위 패턴은 7(자기 중심 3×3)이다. 스킬 확정 즉시 주변 전체를 공격하는 것은 아니다. 반격 범위까지 없다고 해석하면 안 된다. 반격 범위를 계획 화면에 표시할 색·선·명칭은 추가 결정한다.

B01 03 화면 변화와 계획 표시 갱신

시간대 변경을 읽는 예
시간대 버튼 입력 시 효과를 즉시 적용한다. effectiveMoveRange가 바뀐 캐릭터는 이동 계획 전체를 비우고, activeSkillId가 저장된 스킬 actionId와 달라진 캐릭터는 그 스킬 계획을 취소한다. 해당 조건에 걸리지 않는 계획은 유지한다. 이는 계획의 유효성 정리이며 전투 결과 재생이 아니다.
예: 과거 전환으로 이동력이 3에서 4로 바뀌면 기존 이동 경로는 즉시 지워져 다시 지정해야 한다. 실제 캐릭터는 원위치다. 반대로 공격력만 바뀌고 이동력·활성 스킬은 그대로라면 기존 이동·주 행동 계획을 유지하며, 달라진 피해 결과는 작전 개시 또는 관측에서 확인한다.

B01 공통 버튼 상태와 입력 조건
모바일 터치 입력을 기준으로 한다. 턴 설계 버튼 영역은 04 작전 개시·05 미래 관측·06 계획 초기화다. 행동 버튼 영역은 08 일반 공격·스킬이며, B04·B05 지정 중 해당 버튼 위치가 확정·철회로 바뀐다. 지정 중 반대 행동 버튼으로 공격↔스킬을 전환할 수 있다. 캐릭터 변경은 취소 입력 영역으로 나간 뒤 가능하다.

공통 터치 표시
